# 插件机制说明：功能、开发与运维手册

> 面向本仓库（edify / lomva 部署）的研发与运维。
> 内容来源：Dify 官方文档（工作空间插件管理 + 插件开发系列）与本仓库实际部署配置。
> 官方页面：<https://docs.dify.ai/zh/self-host/use-dify/workspace/plugins>

## 1. 插件系统概述

Dify 插件是模块化组件，用于扩展 AI 应用能力：接入模型、连接外部 API、处理数据、执行专业计算与现实世界操作。

**架构**：插件不跑在 api 进程内，而是由独立的 **plugin-daemon** 服务托管（Go 实现，上游镜像 `langgenius/dify-plugin-daemon`，源码不在本仓库）。调用链路：

```
web → api ──(PLUGIN_DAEMON_URL + PLUGIN_DAEMON_KEY)──▶ plugin-daemon ──▶ 各插件进程(Python)
                ▲                                          │
                └──(PLUGIN_DIFY_INNER_API_KEY 反向调用)──────┘
```

- plugin-daemon 监听 **5002**（api 调用入口）与 **5003**（远程调试安装入口）。
- 插件状态存独立数据库（docker 默认 `dify_plugin`，k8s 为 `lomva_plugin`）。
- 插件可反向调用主服务（模型、工具、节点、app、持久化存储等），权限在 manifest 中声明。

## 2. 工作空间侧功能（官方页面总结）

### 2.1 集成类型（7 类）

| 类型 | 作用 |
|---|---|
| 模型供应商 | 提供 LLM、Embedding、Rerank、TTS、Speech2Text、Moderation 等模型 |
| 工具 | 供 Agent 与工作流调用；含工具插件、MCP 服务器、已发布工作流、OpenAPI 服务 |
| 数据来源 | 通过知识流水线为知识库接入外部内容（如 Google Drive、Notion） |
| 触发器 | 外部事件（Webhook）发生时自动启动工作流 |
| Agent 策略 | Agent 节点推理、选工具、执行行动的决策策略 |
| 自定义端点 | 连接自有 API，可挂内容审核或外部数据能力 |
| 扩展 | 自定义 HTTP 端点，承载以上类别未覆盖的能力 |

集成**安装一次，全工作空间的应用共用**，管理入口为 **`/integrations`** 统一页面（旧 `/plugins` 路由仅做重定向，页面结构详见 §5.2）。

### 2.2 安装来源（3 种）

| 来源 | 说明 | 适用 |
|---|---|---|
| Marketplace | 官方与合作伙伴提供、经过测试维护；一键安装 | 通用能力 |
| GitHub | 填公开仓库 URL + 版本号，从 Release 的 `.difypkg` 资产安装 | 开源/内部按 URL 共享 |
| 本地上传 | 上传插件包（`.difypkg`，本质为 zip） | 私有插件、内部测试 |

> Dify Enterprise 中管理员可限制安装来源（仅官方 / 官方+认证伙伴 / 仅市场）。社区版无此能力，管控只能靠签名验证（见 §4.4）。

### 2.3 权限管理（工作空间级，2 项）

所有者/管理员在插件设置中配置，每项可选 **所有人 / 管理员 / 无人**：

1. **谁可以安装和管理集成**（安装、升级、移除）——默认「所有人」
2. **谁可以调试集成**（查看远程调试 key）——默认「无人」

后端实现见 `api/services/plugin/plugin_permission_service.py`。

### 2.4 自动更新

- 按类别（工具、模型、数据来源等）独立设置策略：**关闭 / 仅修订版本（patch）/ 始终最新**。
- 策略可应用于该类别全部集成，或仅选定的部分。
- 后端实现见 `api/services/plugin/plugin_auto_upgrade_service.py`。

## 3. 插件开发

### 3.1 环境准备

- **Python 3.12**（目前插件运行时唯一支持的语言与版本）
- 安装 dify CLI：

```bash
# macOS
brew tap langgenius/dify && brew install dify

# Linux：从 dify-plugin-daemon releases 下载二进制
chmod +x dify-plugin-linux-amd64
sudo mv dify-plugin-linux-amd64 /usr/local/bin/dify

dify version   # 验证
```

### 3.2 脚手架与项目结构

```bash
dify plugin init
```

交互式填写插件名称、作者、描述、仓库地址、README 语言，然后选择 `python` 模板与插件类型（`tool` / `agent-strategy` / `llm` / `text-embedding` / `rerank` / `tts` / `speech2text` / `moderation` / `extension` / `datasource` / `trigger`），生成以插件名命名的目录，基本结构：

```
your_plugin/
├── manifest.yaml        # 插件声明（见 §3.3）
├── main.py              # 入口（python -m main）
├── requirements.txt
├── .env.example         # 远程调试配置模板
└── provider/ + tools/ … # 各类型 provider 与能力定义 yaml
```

### 3.3 manifest.yaml 字段参考

| 字段 | 必填 | 含义 |
|---|---|---|
| `version` | 是 | 插件版本 |
| `type` | 是 | 目前仅支持 `plugin` |
| `author` | 是 | 作者，对应 Marketplace 组织名 |
| `name` | 是 | 插件标识名 |
| `label` / `description` | 是 | 多语言名称 / 描述 |
| `created_at` | 是 | 创建时间（上架市场要求不晚于当前时间） |
| `icon` | 是 | 图标路径 |
| `resource.memory` | 否 | 内存上限（字节），主要供云端 Lambda 分配 |
| `resource.permission.*` | 否 | 反向调用权限：`tool` / `model`（细分为 llm、text_embedding、rerank、tts、speech2text、moderation）/ `node` / `endpoint` / `app` / `storage`（含 `size`） |
| `plugins` | 是 | 能力入口，指向各类型 provider yaml 路径数组（`tools` / `models` / `endpoints` / `agent_strategies` 等） |
| `meta.version` | 是 | manifest 格式版本，初始 `0.0.1` |
| `meta.arch` | 是 | 支持架构：`amd64` / `arm64` |
| `meta.runner` | 是 | 运行时：`language: python`、`version: "3.12"`、`entrypoint: main` |
| `privacy` | 否 | 隐私政策路径/URL，**上架市场必填** |

约束：`tools` 与 `models`、`models` 与 `endpoints` 不可同时扩展；至少要有一种扩展能力；每种类型目前仅支持一个 provider。

### 3.4 远程调试（本地代码直连 Dify 工作区）

1. 在 Dify **插件** 页点「安装插件」旁的 🐞 调试图标，获取 `host:port` 与 API Key
   （自托管默认 `127.0.0.1:5003`，由 plugin-daemon 的调试端口决定）。
2. 配置插件项目：

```bash
cp .env.example .env
```

```ini
INSTALL_METHOD=remote
REMOTE_INSTALL_URL=<host>:<port>     # 注意是 host:port 单字段
REMOTE_INSTALL_KEY=********-****-****-****-************
```

3. 运行：

```bash
pip install -r requirements.txt
python -m main
```

插件即以 debug 标记出现在工作区插件列表，**工作区其他成员可见可用**，触发后请求落到本地进程。

注意：调试 key 不要外泄；**无热重载**，改代码后 Ctrl+C 重跑。

### 3.5 打包、签名与分发

```bash
# 打包（在插件目录的上一级执行），产出 yourapp.difypkg
dify plugin package ./yourapp

# 签名（本仓库部署已强制校验签名，自研插件必做，见 §4.4）
dify signature generate -f your_key_pair          # 生成密钥对
dify signature sign yourapp.difypkg -p your_key_pair.private.pem   # 产出 .signed.difypkg
dify signature verify yourapp.signed.difypkg -p your_key_pair.public.pem  # 本地验证
```

同一个 `.difypkg` 支持三种分发方式，仅渠道不同：

| 渠道 | 流程 | 审核 | 适用 |
|---|---|---|---|
| Marketplace | 向官方仓库提 PR（每版本一个 PR，有自动化 workflow） | 12 项自动检查 + 人工 | 成熟通用插件 |
| GitHub Release | 仓库 Release 挂 `.difypkg` 资产，用户凭 URL 安装 | 无 | 开源、内部按 URL 共享 |
| 本地文件 | 直接分发 `.difypkg`，插件页上传；更新需重新打包分发 | 无 | 私有插件、内部测试 |

常见路径：先 GitHub 快速迭代，稳定后再提 Marketplace。

## 4. 本仓库部署与维护

### 4.1 组件位置

| 环境 | 定义 | 镜像 |
|---|---|---|
| docker | `docker/docker-compose.yaml` 的 `plugin_daemon` 服务 | `langgenius/dify-plugin-daemon:0.6.10-local` |
| k8s | `k8s/base/runtime/plugin-daemon.yaml`（Deployment `lomva-plugin-daemon` + Service `plugin-daemon` + PVC `lomva-plugin-storage`） | 上游转推 TCR 的 `lomva-plugin-daemon:0.6.10-local` |

plugin-daemon 源码不在本仓库，升级 = 换镜像 tag。转推流程见 `k8s/README.md`（`docker pull --platform linux/amd64` → tag → push TCR）。

### 4.2 关键配置（docker/.env.example）

| 变量 | 默认 | 说明 |
|---|---|---|
| `PLUGIN_DAEMON_URL` / `PLUGIN_DAEMON_KEY` | `http://plugin_daemon:5002` | api/agent 调用 daemon 的地址与密钥 |
| `PLUGIN_DIFY_INNER_API_URL` / `PLUGIN_DIFY_INNER_API_KEY` | `http://api:5001` | daemon 反向调用 api 的内部接口与密钥 |
| `DB_PLUGIN_DATABASE` | `dify_plugin` | 插件独立库（k8s 为 `lomva_plugin`，需与 `lomva` 库一起预先建好） |
| `PLUGIN_MAX_PACKAGE_SIZE` / `PLUGIN_MAX_FILE_SIZE` | 50MB | 上传包大小限制 |
| `PLUGIN_DEBUGGING_PORT`（k8s 为 `PLUGIN_REMOTE_INSTALLING_PORT`） | 5003 | 远程调试安装入口 |
| `PLUGIN_STORAGE_TYPE` / `PLUGIN_STORAGE_LOCAL_ROOT` | `local` / `/app/storage` | 插件包与运行数据存储；k8s 挂 PVC |
| `PLUGIN_WORKING_PATH` / `PLUGIN_INSTALLED_PATH` / `PLUGIN_PACKAGE_CACHE_PATH` / `PLUGIN_MEDIA_CACHE_PATH` | — | 运行目录与包缓存（storage 下的 `cwd/`、`plugin/`、`plugin_packages/`、`assets/`） |
| `PLUGIN_MAX_EXECUTION_TIMEOUT` | 600s | 插件单次执行超时 |
| `PLUGIN_PYTHON_ENV_INIT_TIMEOUT` | 120s | 插件 Python 环境初始化超时（冷启动装依赖） |
| `FORCE_VERIFYING_SIGNATURE` | `true` | 强制签名校验（见 §4.4） |
| `MARKETPLACE_ENABLED` / `MARKETPLACE_API_URL` | `true` / `https://marketplace.dify.ai` | 市场开关与地址；**QA 内网若无法出公网，市场安装不可用，改用本地包上传** |
| `PIP_MIRROR_URL` | — | 插件冷启动装依赖的 pip 源；内网建议配 `https://mirrors.cloud.tencent.com/pypi/simple` |

**密钥等式**（改密钥时必须同步，见 `k8s/README.md`）：

```
INNER_API_KEY_FOR_PLUGIN(api/worker) = PLUGIN_DIFY_INNER_API_KEY(daemon) = DIFY_AGENT_INNER_API_KEY(agent)
```

`PLUGIN_DAEMON_KEY` 则是 api/worker/agent → daemon 方向的密钥，k8s 中由 `lomva-secret` 注入。

### 4.3 k8s 部署要点

- **单副本 + `strategy: Recreate`**：PVC 是 CBS RWO 卷，RollingUpdate 会因新 Pod 抢不到盘而死锁（新旧并存、K8s 不自愈），已用 Recreate 根治，不要改回。
- PVC `lomva-plugin-storage` 10Gi：TKE CBS 最小 10Gi，勿调小。
- `initContainers` 等待 PG 就绪后才启动，避免 Init 卡死类事故。
- readinessProbe 探 5002 TCP。
- 日志排障：`kubectl -n qa-ai-lomva logs deploy/lomva-plugin-daemon`；pod 重建后日志即失效，长期方案是接 CLS（见 k8s README 待办）。
- **远程调试可达性**：k8s Service 目前只暴露 5002，未暴露 5003。如需对 QA 环境远程调试插件，先 `kubectl -n qa-ai-lomva port-forward deploy/lomva-plugin-daemon 5003:5003`，再在插件 `.env` 配 `REMOTE_INSTALL_URL=127.0.0.1:5003`（此路径为按 manifest 推断，首次使用前实测）。
- 演进方向（k8s README 已规划）：存储切腾讯 COS（`PLUGIN_STORAGE_TYPE=tencent_cos` + 桶名带 `-APPID`）后可转 emptyDir + 多副本 + RollingUpdate。

### 4.4 签名验证（自研插件安装必读）

docker 与 k8s 均设 `FORCE_VERIFYING_SIGNATURE=true`：**未签名的 `.difypkg` 会被拒绝安装**。运维侧两种放行方式：

1. **给自研插件签名（推荐）**：按 §3.5 生成密钥对并签名；公钥放到 daemon 可达路径
   （docker compose 放 `docker/volumes/plugin_daemon/public_keys/`，容器内 `/app/storage`），
   并配置：
   ```
   THIRD_PARTY_SIGNATURE_VERIFICATION_ENABLED=true
   THIRD_PARTY_SIGNATURE_VERIFICATION_PUBLIC_KEYS=<容器内公钥路径，多个用逗号分隔>
   ```
   私钥保密，公钥分发给各环境管理员加入信任列表。
2. 关闭强制校验（`FORCE_VERIFYING_SIGNATURE=false`）：仅限内网临时环境，不推荐。

## 6. 常见任务速查

| 任务 | 操作 |
|---|---|
| 装官方插件 | 插件页 → Marketplace 一键安装（QA 无公网时改本地上传 `.difypkg`） |
| 开发新插件 | §3.1 CLI → `dify plugin init` → 远程调试 → 打包签名 → 分发 |
| 改插件代码后调试 | Ctrl+C 重跑 `python -m main`（无热重载） |
| 限制谁能装插件 | 插件设置 → 安装管理权限改「管理员」 |
| 插件调用报错 | `kubectl logs deploy/lomva-plugin-daemon` + `deploy/lomva-worker` |
| 升级 daemon | 换镜像 tag（docker compose / TCR 转推），k8s 因 Recreate 会短暂中断 |
| 轮换密钥 | 同步改 `PLUGIN_DAEMON_KEY` 与密钥等式三值，滚动 api/worker/daemon/agent |
