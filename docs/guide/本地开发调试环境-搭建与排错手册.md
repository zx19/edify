# 本地开发调试环境：搭建与排错手册

> 面向本仓库（edify / lomva 部署）的研发。
> 内容来源：本仓库代码 / 配置 / QA 集群实际部署，以及 2026-09-01 搭建过程中实测验证的结论。
> 关联文档：《工作空间机制说明-功能开发与运维手册》（认证链路）、《k8s/README.md》（QA 集群布局与密钥）。
> 标注约定：✅已实测证实 / ⚠️推导未实测 / ❌已证伪。

## 1. 架构与端口总览

本地开发的标准布局（三个进程 + 一条隧道）：

```
浏览器 localhost:3000 (next dev)
  ├─ 浏览器 XHR ──→ dev-proxy :5001 ──→ api :5002
  └─ SSR/RSC 服务端请求（/auth/refresh 等）──→ dev-proxy :5001 ──→ api :5002
                                          （走 CONSOLE_API_URL，见 §4）
api :5002（flask run --debug）
  ├─ PostgreSQL：QA TencentDB（直连公网域名）
  ├─ Redis：本地 :6379（空密码）
  ├─ plugin-daemon：QA 集群（kubectl port-forward :5010）
  └─ 对象存储：本地 api/storage/（fs，需拷私钥，见 §6）
```

| 端口 | 进程 | 说明 |
|---|---|---|
| 3000 | `next dev` | web 前端 |
| 5001 | dev-proxy | 唯一合法的 api 入口（浏览器与 SSR 都必须经它，见 §4） |
| 5002 | flask api | 本地 api；⚠️ 上游默认 5001，因 5001 被 proxy 占用而挪到 5002 |
| 6379 | redis（本地） | 队列/缓存/邀请 token 全在本地 |
| 5010 | kubectl port-forward | 隧道到 QA 集群 plugin-daemon:5002 |

## 2. 启动步骤

```bash
# 0) 依赖（首次）
./dev/setup                      # 复制 env 模板 + 装依赖

# 1) api（迁移自动执行）
uv run --project api flask run --host 0.0.0.0 --port=5002 --debug
#    等价 ./dev/start-api，但那个脚本用默认 5001，需自行确认参数

# 2) dev-proxy（必须先于/独立于 web 启动）
pnpm -C web run dev:proxy        # 读 web/.env.local 的 DEV_PROXY_TARGET

# 3) web
pnpm -C web run dev

# 4) QA plugin-daemon 隧道（长期开发放自己终端跑，别依赖会话）
kubectl -n qa-ai-lomva port-forward svc/plugin-daemon 5010:5002

# 5) 可选：celery worker（不发邮件/异步任务可跳过）
uv run --project api celery -A celery_entrypoint.celery worker --loglevel INFO -P solo
```

## 3. 本地连 QA 的数据面配置

本地调试的定位是「连 QA 数据调试」，与全本地中间件（`./dev/start-docker-compose`）是两种模式。连 QA 需要四个数据面：

### 3.1 PostgreSQL（直连）✅

`api/.env`（gitignored，从 `.env.example` 复制后改）：

```ini
DB_HOST=qa-postgres-default.xsl.link
DB_PORT=5432
DB_USERNAME=dev_svc_lomva
DB_PASSWORD=<从 k8s/overlays/qa/config/secret.env 取>
# 外部 PG 会掐空闲连接：死连接导致 flask-login 吞异常误判 401（登录后死循环）
SQLALCHEMY_POOL_PRE_PING=true
SECRET_KEY=<与 QA 一致，否则 DB 里已加密的模型凭据解不开>
```

⚠️ **写操作直接落在 QA 库上**——本地调试建的测试应用/知识库会出现在 QA 环境，注意清理；调试危险路径（删数据、迁移）前先想清楚。

### 3.2 Redis（本地）✅

`REDIS_HOST=localhost`、空密码。**故意不连 QA 的 redis**：redis 不只是缓存，还有 celery 队列与邀请 token。连 QA 的话，本地投递的异步任务会被 QA 的 worker 用 QA 的代码消费执行——本地改了代码实验时行为对不上，且可能污染 QA（限流锁、真实发邮件）。本地闭环邀请流程不受影响（token 存本地 redis，本地 api 自己读）。

### 3.3 plugin-daemon（port-forward 隧道）✅

`api/.env`：

```ini
PLUGIN_DAEMON_URL=http://127.0.0.1:5010     # 不是 5002！那是 api 自己
PLUGIN_DAEMON_KEY=<QA 轮换后的值，从 lomva-secret 取>
```

取 key：

```bash
kubectl -n qa-ai-lomva get secret -o name | grep lomva-secret | head -1 \
  | xargs kubectl -n qa-ai-lomva get -o jsonpath='{.data.PLUGIN_DAEMON_KEY}' | base64 -d
```

⚠️ 本地没跑 plugin-daemon；`PLUGIN_REMOTE_INSTALL_PORT`（5003）未转发，**本地装新 marketplace 插件会失败**，需要时再加一条 `port-forward svc/plugin-daemon 5011:5003` 并同步改 env。使用 QA 已装的供应商/模型不受影响。

### 3.4 对象存储（本地 + 拷私钥）✅

`STORAGE_TYPE=opendal` / `OPENDAL_FS_ROOT=storage`（默认即本地 fs）。租户 RSA 私钥存在存储卷（不在 DB），用于解密模型供应商凭据。本地不拷会报 `PrivkeyNotFoundError`（见 §7-4）：

```bash
mkdir -p api/storage/privkeys/<tenant_id>
kubectl -n qa-ai-lomva cp <api-pod>:/app/api/storage/privkeys/<tenant_id>/private.pem \
  api/storage/privkeys/<tenant_id>/private.pem
chmod 600 api/storage/privkeys/<tenant_id>/private.pem   # 该路径已被 gitignore
```

⚠️ QA 上传的历史文件（图标/附件）本地没有，浏览到时 404 属预期；本地新上传读写自洽。

### 3.5 邮件（不配）✅

`MAIL_TYPE=` 留空。前端会提示「邮件服务器未设置，无法发送邀请邮件」，属预期：发信是 celery 异步任务，本地没 worker 消费，配了也发不出。测邀请流程用邀请弹窗的**复制邀请链接**直接开本地地址，闭环且不打扰真实邮箱。

## 4. 请求路由：为什么所有入口都必须走 5001 ⚠️（已实测踩坑）

dev-proxy 对 cookie 做**改名隔离**（`web/node_modules/@langgenius/dev-proxy/src/cookies.ts`）：

- api → 浏览器方向：`access_token` 被改名为 `dev_proxy_<hash>_access_token`（并剥 Domain/Secure、Path 改 /，`localCookieScope: 'target-origin'` 按 target origin 哈希隔离，多套后端并存时互不串扰）
- 浏览器 → api 方向：proxy 翻译回普通名

因此 **`web/.env.local` 的 `CONSOLE_API_URL` 必须是 `http://localhost:5001`（proxy），不能是 5002（api 直连）**。SSR 服务端请求（`/auth/refresh` 路由、RSC 数据预取）经 `web/config/server.ts` 拼这个前缀发请求，并**原样转发浏览器 cookie**——直连 5002 就绕过了翻译，api 收到 `dev_proxy_xxx_refresh_token` 认不出，返回 401。

### 4.1 典型症状：登录成功却 401 死循环 ✅

```
POST /console/api/login          200   ← 登录成功，cookie 种了
GET  /console/api/account/profile 401   ← SSR 直连 api，cookie 名没翻译
POST /console/api/refresh-token   401   → 前端 303 回 /signin → 循环
```

判别方法：401 的那批请求（api 日志）不带登录用户语言、URL 带全路径的多为 SSR 代发。修法：`web/.env.local` 改 `CONSOLE_API_URL=http://localhost:5001` 后**重启 next dev**（env 不热载）。

### 4.2 api 侧 cookie 命名（QA 与本地不同）✅

`api/libs/token.py:72` `_real_cookie_name`：仅当 CONSOLE_WEB_URL 与 CONSOLE_API_URL 均为 https、无 COOKIE_DOMAIN、根路径部署时才用 `__Host-` 前缀。本地 http → 普通名 + `path=/`；QA（https 子路径）→ 普通名 + `path=/lomva`。QA 上 nginx 透传不改名，浏览器与服务端同名，故无本地这类问题。

## 5. `web/.env.local` 完整模板（连 QA 模式）✅

在 `.env.example` 基础上改这几项，其余保持默认：

```ini
NEXT_PUBLIC_BASE_PATH=                      # 根路径，QA 才是 /lomva
CONSOLE_API_URL=http://localhost:5001       # ★ 必须 5001（proxy），见 §4
NEXT_PUBLIC_API_PREFIX=http://localhost:5001/console/api
NEXT_PUBLIC_PUBLIC_API_PREFIX=http://localhost:5001/api
NEXT_PUBLIC_SOCKET_URL=ws://localhost:5001  # socket.io 也走 proxy
DEV_PROXY_TARGET=http://localhost:5002      # proxy 转发目标 = 本地 api
DEV_PROXY_ENTERPRISE_TARGET=http://localhost:5002
DEV_PROXY_PUBLIC_TARGET=http://localhost:5002
DEV_PROXY_HOST=127.0.0.1
DEV_PROXY_PORT=5001
```

## 6. 邀请/激活链路调试要点 ✅

本地复现「移除成员后重邀」这类流程时：

1. 邀请在本地发起 → token 存**本地** redis（`member_invite:token:<uuid>`，TTL 72h）
2. 登录/激活都打本地 api（读 QA 的账号表，join 表是本地写入 → 落 QA 库 ⚠️ 注意 §3.1 的写操作提示）
3. 排查顺序：api 日志（login/activate/refresh-token 的状态码序列）→ QA 库 `tenant_account_joins` → redis token 是否存在

## 7. 排错速查表

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 登录 200 后 profile/refresh 全 401 循环 | `CONSOLE_API_URL` 指向 5002 直连，SSR cookie 名没翻译 | 改 5001，重启 next dev（§4） |
| 2 | `model-providers/summary` 404 `/plugin/...` | `PLUGIN_DAEMON_URL` 指向 api 自己（5002） | 改 5010 + 起 port-forward（§3.3） |
| 3 | 插件接口 401 | `PLUGIN_DAEMON_KEY` 是上游默认值，QA 已轮换 | 从 lomva-secret 取新值（§3.3） |
| 4 | `PrivkeyNotFoundError: Private key not found, tenant_id=...` | 租户 RSA 私钥在 QA 存储卷，本地 fs 没有 | `kubectl cp` 拷私钥（§3.4） |
| 5 | 「邮件服务器未设置」提示 | 本地 `MAIL_TYPE` 空 | 预期行为，不配（§3.5） |
| 6 | `workspace not found, please contact system admin...` | 账号无任何 tenant join（如被移除后） | 重邀走修复后的链路（`invite_new_member` 即时恢复 join，a7b59d9abb） |
| 7 | PG 间歇性 401 假象 | 外部 PG 掐空闲连接，池内死连接 | `SQLALCHEMY_POOL_PRE_PING=true`（默认应已开） |

## 8. 与 QA 环境的差异清单（心算差异用）

| 维度 | 本地 | QA（k8s） |
|---|---|---|
| 部署路径 | 根路径 `/` | `/lomva` 子路径 |
| 入口 | dev-proxy（cookie 改名隔离） | nginx 透传（cookie 名不变） |
| api 端口 | 5002 | Service `api:5001` |
| redis | 本地（空密码） | 集群内（有密码） |
| plugin-daemon | port-forward 5010 | 集群内 Service |
| 存储 | 本地 fs + 手拷私钥 | PVC |
| 邮件 | 不发 | 飞书 SMTP（tech01@） |
| 前端构建态 | next dev（源码热载） | 生产镜像（`NEXT_PUBLIC_BASE_PATH=/lomva` 构建期固化） |

> ⚠️ 本地改 `web/` 代码即刻生效；改 `api/` 代码 flask `--debug` 热载（部分扩展初始化路径仍需手动重启，如改了 env）。
