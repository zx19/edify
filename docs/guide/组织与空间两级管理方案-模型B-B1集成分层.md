# 组织与空间两级管理方案（模型 B + B1 集成分层）

> 状态：设计稿（2026-08-27）。与《组织与空间两级管理方案-模型B》（B3 集成分层）互为备选——**同一组织模型，不同的集成分层策略**。
> 关联：《权限体系自研总体方案-模型A》、《系统管理控制台 UI 设计》、模型B+B3 方案。

## 0. B1 与 B3 的一句话区别

- **B3（两层分工）**：平台管"能不能用"（上架），组织管"给谁用"（分发）——平台方运营标准能力集
- **B1（组织级自治，本文）**：集成资源全部挂在组织下，**组织间互不可见**；平台超管只管组织生命周期，不碰插件与凭据——组织互不信赖场景（多集团/对外 SaaS）

## 1. 模型与角色

组织模型与模型 B 完全相同（organizations / organization_members / tenants.organization_id），差异只在集成层：

| 角色 | B1 下的职责 |
|---|---|
| 平台超管 | **收窄**：只管组织 CRUD/归档、组织管理员分配、全局审计（可选只读）。不接触任何插件/凭据内容 |
| 组织管理员 | **放大**：组织内全权——插件中心安装（三源）、托管分发、组织凭据、空间/成员、本组织审计 |
| 空间角色 | 不变 |

## 2. 数据模型变更

| 表 | 变更 |
|---|---|
| `organizations` / `organization_members` / `tenants.organization_id` | 与 B3 相同 |
| `admin_audit_logs` | 加 `organization_id`（同 B3） |
| `integration_grants`（插件托管） | **组织级归属**：`organization_id` 必填；无"平台可见性"字段（无平台目录） |
| 组织级凭据表 | `organization_id` 必填 |
| 平台凭据表 | **不存在**（B1 无平台凭据层） |

凭据回退只有两层：**空间自有 > 组织**。

## 3. 管理系统页面

```
┌────────────────────────────────────────────┐
│ [组织上下文：全部组织 ▾]   ← 仅平台超管可见     │
├──────────┬─────────────────────────────────┤
│ 平台      │                                 │
│  组织管理   │ 组织 CRUD、归档、组织管理员分配     │
│  全局审计   │ 只读跨组织（可选）                 │
│ ────────  │                                 │
│ 组织      │ 以下带组织上下文                    │
│  工作空间   │ 本组织                           │
│  成员      │ 本组织                           │
│  插件中心   │ 组织级安装（市场/GitHub/本地三源）   │
│  插件管理   │ 组织目录 → 分发到本组织空间         │
│  工具      │ 工具插件 / MCP                   │
│  模型提供商 │ 组织级凭据（含策略开关）             │
│  管理员    │ 本组织管理员                       │
│  审计日志   │ 本组织                           │
└──────────┴─────────────────────────────────┘
```

与 B3 的页面差异：**平台段没有插件中心/插件上架/平台凭据**；插件中心下移到组织段（组织管理员可用）。

| 页面 | 平台超管 | 组织管理员 |
|---|---|---|
| 组织管理 / 全局审计 | ✅ | ❌ |
| 插件中心 / 插件管理 / 凭据 | ✅（切入组织视角） | ✅ 本组织 |
| 工作空间 / 成员 / 管理员 / 审计 | ✅ 全量或本组织 | ✅ 本组织 |

## 4. 插件生命周期动线（B1）

```
组织管理员：插件中心安装（三源）→ 组织插件目录
        → 分发到本组织空间（全部/指定）→ 配组织凭据
空间：使用（凭据两层回退：空间自有 > 组织）
```

- 组织私有插件问题在 B1 下不存在——**所有插件本来就是组织私有的**，隔离天然彻底。
- 同一插件在 N 个组织 = N 份独立安装与凭据（这是彻底的代价）。

## 5. 与 B3 的取舍对比

| 维度 | B1（组织自治） | B3（两层分工） |
|---|---|---|
| 隔离强度 | **彻底**（组织间零可见） | 平台目录全局可见（内容脱敏） |
| 实现复杂度 | **较低**（无上架协调层） | 高（平台目录 + 可见性 + 继承升级） |
| 平台运营能力 | 无（不能统一推送/统一采购） | 有（标准能力集、统一升级） |
| 凭据回退层数 | 2 层（空间/组织） | 3 层（空间/组织/平台） |
| 适用 | 多集团、对外 SaaS、强合规隔离 | 企业内平台、统一采购收口 |

## 6. 改造点与工作量

| 层 | 改造 | 增量（相对 A） |
|---|---|---|
| 数据模型 | 组织两表 + tenants.organization_id + 迁移 | +2 人日 |
| 判定/端点 | org_admin_required + 全端点组织过滤 + 组织管理端点 | +3-4 人日 |
| 集成 | integration_grants 组织归属 + 凭据两层回退 + 插件中心下移组织段 | +2-3 人日 |
| 前端 | 组织上下文切换器 + 平台段两页 + 组织段过滤 | +2-3 人日 |
| **合计** | A（6.5-8）+ 增量 | **约 14-17 人日**（比 B3 少 3-5 人日） |

## 7. 分期建议

1. 一期按 A 交付，`organization_id` 可空列预留（与 B3 路径共用同一套表结构预留）。
2. 二期升 B 时选 B1 或 B3——**表结构层面两者兼容**，差异在集成层的归属语义与页面分布；甚至可混合：默认 B1，个别"平台标准插件"用 B3 式上架（加 platform_visible_orgs 可空字段即兼容）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 组织过滤漏判（跨组织读写） | 判定收口装饰器 + 服务层统一 where；跨组织越权合同测试 |
| 同一插件多组织重复安装的运维负担 | 接受（B1 的固有代价）；必要时二期补"平台推荐目录"只读视图 |
| 超管失去集成可见性 | 全局审计保留事件级可见（不暴露凭据内容）；或超管切入组织视角只读 |
