### 3.2 铁律与守卫

- **旧轨只读**：web/ 零业务提交；CI 对 web/ 的 diff 出现即告警（与 tripwire 双保险）。
- **e2e 双轨串行**：同 feature 集，先 :3000 → **reset+seed** → :3001（**每遍前 reset+seed**，防前遍数据污染；runner 参数化前端目标）。**「契约层 diff」定义**：同 scenario 两轨 pass/fail 对齐即达标；请求序列/payload 深比对（代理录制）为可选增强、不作门槛。
- **环境前置**：复用 e2e 现成机制（middleware up/down、seed、storageState、E2E 资源命名、fixtures/test-materials）；双轨共用同一后端。

### 3.3 后端咬合（唯一的外部依赖链）

e2e auth bootstrap 走 install 模式（`e2e/fixtures/auth.ts`，`mode: 'install' | 'login'`）。后端 T3（install 瘦身、首账号不建空间）落地后，e2e 安装链断——**适配**：install → `POST /admin/workspaces` 建首空间 → seed。适配后的后端形态才是重写期恒定形态；**先冻基线再合 T3 = 基线作废重刷**。此适配归后端轨随 T3 一起交付。

## 4. 原语轨（批发搬迁——2026-09-11 用户拍板机制变更）

**为什么从逐原语改批发**：实证——逐字搬迁下逐原语 parity 信息价值≈0（构造上恒真）；button/cn/icon-button/select 四次闭环的批量改写（499/965/225/73 文件）全部一次绿，失败全出在基建（lint 作用域/豁免/fmt 排序）而非原语逻辑。「批量改失败难定位」在零逻辑改动前提下不成立（tsc + 全量套件立刻指认现场）。

**批发动作（一次完成 2a+2b）**：

| 步 | 动作 | 验收（机器） |
|---|---|---|
| 1 整包复制 | `packages/dify-ui` → `packages/lomva-ui`（`@xsl/lomva-ui`，39 原语 + 全部测试 + storybook rig 连搬），**搬运时去 Dify 信息**（包名/注释/README/数据属性 `data-dify-*`/品牌向 CSS 变量名 `--color-dify-*` 等；旧轨 `packages/dify-ui` 原样保留至第 7 步——双轨对照物的载体） | 包自身测试全绿 |
| 2 全量 codemod | web-new 内 `@langgenius/dify-ui/*` → `@xsl/lomva-ui/*`（全部子路径 + styles.css @import + 被改名的 CSS 变量在 web-new 侧共改） | `@langgenius` 引用归零 |
| 3 批发验证 | tsc + web-new 全量单测 + `@xsl/lomva-ui` 包自身 browser spec 全量 + Storybook 抽样像素 diff；批末 e2e（B-2） | 全绿；抽样像素 diff < 0.1% |
| 4 标记追平 | 删旧台账整包一条（39 原语 + styles），第 7 步统一删 | 台账更新 |

**保留粒度的例外**：`table` 新建（无源码可搬，走下方五步闭环）；原语后续演进改动（接 token、修 bug、**单独重写实现**）——差异出现时 parity/对照才有信息价值，届时补写。

> **实证补课（2026-09-13，3a-1）**：批发验证缺 dev 启动冒烟——`globals.css @apply text-saas-dify-blue-inverted` 编译炸点 + 15 处 tsx 的 `saas-dify-blue`/`dify-logo` 工具类改名残留漏网（tsc/vitest 均不编译 css 全链路，dev 编译期/运行期才暴露；lomva-ui 侧为同值纯改名，已修）。教训：批次级验证自此补一步 dev 冒烟。

**基础组件口径（2026-09-11 用户澄清）**：验收 = API（props 冻结签名）不变 + 视觉不变（storybook 作护栏）；**同 API 同视觉 ≠ 同代码**——实现允许与 Dify 版不同，逐字搬迁只是批发期最低成本形态，单个原语后续可独立重写。parity.spec（双轨 DOM/行为恒等测试）属逐字副本的恒真仪式，已删除；视觉护栏走 storybook + screenshot:diff。

**单原语五步闭环**（保留为例外流程：table 新建 / 原语大改时使用，走完一个才动下一个）：

| 步 | 动作 | 验收（机器） |
|---|---|---|
| 1 冻结 | 读 dify-ui-api.json 该原语签名 | 签名入库 |
| 2 重写 | 新包名下实现，props 100% 对齐 | `tsc --noEmit` 0 错 |
| 3 换 import | web-new 内批量改写说明符 + `pnpm install`；旧轨零改动 | web/ 无 diff |
| 4 验证 | **分层验证**（附录 B-2 + B-5）：闭环级 = `vitest related` + 本原语 spec + Storybook 双 stories 像素 diff；批次级 = 受影响目录单测子集 + 受影响 e2e feature + `screenshot:diff`；里程碑级 = 全量单测+coverage（低并发配方）+ 全量 e2e | 闭环/批次项绿；像素 diff < 0.1%；里程碑全量绿 |
| 5 标记追平 | **不删实现**——dify-ui 旧包为两轨共享（web/ 仍 import 它），逐原语删旧即断 :3000 编译；登记删旧台账，统一删除推迟到第 7 步终验通过后（§6） | 台账更新，依赖者解锁 |

> **token 默认值**：新原语包 CSS 变量**默认值 = Dify 现行视觉值**（提取落库）；白+黑+橙新值仅在 `.webapp-theme` / `.admin-theme` / `.console-theme` 三主题类下覆盖。Storybook 像素 diff 在**无作用域态**跑（默认值对齐旧版），作用域内新视觉属预期（同 dark 模式机制）。

## 5. 业务重写轨

### 5.1 迁移单元

- 聚类：`web/app/components`（~3700 tsx）按功能单元聚 ~几十个；拓扑 = madge import 图 **+ 状态隐式边**（5 个共享 atom 文件与其引用者连边、同 queryKey 读写组件连边；**同边组件同单元或后迁**）。
- **叶子先迁** → 中层 → 顶层；禁止组合件先于其叶子。

### 5.2 验收（两层制合成一张表——"到哪算完"查此表）

| 层 | 基础组件（原语 + 纯展示叶子） | 业务组件（壳层 + 复合） |
|---|---|---|
| 契约 | props 100% 对齐冻结签名 | props（tsc）+ **选择器契约 = data-testid 冻结清单**——role/accessible name 派生自渲染文案、随呈现层变（实证：e2e step definitions 以字面文案做 name 选择器，冻 name 即冻文案，与重设计互斥）；feature 文件两轨共用，step definitions 允许按轨分叉 |

## 附录 E：组件级执行细则（自 v1 收入完整判定规则——§5.2 是口径总表，本附录是操作细则）

### E.1 迁移单元与依赖拓扑
- 清单：扫 `web/app/components/**/*.tsx` → `baselines/components.json`；依赖图 = madge import 图 **+ 状态隐式边**（5 个共享 atom 文件与其引用者连边、同 queryKey 读写组件连边；**同边组件同单元或后迁**）；按功能单元聚类 → `baselines/migration-units.json`。
- **叶子先迁** → 中层 → 顶层；禁止组合件先于其叶子。每迁完一组件更新图、解锁依赖者。

### E.2 单组件闭环（与 §4 原语五步同构，契约源不同）
原语契约源 = `baselines/dify-ui-api.json`；业务组件契约源 = 从 Dify 现有组件 `.tsx` 的 interface/type 提取 → `contracts/<component>.json`。双轨渲染 = web-new 内批量改写 import（同 C6）。

### E.3 基础组件四层判定（视觉对齐 Dify 原）
- **0 契约**：新版 props 接口 vs 冻结签名，字段名/类型/必填/默认值 100% 匹配，`tsc --noEmit` 0 错。
- **1 DOM**：同 props 渲染两版，`prettyDOM()` diff。normalize（diff 前必做）：剥 React key、随机 id/`aria-*`、动画内联样式（transform/opacity 过渡值）；保留标签层级、文本内容、`data-testid`、`role`。**去 Dify 化白名单**（`baselines/allowlist.json`）仅三类预期差异：class 名映射（`dify-button`→`xsl-button`）、命名空间 import 路径、包名——非白名单 diff 行数 = 0。
- **2 行为**：同 props + 同交互序列，行为快照 = 回调调用序列 + 每次参数 + 最终 state + 触发的请求体/响应处理；`vi.useFakeTimers()` + msw 给同响应。**布尔判定，无容差**。
- **3 视觉**：Storybook 双 stories + `toHaveScreenshot`，`maxDiffPixelRatio: 0.001`；等稳定态截图（`locator.waitFor` + 动画结束，可配 `prefers-reduced-motion`）。超阈值人工判定流见 §5.2。
- **props 矩阵**：契约冻结后生成代表性组合（含边界：空列表/加载态/错误态/最大长度），四层在所有组合通过才算追平。

### E.4 白名单审计（防借白名单掩盖退步）
每条变更须 git commit 说明 + 关联迁移单元；CI 守卫条目数只增不减（删对应旧代码除外）；定期抽查条目确属"去 Dify 化预期差异"而非退步被豁免。

### E.5 测试体系六层
| 层 | 工具 | 何时跑 | 验收 |
|---|---|---|---|
| 单元 | Vitest + happy-dom | 分层（B-5）：闭环 related / 批次子集 / 里程碑全量+coverage | 契约层测试不降、里程碑 coverage ≥ baseline（总量为参考信号） |
| 浏览器组件 | Vitest + Chromium | dify-ui 原语迁移时 | props 行为对齐冻结契约 |
| 组件库 | Storybook | dify-ui 全量 | 全绿 |
| E2E | Playwright + Cucumber | 双轨串行各跑一遍（每遍前 reset+seed） | 契约层 diff = 0（pass/fail 对齐） |
| 视觉回归 | Playwright screenshot | 每模块 + 终验 | 基础组件对旧版 < 0.1%；业务组件对新基线绿 |
| 契约 | dify-ui API 冻结 + oRPC contracts | 迁移时 | 签名不变 |

四原则：断言行为（非实现）、真实边界 mock、语义选择器优先、coverage 是信号不是目标。

### E.6 设计时机混合模式（业务组件）
全局 token 层提前（§4 注记）；共享壳层 mockup（chat-with-history / text-generation）首单元做范本；各单元三件套到该单元迁移时做。单元内流程：QA 实证清单 → mockup（对照 token）→ 功能对照表 → 重写 → §5.2 验收；设计假设在重写时立即验证，不成立马上改 mockup（不返工到全局）。跨单元一致性靠 token 层 + 每单元 mockup 评审（含"交互序列不变或对应 e2e step 可分叉"检查项）+ 共享壳层，**不靠一次性设计所有 mockup**。
