# 工作空间机制说明：功能、开发与运维手册

> 面向本仓库（edify / lomva 部署）的研发与运维。
> 内容来源：Dify 官方文档（workspace 系列）与本仓库实际代码/部署配置。
> 关联文档：《插件机制说明-功能开发与运维手册》（插件权限、模型供应商均在插件手册）、《知识库机制说明-功能开发与运维手册》（数据集访问控制见本文 RBAC 节）。

## 1. 工作空间概述

工作空间（Workspace/Tenant）是 Dify 的**基础组织单元**，容纳并隔离应用、知识库、成员、模型配置与集成；工作空间之间完全隔离，模型与集成配置一次全空间共用。

核心数据关系（`api/models/account.py`）：

```
Account（账号）── TenantAccountJoin（成员关系：role/current/invited_by）── Tenant（工作空间：plan/status/custom_config）
AccountIntegrate（OAuth/SSO 绑定）   InvitationCode（邀请码）   TenantPluginPermission（插件权限）
```

- 角色枚举 `TenantAccountRole`（`account.py:21`）：`owner` / `admin` / `editor` / `normal` / `dataset_operator`。
- 账号状态 `AccountStatus`（`account.py:81`）：`pending`（被邀请未激活）/ `uninitialized` / `active` / `banned` / `closed`。
- 账号的当前工作空间 = `TenantAccountJoin.current = true` 的那条记录。

## 2. 功能总览（官方使用侧）

### 2.1 角色与权限边界

| 角色 | 权限 |
|---|---|
| Owner | 完全控制，**每空间仅一人，不可被移除** |
| Admin | 管成员与模型供应商 + Editor 的全部能力 |
| Editor | 创建/编辑/删除应用与知识库 |
| Normal | 仅可使用已发布的应用 |

> 代码中实际还有第 5 个角色 **`dataset_operator`**（`models/account.py:21`，官方文档未列）：仅知识库操作的专项角色（`is_dataset_edit_role` 含之、`is_editing_role` 不含），受 feature `dataset_operator_enabled` 控制开放。权限分组方法：`is_privileged_role`=owner/admin、`is_editing_role`=+editor、`is_dataset_edit_role`=+dataset_operator。

Owner/Admin/Editor 可创建知识库；对已有知识库的访问由知识库设置单独管理（RBAC 数据集访问控制）。角色变更**在成员下一次操作时即生效**（无需重新登录）；移除成员**立即生效**，其创建的应用与知识库保留在工作空间。

### 2.2 邀请与加入

- 仅 Owner/Admin 可邀请：输入邮箱（可批量）+ 选角色 → 发送邀请邮件；弹窗中也展示**邀请链接**可直接复制转发。
- 邀请链接默认 **72 小时**过期（`INVITE_EXPIRY_HOURS=72`）。
- **Owner 转让**需向原 Owner 邮箱发送验证码确认 → 依赖邮件服务可用（`MAIL_TYPE` 已配置），否则不可用。

### 2.3 多工作空间

安装时创建第一个工作空间（`/install` 设置的管理员即 Owner）。社区版默认单空间（`ALLOW_CREATE_WORKSPACE=false`）；企业版可多空间隔离不同团队/客户，左上角切换器切换。

### 2.4 个人账号设置

头像、显示名、邮箱（改邮箱需邮件验证码）、密码、界面语言（英/简中/繁中）、时区；企业版可用 OAuth/SAML SSO 替代密码登录。

### 3.3 权限校验体系（三层）

1. **传统角色硬校验**（`RBAC_ENABLED=false` 时）：`check_member_permission()` 写死成员增删改需 owner/admin、admin 不能动 owner（`account_service.py:1722/1737`）；`Account` 便捷属性 `is_admin_or_owner` 等（`account.py:196-244`）。
2. **装饰器**（`controllers/console/wraps.py`）：`@setup_required`、`@login_required`（含 CSRF）、`@account_initialization_required`、`@is_admin_or_owner_required`（:423）、`@cloud_edition_billing_resource_check("members")`（配额）；新版统一入口 `@console_account_admission()`（`flask_admission.py:17`）。
3. **RBAC**（`RBAC_ENABLED=true` 时）：权限点枚举 `core/rbac/entities.py:24`（约 50 个：`app_edit`、`app_monitor`、`dataset_retrieval_recall`、`plugin_install`、`credential_manage`、`workspace_member_manage` 等），作用域 workspace/app/dataset，白名单 ALL/SPECIFIC/ONLY_ME；`rbac_permission_required` 装饰器（`controllers/common/wraps.py:69`，资源 maintainer 短路放行）；RBAC 关闭时走 `_LEGACY_*_KEYS` 把传统角色映射成权限点（`services/enterprise/rbac_service.py:306-519`）。**企业版 RBAC 数据经 `EnterpriseRequest` 转发到企业后端**（`rbac_service.py:782`）。

**固定角色 vs 企业 RBAC**：

| 维度 | 固定角色（社区版现状） | 企业 RBAC |
|---|---|---|
| 权限粒度 | 5 枚举角色，能力捆写死在代码 | 权限点自由组合成自定义角色（`/rbac/roles` CRUD） |
| 资源作用域 | 仅工作空间级，对所有 app/dataset 一视同仁 | 三级作用域 × 白名单（如"只能编辑应用 A、只读知识库 B"） |
| 判定 | 本地硬编码，零依赖 | 转发闭源企业后端 check-access |
| 前端 | 角色/权限集 tab 隐藏 | 角色管理、访问规则、访问矩阵 UI 出现 |
| 衔接 | — | 关闭时 `_LEGACY_*_KEYS` 映射固定角色为权限点，前端一套代码通吃 |

### 3.4 Feature / Quota / Billing

- `services/feature_service.py`：`get_features()` 按部署形态取配额——Cloud 走 Billing API、Enterprise 走 EnterpriseService、**自托管走 env 默认值**（`feature_service.py:23`）；`get_system_features()`（:102）返回登录前可用的系统开关（`enable_email_password_login`、`rbac_enabled` 等，前端登录页依赖）。
- `services/billing_service.py`：Cloud 计费 API（subscription/quota/vector-space）。
- 成员数限制示例：邀请时 Enterprise 查 license seats、Cloud 查 `features.members.limit`（`members.py:177/193`）。
- 版本开关：`DEPLOYMENT_EDITION`（`configs/deploy/__init__.py:28`）+ `only_edition_*` / `enterprise_license_required` 装饰器。

### 3.5 工作空间切换机制

`POST /workspaces/switch` → `TenantService.switch_tenant()`：校验成员关系 → 旧 join `current=false` → 目标 join `current=true` + `last_opened_at` → 注入运行时 `current_tenant`/`role`。登录时若当前空间被归档，自动切到第一个可用空间（`account_service.py:321`）。

### 3.6 OAuth / SSO / RBAC 实现现状（本 fork）

**OAuth（社区版完整可用）**：

| 场景 | 位置 | 配置 |
|---|---|---|
| 控制台社交登录（GitHub/Google） | `controllers/console/auth/oauth.py`；绑定存 `AccountIntegrate` 表 | `GITHUB_CLIENT_ID/SECRET`、`GOOGLE_CLIENT_ID/SECRET`、`OAUTH_REDIRECT_PATH` + `ENABLE_SOCIAL_OAUTH_LOGIN`（k8s 当前 false） |
| 数据源/插件授权 | `console/auth/data_source_oauth.py`；插件侧 `services/plugin/oauth_service.py`（Redis 一次性 proxy_context 防 CSRF） | 随插件配置 |
| OAuth Server / 设备码（CLI、第三方客户端） | `console/auth/oauth_server.py`、`openapi/oauth_device*.py`；`ENABLE_OAUTH_BEARER` | — |
| MCP | `controllers/mcp/mcp.py` | — |
| 过期 token 清理 | `ENABLE_CLEAN_OAUTH_ACCESS_TOKENS_TASK` | — |

**SSO（无实现，企业版闭源）**：`api/controllers/` 下无 enterprise 目录，web 的 `/enterprise/sso/saml|oidc|oauth2/login` 在本 fork 会 404；仅 `SSOProtocol` 枚举（`feature_entities.py:108`）作特性声明。要接公司 SSO 是开发项——`AccountIntegrate` 表可直接作账号绑定接入点，或走网关层 SSO 前置。

**RBAC（接口完整、判定依赖闭源企业后端）**：开关 `RBAC_ENABLED` 默认 false。开启后 `rbac_permission_required` → `services/enterprise/rbac_service.py` → HTTP 转发闭源企业后端（`ENTERPRISE_API_URL` / `ENTERPRISE_RBAC_API_URL` + `Enterprise-Api-Secret-Key` 头，`services/enterprise/base.py:156-160`，**该后端不在本仓库**，授权联系 business@dify.ai）。关闭时 `_LEGACY_*_KEYS` 把四档传统角色映射为权限点兜底（`rbac_service.py:306-519`），前端语义不变、「角色与权限」tab 隐藏。即：社区版权限模型 = 四档角色；细粒度授权需企业后端或自研替代 `rbac_service.py` 数据源。

**RBAC 开启配置（企业后端就绪后）**：
1. env（api+worker）：`RBAC_ENABLED=true`、`ENTERPRISE_API_URL`、`ENTERPRISE_RBAC_API_URL`（可选）、`ENTERPRISE_API_SECRET_KEY`；超时 `ENTERPRISE_RBAC_REQUEST_TIMEOUT=30`、`ENTERPRISE_REQUEST_TIMEOUT=5`。
2. 前端随 `system-features.rbac_enabled` 自动出现角色/权限集 tab，无需改前端。
3. 配置顺序：权限目录（只读）→ 自定义角色（`/rbac/roles`）→ 访问策略（`/rbac/access-policies`）→ 应用/数据集访问矩阵 → 成员角色分配（`/rbac/members/<id>/rbac-roles`）。
4. **fail-closed 警告**：无企业后端时开启 = 校验接口 403/500；存量成员开启后需在企业后端分配好 RBAC 角色再开开关（固定角色不再参与判定，资源创建者例外短路放行，`common/wraps.py:110`）。
5. 自研路径：`_inner_call`（`rbac_service.py:715`）是唯一出口，换成本地实现（PG 存角色/权限点/分配）即可，控制器与前端原样可用。

## 5. 部署与运维（本仓库）

### 5.1 初始化与登录开关

- 首次部署后访问 **`/install` 创建管理员**（k8s README 验收项之一）；`SECRET_KEY` 必配（JWT/会话签名）。`INIT_PASSWORD` 是 **`/install` 的访问口令**（设了它，setup 完成前访问先验口令，防裸奔期抢建管理员），**不是**预设管理员密码。
- 本仓库 k8s（`base/config/lomva-config.env:31-38`）与 docker 默认一致：

| 开关 | 当前值 | 含义 |
|---|---|---|
| `ENABLE_EMAIL_PASSWORD_LOGIN` | `true` | 邮箱+密码登录 |
| `ENABLE_EMAIL_CODE_LOGIN` | `false` | 邮箱验证码登录（依赖邮件服务） |
| `ENABLE_SOCIAL_OAUTH_LOGIN` | `false` | GitHub/Google 登录 |
| `ALLOW_REGISTER` | `false` | 开放注册关闭 → **只能邀请进人** |
| `ALLOW_CREATE_WORKSPACE` | `false` | 单工作空间 |
| `ENABLE_CHANGE_EMAIL` | `true` | 允许改邮箱（**需邮件服务**） |
| `DEPLOYMENT_EDITION` | `COMMUNITY` | 社区版（无企业 RBAC 后端/计费） |

### 5.2 邮件服务（当前 k8s 未配置，注意）

支持三种类型（`api/extensions/ext_mail.py`）：`smtp` / `resend` / `sendgrid`。本环境推荐 SMTP（腾讯 SES `smtp.qcloudmail.com:465` 或企业邮箱网关）。

**配置方法**：非敏感项进 `k8s/base/config/lomva-config.env`（api/worker 共用——发信是 Celery 任务跑在 worker 上）：

```ini
MAIL_TYPE=smtp
SMTP_SERVER=smtp.qcloudmail.com
SMTP_PORT=465
SMTP_USE_TLS=true
MAIL_DEFAULT_SEND_FROM=no-reply@<服务商侧已验证的域名/地址>   # 最易漏：发件地址需先在服务商验证
```

敏感项进 `lomva-secret`：`SMTP_USERNAME`、`SMTP_PASSWORD`。docker 侧对应 `docker/envs/core-services/shared.env.example:167-176`。

两者关系（`api/libs/smtp.py:39-49`）：`SMTP_USERNAME/PASSWORD` 是 **SMTP 登录认证**；`MAIL_DEFAULT_SEND_FROM` 是**信封发件人**（收件人看到的 From）。**企业邮箱场景两者填同一完整邮箱地址**（服务商会校验 From == 登录账号，不一致拒信）。注意：腾讯企业邮箱/QQ 邮箱的 `SMTP_PASSWORD` 要填**客户端授权码**（网页端设置→账户→开启 SMTP 生成），不是登录密码；建议用专用系统邮箱而非个人邮箱（离职即失效）；企业邮箱有发信频率限制，prod 大量发信建议换腾讯 SES。

**验证**：控制台邀请成员后 `kubectl -n qa-ai-lomva logs deploy/lomva-worker | grep mail_invite_member`。

**k8s 当前未配置的影响**：

- 邀请**邮件发不出**——邀请后用弹窗中的链接手动转发（功能不受影响）；
- **Owner 转让不可用**（官方要求邮件验证码）；
- 忘记密码重置不可用；
- 邮箱验证码登录不可用（与 `ENABLE_EMAIL_CODE_LOGIN=false` 一致）；
- `ENABLE_CHANGE_EMAIL=true` 实际走不通（改邮箱需验证码），建议配邮件后再开。

### 5.3 其他运维点

- 邀请配额装饰器 `@cloud_edition_billing_resource_check("members")` 仅 Cloud 生效；自托管成员数无硬限制（Enterprise 看 license seats）。
- RBAC：社区版 `RBAC_ENABLED=false`，传统角色即全部权限模型；角色与权限 tab 前端按 `rbac_enabled` 显隐。
- 认证面排障：401/掉线先看 Cookie 三 token 与 Redis（refresh token 存 Redis）；`SECRET_KEY` 轮换会使**全部会话失效**（轮换登记见 deploy 文档）。
- 管理员间调用：`ADMIN_API_KEY` + `X-WORKSPACE-ID` 头可以 owner 身份操作任意空间（`ext_login.py:73`）——密钥严格保密。

## 6. 常见任务速查

| 任务 | 操作 |
|---|---|
| 加人 | `?settings=members` → 邀请（邮件或复制链接）；QA 无邮件，直接发链接 |
| 改角色/移除 | 成员列表行菜单；立即/下次操作生效，无需对方重登 |
| 创建首个管理员 | 访问 `/install`；已初始化则该页关闭 |
| 排查登录失败 | 确认 `ENABLE_*_LOGIN` 开关 → `GET /system-features` 返回值；Cookie/Redis 状态 |
| 开邮箱验证码登录/改邮箱 | 先配 `MAIL_TYPE`+SMTP（docker shared.env / k8s 需补配），再开开关 |
| 转移 Owner | `?settings=members` → 转让（需邮件服务；QA 当前不可用） |
| 多空间隔离 | 企业版能力；社区版 `ALLOW_CREATE_WORKSPACE=false` 单空间 |
| 细粒度权限（按应用/数据集授权） | 需企业 RBAC（`RBAC_ENABLED=true` + 企业后端）；社区版只有四档角色 + 数据集级访问设置 |
