# 组织与空间两级管理方案（模型 B + B3 集成分层）

> 状态：设计稿（2026-08-27）。**备选演进路径**——当前一期按模型 A（部署级管理员）实施，本文档为两级模型的完整设计，待决策启用时机。
> 关联：《权限体系自研总体方案-模型A》（模型 A 与流 A/B）、《系统管理控制台 UI 设计》。

## 1. 模型与角色

```
部署（平台超管）
  └─ Organization（组织）── organization_members（账号 × 组织 × 组织角色）
       └─ Tenant（工作空间，加 organization_id 归属）── tenant_account_joins（现有）
```

| 角色 | 范围 | 来源 |
|---|---|---|
| 平台超管 | 部署级：组织 CRUD、插件上架、平台凭据、全局审计 | `/install` 产出首任；`SYSTEM_ADMIN_EMAILS` ∪ `is_system_admin` |
| 组织管理员 | 组织级：本组织的空间/成员/集成分发/组织凭据/本组织审计 | `organization_members`（org_admin），平台超管或本组织管理员授予 |
| 空间角色 | 空间级：owner/admin/editor/normal/dataset_operator | 现有五档，不变 |

**关键判定**：组织管理员鉴权 = `@org_admin_required`——解析目标资源的 `organization_id` 并校验管理员归属；平台超管 = `@platform_admin_required`（现 `system_admin_required` 改名/扩展）。

## 2. 数据模型变更

| 表 | 变更 |
|---|---|
| `organizations`（新） | id、name、status(normal/archived)、时间戳 |
| `organization_members`（新） | id、organization_id、account_id、role(org_admin)、唯一(org,account) |
| `tenants` | 加 `organization_id`（存量迁入默认组织） |
| `admin_audit_logs` | 加 `organization_id`（可空；组织级动作记组织，平台级动作记 NULL） |
| `integration_grants`（插件托管） | 加两层归属：`platform_visible_orgs`（平台可见性：全部/指定组织）+ 分发记录的 org/tenant 归属 |
| 组织级凭据表 | 加 `organization_id`；部署级凭据表（可选）org 为 NULL |
| 模型 A 已建的表 | 均可平滑扩展（全部新增可空列/新表，无破坏性变更） |

## 3. 管理系统页面（一套 /admin + 组织上下文）

```
┌────────────────────────────────────────────┐
│ [组织上下文：全部组织 ▾]   ← 仅平台超管可见     │
├──────────┬─────────────────────────────────┤
│ 平台      │                                 │
│  组织管理   │ 组织 CRUD、归档、组织管理员分配      │
│  插件中心   │ 安装到平台（市场/GitHub/本地三源）   │
│  插件上架   │ 平台插件目录 + 组织可见性           │
│  平台凭据   │ 部署级兜底 key（可选）              │
│  全局审计   │                                 │
│ ────────  │                                 │
│ 组织      │ 以下带组织上下文                    │
│  工作空间   │ 组织管理员：仅本组织                │
│  成员      │ 超管：全部（可按组织过滤）           │
│  插件管理   │ 本组织可见集合 → 分发到本组织空间     │
│  工具      │ 工具插件 / MCP                    │
│  模型提供商 │ 组织级凭据                         │
│  管理员    │ 超管=平台超管+各组织管理员；          │
│           │ 组织管理员=仅本组织                  │
│  审计日志   │ 超管=全局；组织管理员=本组织          │
└──────────┴─────────────────────────────────┘
```

- **组织上下文**：超管顶栏切换「全部组织 / 某组织」；组织管理员锁定本组织、无切换器。URL 带组织维度：`/admin/orgs/...`（平台段）、`/admin/org/<org_id>/workspaces/...`（组织段）。
- **页面 × 角色矩阵**：

| 页面 | 平台超管 | 组织管理员 |
|---|---|---|
| 组织管理 / 插件上架 / 插件中心（平台级）/ 平台凭据 / 全局审计 | ✅ | ❌ |
| 工作空间 / 成员 | ✅ 全量可过滤 | ✅ 本组织 |
| 插件管理 / 工具 / 模型提供商（组织凭据） | ✅（切入组织视角） | ✅ 本组织 |
| 管理员 | ✅ 平台超管 + 各组织管理员 | ✅ 本组织管理员 |
| 审计日志 | ✅ 全局 | ✅ 本组织 |

## 4. 插件生命周期动线（B3 核心）

```
平台超管：插件中心安装（三源）→ 平台插件目录
        → 插件上架页设组织可见性（全部组织 / 指定组织）
组织管理员：「插件管理」看到本组织可见集合
        → 分发到本组织空间（全部/指定）→ 配组织凭据
空间：使用（凭据三层回退：空间自有 > 组织 > 平台）
```

- **组织私有插件**：一期**不允许**（全部经平台上架，管控干净）；二期视摩擦再开放组织自装（本地上传/GitHub 到组织级目录）。
- 版本升级：超管平台级推送 → 各组织继承（组织无独立版本）。

## 5. 凭据三层回退

```
空间自有凭据 > 组织级凭据 > 平台凭据（可选层）
```

配置策略模型（空间自配/组织统一）语义不变，作用在"组织层 vs 空间层"；平台凭据只是更底层的兜底。MCP/OpenAPI 连接实例型仍不适用策略开关（只有分发来源差异）。

## 6. 改造点与工作量（相对模型 A 的增量）

| 层 | 改造 | 增量 |
|---|---|---|
| 数据模型 | organizations / organization_members / tenants.organization_id + 存量迁移 | +2 人日 |
| 判定 | org_admin_required + 组织上下文注入 + 目标归属校验 | +1-2 人日 |
| admin 端点 | 全端点组织过滤 + 组织管理端点 + 插件上架端点 | +3-4 人日 |
| 集成 | integration_grants 双层归属 + 凭据三层回退 | +2-3 人日 |
| 前端 | 组织上下文切换器 + 平台段四页 + 组织段过滤 | +3-4 人日 |
| **合计** | A（6.5-8）+ 增量 | **约 18-22 人日** |

## 7. 分期建议

1. **一期（按 A 交付，为 B 预留）**：表结构预留 `organization_id` 可空列（审计/托管/凭据）；空间创建挂默认组织（隐式）。
2. **二期（升级 B）**：组织模型 + 组织过滤 + 平台段页面；存量空间全部归默认组织，无感迁移。
3. **三期（B3 完整）**：插件上架双层目录 + 凭据三层回退 + （可选）组织私有插件。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 存量数据迁移（空间归默认组织） | 迁移脚本 dry-run + 灰度；默认可空列先行 |
| 组织过滤漏判（跨组织读写） | 判定收口在 `@org_admin_required` + 服务层统一 where；合同测试覆盖跨组织越权用例 |
| 两套语义并存期（A 的部署级 vs B 的组织级"组织级凭据"） | 文档术语统一：A 阶段"组织级"=部署级；升 B 时全局改为"平台级/组织级" |
| 权限复杂度超用户心智 | 页面 × 角色矩阵为唯一事实来源；超管切入组织视角用只读样式区分 |
