# 知识库机制说明：功能、开发与运维手册

> 面向本仓库（edify / lomva 部署）的研发与运维。
> 内容来源：Dify 官方文档（知识库系列）与本仓库实际代码/部署配置。
> 关联文档：《插件机制说明-功能开发与运维手册》（embedding/rerank 模型、datasource 均依赖插件体系）。

## 1. 知识库系统概述

知识库（Dataset/RAG）把原始文档变成可检索的上下文，供应用/Agent/工作流引用。两条主链路：

```
写入（索引）：上传/同步文档 → 解析(extract) → 清洗(clean) → 分段(chunk) → embedding → 写入向量库 + docstore
读取（召回）：应用/工作流/命中测试 → DatasetRetrieval → RetrievalService → 向量/全文/关键词检索 → rerank → 返回分段
```

- 索引是**异步**的：api 只写任务，实际处理在 **worker**（Celery，队列 `dataset` / `priority_dataset` / `pipeline`）。
- 向量库本仓库用 **Weaviate**（集群内 StatefulSet），驱动已插件化（`api/providers/vdb/vdb-*`）。
- 知识库涉及的外部能力全部走插件：embedding/rerank 模型（model 插件）、Notion/网页/网盘等数据源（datasource 插件）。

## 2. 功能总览（官方使用侧）

### 2.1 创建与数据源

创建入口「Knowledge → Create」，数据源四类：**上传本地文件**、**同步 Notion**、**同步网页**、**创建空知识库**（后续再补文档）；另有**连接外部知识库**（见 §2.6）。流程：选数据源 → 配置分段并预览 → 指定索引方式与检索设置 → 等待索引完成。

### 2.2 分段与清洗

| 模式 | 机制 | 关键参数 |
|---|---|---|
| 通用分段 | 切成独立块，命中即返回 | 分隔符（分段时会从文本中移除）、最大分段长度、分段重叠（保留语义连贯） |
| 父子分段 | 查询匹配**子块**、返回**父块** | 父块两种生成方式：**Paragraph**（按分隔符+最大长度，适合结构清晰长文）、**Full Doc**（整篇为父块，仅处理前 10000 tokens、父块不可编辑） |
| Q&A 模式 | 自动生成问答对，「Q 匹配 Q」，适合 FAQ 场景 | — |
| 摘要索引 | 为每个块生成摘要一并索引，命中摘要返回原块；配视觉模型可结合图片 | — |

清洗预处理：连续换行/多空格/制表符等规整、移除 URL 与邮箱（Full Doc 模式下忽略清洗）。**分段模式在知识库创建后不可更改**（分隔符、长度等参数可再调）。

### 2.3 索引方式

| 方式 | 实现 | 说明 |
|---|---|---|
| 高质量 | Embedding 模型向量化 | 支持向量/全文/混合检索；**启用后不可切回经济模式**；跨模态检索需选带 Vision 标识的 embedding |
| 经济 | 每块 10 个关键词倒排索引 | 不耗 token、精度低；仅支持 TopK；可在设置页升级到高质量 |

### 2.4 检索设置

- **向量检索** / **全文检索**（倒排关键词）/ **混合检索**（两者并行，权重可调或走 Rerank）。
- 公共参数：**Rerank 模型**（默认关；多模态 embedding 需配多模态 rerank，否则图片被排除）、**TopK**（默认 3）、**Score 阈值**（默认 0.5）。注意：TopK 与 Score 阈值**仅在 Rerank 阶段生效**，需开启 Rerank 模型。

### 2.5 元数据

- **内置元数据**（默认禁用、手动启用后自动抽取，生成后不可改）：document_name、uploader、upload_date、last_update_date、source。
- **自定义元数据**：string / number / time 三类，可增删改、可批量编辑；**删除字段会连带删除所有文档上的值**。
- 检索时可按元数据过滤（automatic 模式由 LLM 生成过滤条件 / manual 手动指定）。

### 2.6 外部知识库

通过 API 接入自建 RAG / 第三方知识服务（如 AWS Bedrock），Dify **只读检索、不托管内容**。配置：API Endpoint（Dify 自动追加 `/retrieval`）、API Key（Bearer）、External Knowledge ID、Top K、Score 阈值。对端规范：`POST /retrieval`，返回记录必须含 `content`、`score`，`metadata` 必须是对象 `{}`（为 `null` 会报错）。

### 2.7 命中测试与知识流水线

- **命中测试**：知识库内模拟查询、临时调整检索参数（仅当次会话生效）；Records 记录该库全部检索事件（含关联应用发起的）。
- **知识流水线（Knowledge Pipeline）**：把「数据源 → 抽取 → 处理 → 入库」编排成工作流（复用 workflow 编排器），支持内置/自定义模板与 DSL 导入，发布后供知识库使用；旧知识库可转换为 pipeline。

| `splitter/` | 分段器（`fixed_text_splitter.py`、`text_splitter.py`） |

| `embedding/` | embedding 代理、缓存、token 计数 |
| `datasource/vdb/` | 向量库抽象（`vector_factory.py`、`vector_type.py`、`vector_backend_registry.py`） |
| `datasource/keyword/` | 关键词表（仅 jieba 实现，经济模式用） |
| `datasource/retrieval_service.py` | **统一检索入口**：semantic/full_text/keyword/hybrid |

| `rerank/` | rerank 模型工厂、加权分数（`WEIGHTED_SCORE`） |

| `entities/`、`models/` | 检索配置/元数据过滤/ParentMode 等实体、RAG 数据模型 |

### 3.2 文档生命周期（写入链）

```
DatasetService/DocumentService（services/dataset_service.py）
  → extract（ExtractProcessor）→ clean（CleanProcessor）
  → transform（IndexProcessor：paragraph/parent_child/qa）
  → docstore.add_documents()（写 PG：document_segments/child_chunks）
  → vector.create()（embedding + 写向量库，batch=1000）或 keyword.add_texts()（经济模式）
```

编排核心 `api/services/dataset_service.py`（约 205KB，四个类）：`DatasetService`（库 CRUD、模型校验、pipeline 库创建）、`DocumentService`（文档创建/状态/下载，`batch_update_document_status` 处理 enable/disable/archive）、`SegmentService`（分段与子段 CRUD）、`DatasetPermissionService`。

**索引任务**（`api/tasks/`，均为 Celery，队列为 `dataset`，优先任务走 `priority_dataset`）：

| 任务 | 职责 |
|---|---|
| `document_indexing_task.py` | 文档索引主任务（含 priority 变体） |
| `document_indexing_update_task.py` / `document_indexing_sync_task.py` | 更新重建 / Notion 同步 |
| `add_document_to_index_task.py` | enable 后补索引 |
| `retry_document_indexing_task.py` / `duplicate_document_indexing_task.py` | 重试 / 复制 |
| `create/batch_create/enable/disable/delete_segment_to/from_index_task.py` | 分段级索引操作 |
| `clean_document_task.py` / `clean_dataset_task.py` | 清理文档/整库索引 |
| `generate/regenerate_summary_index_task.py` | 摘要索引 |
| `rag_pipeline/rag_pipeline_run_task.py` | 知识流水线执行（queue=`pipeline`） |

### 3.3 召回链路（读取链）

| 场景 | 入口 |
|---|---|
| 应用/Agent/工作流检索 | `core/rag/retrieval/dataset_retrieval.py:104` `DatasetRetrieval.knowledge_retrieval()` |
| 命中测试 | `services/hit_testing_service.py:104`（console 控制器 `controllers/console/datasets/hit_testing.py`，`POST /datasets/{id}/hit-testing`） |
| 外部知识库 | `core/rag/datasource/retrieval_service.py:176` `external_retrieve()` |

实现要点（`retrieval_service.py` `RetrievalService.retrieve()`）：

- semantic → `Vector.search_by_vector()`；full-text → `Vector.search_by_full_text()`；keyword → jieba 关键词表；**hybrid = semantic + full-text 双线程并行**，去重后进 rerank/后处理。
- rerank 经 `data_post_processor.py` `DataPostProcessor`，两种模式：`RERANKING_MODEL`（调 rerank 模型，走插件）/ `WEIGHTED_SCORE`（向量+关键词加权）；**跨库检索（multiple_retrieve）会二次 rerank**（`dataset_retrieval.py:748`）。
- hybrid 时早期向量阈值强制为 0，阈值在 rerank 后统一应用（`retrieval_service.py:328`）。
- 元数据过滤：`dataset_retrieval.py:1450`，automatic 模式由 LLM 生成条件，操作符处理在 `:1616`。
- 父子分段：先召回子块再映射回父 segment（`retrieval_service.py:471` `format_retrieval_documents()`）。

### 3.4 向量库驱动（已插件化）

- 枚举 `core/rag/datasource/vdb/vector_type.py:4` `VectorType`：weaviate、qdrant、milvus、pgvector、elasticsearch、tidb_vector、oceanbase、vikingdb、tencent 等 30+。
- 实现**不在 core 里**，而是独立的包：`api/providers/vdb/vdb-weaviate/`、`vdb-qdrant/`、`vdb-milvus/`、`vdb-pgvector/` 等，通过 `importlib.metadata.entry_points(group="dify.vector_backends")` 发现（`vector_backend_registry.py:75`）。**新增/升级向量库 = 改对应 providers 包**。
- 配置 `api/configs/middleware/__init__.py:103` `VectorStoreConfig`：`VECTOR_STORE`、`VECTOR_STORE_WHITELIST_ENABLE`、`VECTOR_INDEX_NAME_PREFIX`。
- 每个 dataset 持久化自己的 `index_struct_dict["type"]`，优先于全局 `VECTOR_STORE`（`vector_factory.py:132`）——**切换全局向量库不影响存量知识库**。

### 3.5 外部知识库与 Service API

- 外部知识库服务：`services/external_knowledge_service.py:32` `ExternalDatasetService`；console 控制器 `controllers/console/datasets/external.py`（`/datasets/external-knowledge-api` CRUD + hit-testing）。
- 知识库开放 API（`/v1/datasets`）：`controllers/service_api/dataset/` 下 dataset/document/segment/metadata/hit_testing/rag_pipeline 六个控制器。
- 内部检索接口：`controllers/inner_api/knowledge/retrieval.py`。

### 3.6 知识流水线

- 服务：`services/rag_pipeline/`（`rag_pipeline.py` 模板/保存/执行、`rag_pipeline_dsl_service.py` DSL 导入导出、`pipeline_template_factory.py`、`pipeline_generate_service.py`）。
- 控制器：`controllers/console/datasets/rag_pipeline/`（模板、pipeline 库创建、DSL 导入、workflow 草稿/发布/运行、datasource 授权与预览）。
- 执行：`tasks/rag_pipeline/rag_pipeline_run_task.py`（queue=`pipeline`），队列实现 `core/rag/pipeline/queue.py` `TenantIsolatedTaskQueue`（Redis）。
- datasource 节点走插件：`core/plugin/impl/datasource.py` `PluginDatasourceManager`（网站抓取、在线文档、网盘、凭据校验），本地文件有兜底 provider。

## 5. 部署与运维（本仓库）

### 5.1 组件与配置

| 组件 | 位置 | 说明 |
|---|---|---|
| 向量库 Weaviate | k8s `base/middleware/weaviate.yaml`（StatefulSet）/ docker `COMPOSE_PROFILES` 含 `${VECTOR_STORE}` | 集群内自建，数据在 `lomva-weaviate-data` PVC |
| 关键环境变量 | `VECTOR_STORE=weaviate`、`VECTOR_INDEX_NAME_PREFIX=Vector_index`、`WEAVIATE_ENDPOINT/GRPC_ENDPOINT`（k8s `base/config/lomva-config.env:80-84`；docker `.env.example:163-182` 含 API Key 认证配置） | 换向量库改这里 |
| 索引参数 | `INDEXING_MAX_SEGMENTATION_TOKENS_LENGTH=4000` | 分段 token 上限 |
| 索引执行 | `k8s/base/app/worker.yaml` / docker worker | **单个 worker 消费全部队列**（dataset、priority_dataset、pipeline、workflow、mail…）；知识库任务堆积看 worker 日志 |
| 文件存储 | `STORAGE_TYPE=opendal` + 本地 PVC（`lomva-app-storage`） | 原始上传文件；README 已规划切腾讯 COS（api/worker 多副本 HA 前置，**优先级：必做**） |

### 5.2 已规划的演进（k8s/README.md）

- **向量库外置**：weaviate → **pgvector**（复用外部 PG，中小规模首选；步骤见 README「切换向量库为 pgvector」），切换后删 `lomva-weaviate-data` PVC 与 weaviate StatefulSet。注意存量库的 `index_struct_dict["type"]` 锁定旧后端，切换只对新库生效（见 §3.4）。
- 集群内 redis/weaviate 随 kustomize 删除会**连 PVC 一起销毁**，操作前确认备份。

### 5.3 运维注意点

- **embedding/rerank 模型即插件**：索引与召回的模型调用全走 plugin-daemon（见插件手册 §5.1），「索引卡住/检索报错」先看 plugin-daemon 与 worker 日志。
- **外部知识库出公网走 SSRF 代理**：连接被拒/超时，需在 `docker/ssrf_proxy/squid.conf.template` 的 `allowed_domains` 加白名单并重启 ssrf-proxy。
- **Web 双套 UI**：新版 Knowledge FS（`features/new-rag/`）与旧版并存，由 `knowledge_fs_enabled` 控制；改知识库功能先确认目标版本。
- **分段模式创建后不可改**、高质量模式不可降级、删除元数据字段连带删值——涉及用户数据的不可逆操作，变更相关代码时注意兼容。
- 删除知识库会触发 `clean_dataset_task` 清向量库；向量库里的 collection 名为 `{VECTOR_INDEX_NAME_PREFIX}_{dataset_id}` 形态（前缀见配置）。

## 6. 常见任务速查

| 任务 | 操作 |
|---|---|
| 索引一直卡住 | 看 worker（`kubectl logs deploy/lomva-worker`，queue=dataset）与 plugin-daemon 日志；失败文档可页面重试（`POST /datasets/{id}/retry`） |
| 检索效果差 | 命中测试页面临时调参验证；确认是否开了 Rerank（TopK/Score 阈值仅 rerank 阶段生效）；考虑升级高质量索引 |
| 接入外部知识库 | `/datasets/connect` 配置 endpoint/key/id；连不通先查 SSRF 白名单 |
| 换 embedding 模型 | 设置页更换后需重建索引；模型来自插件市场，先确认插件已装 |
| 换向量库 | 改 `VECTOR_STORE` + 装对应 `api/providers/vdb/vdb-*` 包；存量库不受影响（index_struct 锁定）；pgvector 迁移按 k8s README 步骤 |
| 用 API 维护知识库 | 列表页头部「服务 API」开开关、取密钥；接口前缀 `/v1/datasets`（`controllers/service_api/dataset/`） |
| 自定义入库流程 | 用知识流水线：模板创建或 `/datasets/[id]/pipeline` 编排，datasource 节点来自插件 |
