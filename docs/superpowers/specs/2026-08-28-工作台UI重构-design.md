## 1. 背景与范围

**总原则（2026-08-31 用户确认）**：**保留原有功能、删减不用的、重新设计 UI**。删减依据有二：托管收窄（上游方案 A §6.4 收走的安装/凭据/权限能力）与 QA 现状实证（在用的保留，不用的删）。本稿的功能去留结论以 §2 末「功能去留总表」为准。

一期收窄后，普通用户工作台从「全功能自助空间」变为「纯使用方」：插件/凭据/成员治理收归系统管理控制台，工作台保留使用与编排。本 mockup 定义收窄后的工作台形态与信息架构。

**三条主线**：

1. **侧栏重构**：全局侧栏改为「logo + 空间切换器 + 导航（主页/工作室/Agents/知识库/Skills/集成）+ Web Apps + 底部账号区」，视觉语言与系统管理控制台统一（白+黑+橙，`#FF8C00` 选中/强调）。
2. **集成页重构**（最大改动面）：导航删「Marketplace」一级入口；集成展开二级（模型供应商/工具），工具页内再分三级子 tab（工具插件/MCP/工作流作为工具/Swagger API）——四个子 tab 现状已存在于集成二级侧栏（QA 实证），此处为**视觉重排非新 IA**。
3. **空间侧全面只读化**：插件安装/升级/卸载/凭据配置/自动更新入口全部移除，对应四道 api 层防线（见总体方案 §6.4，含 `/permission/change` 锁改），UI 只做呈现收敛。

**非目标（一期不做）**：工作室与主页改版（维持现状）、Agents/Skills 任何改动（保留现状）、知识库管线型（Pipeline）新建入口、**数据来源（整体不开放，含 OAuth 类与 Key 类）**、**触发器（一期不用）**、空间内插件安装/调试/权限页。

**导航删除项**（对照 QA 现状实证，2026-08-31 校准——现状一级为 主页/工作室/Agents/知识库/Skills/集成/Marketplace，无「探索」页）：**Marketplace 一级入口整页删除**（市场内容不再在空间侧出现，含工具页底部市场精选轮播）；集成二级的 数据来源/触发器/Agent 策略/扩展/自定义端点 五个类型页**一期不出现**，连同 调试/权限 两个底部入口与顶部「安装」按钮——它们的空间侧入口随托管收窄移除，类型过滤在系统管理控制台插件管理页承载。

**Agents（BETA）/ Skills 保留说明（2026-08-31 用户确认）**：两者均属新 Agent 栈（Agent App/Agent v2 与能力包，QA 实证 Skills 卡片以"N 个 Agent"为副标题），**保留在导航、一期不改动**。与《agent-架构梳理与摘除评估》的关系：摘除是独立决策，若日后执行其方案 A（`NEXT_PUBLIC_ENABLE_AGENT_V2=false` 隐藏入口），本设计无需返工——届时 nav 项随 flag 消失即可。

**空间切换面板**（侧栏顶部触发，上滑面板）：**操作行两项——工作空间设置（打开既有 `?settings=` 弹窗）、邀请成员**（QA 实证现状切换器菜单含此两项，owner/admin 视角的成员管理入口，属保留功能）；当前空间高亮 + 角色副文本；列表含多空间、**已归档空间置灰不可选**（`ws-prole=已归档` + `opacity:.5`）；无「创建空间」入口（`ALLOW_CREATE_WORKSPACE=false`，创建收归系统管理员）。角色文案口径：owner/admin/editor/normal 直显；`dataset_operator` 显示为「知识库专员」（受 `dataset_operator_enabled` feature 控制开放）。

**头像下拉菜单**：账号区四项——个人资料（→`/account`）、密码与安全（→`/account`）、**偏好设置**（→`?settings=preferences`，语言/时区）、**外观**（主题切换）——后两项为 QA 现状功能、用户确认保留（2026-08-31）；退出登录。系统管理员账号在同菜单**追加**「系统管理」入口（`is_system_admin` 显隐，跳 `/admin`）——mockup 已补画（带"仅系统管理员可见"标注）。

**WEB APPS 区**（QA 实证为现有功能，非新增）：已安装 WebApp 列表，可折叠 + 搜索；条目点击进 `/installed/<id>` 内嵌使用页（聊天/表单 UI），条目带「更多操作」。mockup 的"会议纪要"即 QA 真实条目。数据源与行为维持现状，仅视觉随侧栏重构。

## 3. 页面设计

### 3.1 主页 / 工作室

一期**不改动**：主页（最近 + 模板）、工作室（卡片网格 + 类型/标签筛选 + 搜索 + 创建）维持现状。mockup 仅作导航上下文呈现。

### 3.2 知识库（收窄）

- 保留：创建即用型（General）知识库、本地文件上传 / 网址抓取两导入源、标签筛选与搜索。
- 删除：**数据源同步导入整体不开放**（2026-08-31 用户决策：含 OAuth 类 Notion/网盘与 Key 类腾讯云 COS，不单拆 OAuth）——顶部 `notice-blue` 提示「导入源仅保留导入已有文本；数据源同步一期暂不开放」。⚠️ 文案**不提**「收归系统管理员配置」：组织代授权是二期能力，管理员一期也配不了，指路即误导（QA 实证：已装 Notion/COS/GitHub 三个数据源插件均未配置，无实际使用）。
- ⚠️ 边界：**管线型（Pipeline）知识库卡片**（mockup 里有 `Pipeline` 类型卡片）是刻意保留的存量展示口径--已有管线型库仍可见可进，**新建入口一期隐藏**。实现时若存量库为零，该类型卡片自然不出现，无需特判。存量 pipeline 内的数据源节点因无可用数据源插件，显示插件缺失态（点发现口径，同 §3.3.4）。

### 3.3 集成（重构主体）

**二级导航 + 三级子 tab 的双层结构**：侧栏二级（模型供应商/工具）承载大类切换；工具页内三级子 tab（pill 式，深色选中）承载工具四形态。这个双层是**刻意设计**：模型供应商与工具的差异是「有无凭据语义」，工具插件/MCP/工作流/API 的差异是「托管 vs 空间自建」--两级切分让每一层只表达一个维度。

#### 3.3.1 模型供应商（只读两态）

- 卡片网格（图标/名称/副文案/状态徽标/可用模型列表），**只读两态：可用（绿）/ 未配置（灰）**；无 Add API Key、无 Default Models、无安装入口、无来源徽标。
- 「未配置」态文案指向系统管理控制台（「联系系统管理员在系统管理 · 模型提供商中配置」）--这是显式分派解耦后的正常态（插件已装、组织未配凭据），**不是错误态**。
- 页头常驻 `pill-accent`「由系统管理员统一托管」徽标。
- ⚠️ mockup 的「配额不足」琥珀态为演示数据；一期实际状态来自组织凭据有效性，**实现时以两态为准**，配额/凭据失效等细分态二期再分层。

#### 3.3.2 工具插件（托管卡片 + 详情抽屉）

- **大卡片网格**（非现状的列表行）：图标/名称/描述/版本（mono 字体）/来源（org/name）+「托管」紫徽标。
- 点击卡片开**右侧滑出详情抽屉**（440px，mask 遮罩，Esc 关闭）：简介 / actions 列表（操作名+描述，**纯展示、无点击行为**）/ 托管状态区 / 底部 violet notice 引导至系统管理控制台。
- **抽屉限工具插件 tab 使用**，且「托管状态」区**按类型显隐**（2026-08-31 修订）：托管插件显示 来源=托管分发 / 版本 / 凭据=组织统一 / 升级卸载说明 四行 + violet notice；**内置工具**（代码解释器等，无插件包结构、无凭据概念）只显示 来源=内置 + 版本两行，不显示 notice。MCP/工作流/API 三 tab 不走此抽屉（见 §3.3.3）。
- 全部卡片均为「托管」态（一期无空间自装）；「内置」灰徽标仅用于 Dify 内置工具（代码解释器等，无插件包结构）。
- **删除项**：安装按钮与安装下拉、市场精选轮播（QA 实证现状工具页底部有「来自 Marketplace 的更多内容」区块）、自动更新设置、调试/权限入口、卡片行内操作按钮。

#### 3.3.3 MCP / 工作流作为工具 / Swagger API（空间自建，维持现状）

三个子 tab **一期不动**：MCP 保留添加（HTTP）与管理入口（连接实例不托管、**凭据空间自管**——`tool_mcp_providers.encrypted_credentials` 不纳入组织凭据，见总体方案 §6.4 MCP 注）；工作流/API 工具为空间原生功能。页面结构对齐新卡片网格视觉，功能面不变。**这三个 tab 不走统一详情抽屉**（抽屉的"凭据=组织统一"语义对它们不成立），管理交互走各自既有 UI；卡片上不显示托管徽标，页头也不显示「由系统管理员统一托管」徽标（该徽标仅模型供应商页常驻，见 §4 表）。

#### 3.3.4 渗透面收敛（托管收口的非集成页面，2026-08-31 新增）

插件能力渗透在 5 处非集成页（基准清单见《插件机制说明》§5.2「渗透插件能力的其他页面」），现状均带 `useNodePluginInstallation` 缺失检测 + `InstallPluginButton` 安装入口。托管收口后这些入口**全部改为提示态**（「由系统管理员统一分发，如需请联系系统管理员」），不出现安装按钮；后端四道防线不变，前端隐藏只是避免点击后吃 403：

| 位置 | 现状入口 | 收敛后 |
|---|---|---|
| 工作流·工具节点选择器（`block-selector/tools.tsx`） | 可装市场工具 | 仅列已装可用；市场/安装部分删除 |
| 工作流·Agent 节点策略选择器（`agent-strategy-selector.tsx:103`） | 已装策略 + 可装市场策略 | 仅列已装 |
| 工作流·Trigger / DataSource 节点 | 可装触发器/数据源插件 | 一期无此类插件分发，选择器自然为空；存量引用显示插件缺失态（点发现：`ToolProviderNotFoundError` + 编辑器标红，同总体方案 §6.4 统一警示原则） |
| 知识库建文档（`create-from-pipeline`） | 数据源插件选择 | 一期不开放（pipeline 新建入口已隐藏，§3.2） |
| 知识库索引设置（embedding/rerank） | 依赖插件版 model provider | 组织未配凭据时显示「未配置，联系系统管理员」提示态 |

### 3.4 登录失败态（无空间普通账号）

独立全屏态（非控制台外壳内）：图标 + 「登录失败：未加入任何工作空间」+ 引导文案（联系系统管理员）+ 返回按钮。**侧栏在此态隐藏**（`body[data-mode=login-fail] .side { display:none }`）--无空间即无工作台上下文，与 login 后端预检口径一致（无会话建立）。

## 4. 托管态的空间侧呈现口径（与总体方案 §6.4 对齐）

| 呈现位 | 口径 |
|---|---|
| 插件卡片/详情 | 「托管」徽标 + 版本号；**不显示升级入口、不显示新版本徽标**（内网 marketplace 不可达时 `list_latest_versions` 返回 None，无数据可显） |
| 详情抽屉「凭据」 | 「组织统一」绿徽标；无凭据查看/编辑入口（掩码只进不出，空间侧连掩码都没有） |
| 模型供应商卡 | 两态（可用/未配置），无操作按钮 |
| 集成页头托管徽标 | 仅模型供应商页常驻；工具各 tab 不显示（托管语义由卡片级徽标承载） |
| `?settings=` 弹窗体系 | **保留**：成员/偏好设置/品牌自定义等 tab 不变（现状功能）；集成类 modal 双入口收敛——只留 `/integrations` 页形态，设置弹窗不再内嵌集成 section |
| Agents(BETA) / Skills | 保留在导航，一期不改动；未来若执行摘除评估方案 A，入口随 `NEXT_PUBLIC_ENABLE_AGENT_V2` flag 消失 |
| 触发器存量（QA 已装 GitHub trigger 1.5.0） | 一期不用触发器：不分发、nav 无入口；存量建议由系统管理员在插件管理页**回收**（卸载波，连带删凭据），不回收则插件留在空间但无任何 UI 入口 |
| 数据来源存量（QA 已装 Notion/COS/GitHub，均未配置） | 一期整体不开放；同触发器口径，建议回收以保持「空间可见=可用」一致 |
| 收缩范围通知 | 空间侧会收到「插件已被系统管理员移除」的系统通知（admin 改范围收缩方向触发，见 UI 设计稿 §4.6 reason 机制）--工作台通知位一期用既有站内信/邮件通道，**不新建通知中心** |
| MCP/工作流/API | 不显示托管徽标（非托管对象），维持自建操作入口 |

**后端防线与 UI 的关系**：UI 呈现收敛只是第一层；真正封死是 api 层四道防线（install_permission=noone / 托管态 403 / 自动升级任务过滤 / `/permission/change` 锁改）。**实现要求：前端不能只做「藏按钮」**--所有空间侧插件操作端点在后端被拦，前端隐藏只是避免用户点击后吃 403。验收按「藏了且拦了」双标准走。

## 5. 实现注意点与要求

1. **视觉 token 全量对齐系统管理控制台**：CSS 变量集（`--bg/--text-1/--accent` 等）两份 mockup 完全一致，实现时抽公共 token 层（Tailwind v4 + `@langgenius/dify-ui` primitives），不允许两套控制台各写一套色值。
2. **侧栏是共享组件**：本 mockup 的侧栏与系统管理控制台的侧栏是**同一个组件的两个实例**（同一账号区/同一视觉/不同导航集）。实现为共享组件目录（如 `web/app/components/console-shell/`），供 `(commonLayout)` 与 `/admin` 独立 layout 两处引用——**不要放进任一路由组目录**（admin 不挂 commonLayout，放 `(commonLayout)/` 下名不正言不顺），也不要复制两份。
3. **空间切换器**：mockup 的 `ws-panel` 为静态演示；实现对接既有 `currentWorkspaceAtom` 与租户切换 API，切换成功后 `location.assign()` 整页刷新（QA 现状即如此，沿用）。**归档空间置灰但可见**（切换后 login 预检会拦，UI 提前置灰防误触）；「创建空间」入口按 `ALLOW_CREATE_WORKSPACE=false` 不渲染；**「工作空间设置」「邀请成员」两操作行保留**（现状功能，分别打开 `?settings=` 弹窗与邀请弹窗，邀请成员按 owner/admin 角色显隐）。
4. **头像菜单的「系统管理」入口**：mockup 已补画（带"仅系统管理员可见"标注）。实现必须包含——`is_system_admin` 由 `/account/profile` 下发，真则追加菜单项，点击跳 `/admin`。这是两份控制台之间的唯一互跳通道，漏掉会造成系统管理员必须手敲 URL。菜单其余项（个人资料/密码与安全/偏好设置/外观/退出登录）均为现状功能保留，分别对接 `/account` 页与 `?settings=preferences`、主题切换。
5. **工具详情抽屉的数据源**：卡片与抽屉数据来自 daemon `list_plugins`（经 api 聚合）；actions 列表来自插件 declaration。「内置」工具（非插件）走 `BuiltinToolProvider` 既有链路，混排时以「有无 plugin_unique_identifier」判型。
6. **登录失败态的路由归属**：不属于 `/admin` 也不属于工作台路由组，实现为登录流程的终态页（login 组件内分支），不建独立 route。
7. **三级子 tab 的路由化**：`tools-builtin/tools-mcp/tools-workflow/tools-api` 实现为 `/integrations` 下的 query 或嵌套路由（浏览器前进后退可用），不用纯前端 state（mockup 是演示切换，真实页面要可分享 URL）。
8. **知识库 notice 文案**：指向「联系系统管理员」，不指向具体管理页 URL（普通用户无权访问 `/admin`，指路即死链）。
9. **一期验收联动**：本页「插件全部托管徽标/无安装入口」的验收与 UI 设计稿 §7 流 B QA 是同一套用例（`/integrations` 侧走查），两份文档共用 QA 清单，不重复立项。
10. **WEB APPS 区实现**：复用现状已安装 WebApp 列表的数据源与行为（条目 → `/installed/<id>`），只换视觉；折叠/搜索/条目更多操作保留。
11. **`?settings=` 弹窗存续**：弹窗体系整体保留（成员/偏好设置/品牌自定义等）；仅收敛其中的集成 modal 双入口（`integrations/modal.tsx` + `section-renderer.tsx` 的 modal 形态下线，只留 `/integrations` 页形态），注意该 modal 组件与页形态共享 renderer，下线时勿误伤页形态。
