# 工作台 UI 重构设计

> 状态：设计稿（2026-08-28 出 mockup；2026-08-30 补写本文并同步总体方案 §6.4 最新口径）。
> 上游方案：《权限体系自研总体方案-模型A》流 B（`docs/guide/权限体系自研总体方案-模型A.md` §6.4）；配套设计：《2026-08-26-系统管理控制台UI-design.md》--本文是**普通用户工作台侧**的对应改造，两份合起来是方案 A 一期的全部前端面。
> 配套 mockup：`2026-08-28-工作台UI重构-mockup.html`（本文即其设计说明与实现要求）。

## 1. 背景与范围

一期收窄后，普通用户工作台从「全功能自助空间」变为「纯使用方」：插件/凭据/成员治理收归系统管理控制台，工作台保留使用与编排。本 mockup 定义收窄后的工作台形态与信息架构。

**三条主线**：

1. **侧栏重构**：全局侧栏改为「logo + 空间切换器 + 导航（主页/工作室/知识库/集成）+ Web Apps + 底部账号区」，视觉语言与系统管理控制台统一（白+黑+橙，`#FF8C00` 选中/强调）。
2. **集成页重构**（最大改动面）：导航删「探索」（无市场入口）、「工具」并入集成；集成展开二级（模型供应商/工具），工具页内再分三级子 tab（工具插件/MCP/工作流作为工具/Swagger API）。
3. **空间侧全面只读化**：插件安装/升级/卸载/凭据配置/自动更新入口全部移除，对应三道 api 层防线（见总体方案 §6.4），UI 只做呈现收敛。

**非目标（一期不做）**：工作室与主页改版（维持现状）、知识库管线型（Pipeline）入口、OAuth 数据源导入、空间内插件安装/调试/权限页。

## 2. 信息架构与路由

```
侧栏（一级）              集成（二级）        工具页内（三级）
主页                      模型供应商          -
工作室                    工具                工具插件 / MCP / 工作流作为工具 / Swagger API 作为工具
知识库
集成（可展开）
Web Apps 区（固定示例：会议纪要）
底部：账号区（头像下拉） + 帮助按钮
```

**导航删除项**（对照现状）：探索（Explore，市场入口整页删除）、工具（独立一级，并入集成二级）。集成二级的其余类型（数据来源/触发器/Agent 策略/扩展/自定义端点）**一期不出现**--它们的空间侧入口随托管收窄移除，类型过滤在系统管理控制台插件管理页承载。

**空间切换面板**（侧栏顶部触发，上滑面板）：当前空间高亮 + 角色副文本；列表含多空间、**已归档空间置灰不可选**（`ws-prole=已归档` + `opacity:.5`）；无「创建空间」入口（`ALLOW_CREATE_WORKSPACE=false`，创建收归系统管理员）。

**头像下拉菜单**：账号区（个人资料/密码与安全/退出登录）。系统管理员账号在同菜单**追加**「系统管理」入口（`is_system_admin` 显隐，跳 `/admin`）--mockup 未画，实现要求见 §5。

## 3. 页面设计

### 3.1 主页 / 工作室

一期**不改动**：主页（最近 + 模板）、工作室（卡片网格 + 类型/标签筛选 + 搜索 + 创建）维持现状。mockup 仅作导航上下文呈现。

### 3.2 知识库（收窄）

- 保留：创建即用型（General）知识库、本地文件上传 / 网址抓取两导入源、标签筛选与搜索。
- 删除：**OAuth 数据源导入**（Notion、网盘等）--数据源凭据已收归组织级（OAuth 类一期空间自管但入口收窄，见总体方案 §6.4 分期口径），顶部 `notice-blue` 提示「导入源仅保留导入已有文本，如需接入请联系系统管理员」。
- ⚠️ 边界：**管线型（Pipeline）知识库卡片**（mockup 里有 `Pipeline` 类型卡片）是刻意保留的存量展示口径--已有管线型库仍可见可进，**新建入口一期隐藏**。实现时若存量库为零，该类型卡片自然不出现，无需特判。

### 3.3 集成（重构主体）

**二级导航 + 三级子 tab 的双层结构**：侧栏二级（模型供应商/工具）承载大类切换；工具页内三级子 tab（pill 式，深色选中）承载工具四形态。这个双层是**刻意设计**：模型供应商与工具的差异是「有无凭据语义」，工具插件/MCP/工作流/API 的差异是「托管 vs 空间自建」--两级切分让每一层只表达一个维度。

#### 3.3.1 模型供应商（只读两态）

- 卡片网格（图标/名称/副文案/状态徽标/可用模型列表），**只读两态：可用（绿）/ 未配置（灰）**；无 Add API Key、无 Default Models、无安装入口、无来源徽标。
- 「未配置」态文案指向系统管理控制台（「联系系统管理员在系统管理 · 模型提供商中配置」）--这是显式分派解耦后的正常态（插件已装、组织未配凭据），**不是错误态**。
- 页头常驻 `pill-accent`「由系统管理员统一托管」徽标。
- ⚠️ mockup 的「配额不足」琥珀态为演示数据；一期实际状态来自组织凭据有效性，**实现时以两态为准**，配额/凭据失效等细分态二期再分层。

#### 3.3.2 工具插件（托管卡片 + 详情抽屉）

- **大卡片网格**（非现状的列表行）：图标/名称/描述/版本（mono 字体）/来源（org/name）+「托管」紫徽标。
- 点击卡片开**右侧滑出详情抽屉**（440px，mask 遮罩，Esc 关闭）：简介 / actions 列表（操作名+描述）/ 托管状态区（来源=托管分发、版本、凭据=组织统一、升级卸载=「由系统管理员统一管理」）/ 底部 violet notice 引导至系统管理控制台。
- 全部卡片均为「托管」态（一期无空间自装）；「内置」灰徽标仅用于 Dify 内置工具（代码解释器等，无插件包结构）。
- **删除项**：市场轮播、自动更新设置、安装/调试/权限入口、卡片行内操作按钮。

#### 3.3.3 MCP / 工作流作为工具 / Swagger API（空间自建，维持现状）

三个子 tab **一期不动**：MCP 保留添加（HTTP）与管理入口（连接实例不托管，见总体方案 §6.4 MCP 目录模型注）；工作流/API 工具为空间原生功能。页面结构对齐新卡片网格视觉，功能面不变。

### 3.4 登录失败态（无空间普通账号）

独立全屏态（非控制台外壳内）：图标 + 「登录失败：未加入任何工作空间」+ 引导文案（联系系统管理员）+ 返回按钮。**侧栏在此态隐藏**（`body[data-mode=login-fail] .side { display:none }`）--无空间即无工作台上下文，与 login 后端预检口径一致（无会话建立）。

## 4. 托管态的空间侧呈现口径（与总体方案 §6.4 对齐）

| 呈现位 | 口径 |
|---|---|
| 插件卡片/详情 | 「托管」徽标 + 版本号；**不显示升级入口、不显示新版本徽标**（内网 marketplace 不可达时 `list_latest_versions` 返回 None，无数据可显） |
| 详情抽屉「凭据」 | 「组织统一」绿徽标；无凭据查看/编辑入口（掩码只进不出，空间侧连掩码都没有） |
| 模型供应商卡 | 两态（可用/未配置），无操作按钮 |
| 收缩范围通知 | 空间侧会收到「插件已被系统管理员移除」的系统通知（admin 改范围收缩方向触发，见 UI 设计稿 §4.6 reason 机制）--工作台通知位一期用既有站内信/邮件通道，**不新建通知中心** |
| MCP/工作流/API | 不显示托管徽标（非托管对象），维持自建操作入口 |

**后端防线与 UI 的关系**：UI 呈现收敛只是第一层；真正封死是 api 层三道防线（install_permission=noone / 托管态 403 / 自动升级任务过滤）。**实现要求：前端不能只做「藏按钮」**--所有空间侧插件操作端点在后端被拦，前端隐藏只是避免用户点击后吃 403。验收按「藏了且拦了」双标准走。

## 5. 实现注意点与要求

1. **视觉 token 全量对齐系统管理控制台**：CSS 变量集（`--bg/--text-1/--accent` 等）两份 mockup 完全一致，实现时抽公共 token 层（Tailwind v4 + `@langgenius/dify-ui` primitives），不允许两套控制台各写一套色值。
2. **侧栏是共享组件**：本 mockup 的侧栏与系统管理控制台的侧栏是**同一个组件的两个实例**（同一账号区/同一视觉/不同导航集）。实现为 `web/app/(commonLayout)/` 下的共享 sidebar，导航项由路由上下文（workspace vs admin）决定，不要复制两份。
3. **空间切换器**：mockup 的 `ws-panel` 为静态演示；实现对接既有 `currentWorkspaceAtom` 与租户切换 API。**归档空间置灰但可见**（切换后 login 预检会拦，UI 提前置灰防误触）；「创建空间」入口按 `ALLOW_CREATE_WORKSPACE=false` 不渲染。
4. **头像菜单的「系统管理」入口**：本 mockup 未画（演示账号非系统管理员），但实现必须包含--`is_system_admin` 由 `/account/profile` 下发，真则追加菜单项，点击跳 `/admin`。这是两份控制台之间的唯一互跳通道，漏掉会造成系统管理员必须手敲 URL。
5. **工具详情抽屉的数据源**：卡片与抽屉数据来自 daemon `list_plugins`（经 api 聚合）；actions 列表来自插件 declaration。「内置」工具（非插件）走 `BuiltinToolProvider` 既有链路，混排时以「有无 plugin_unique_identifier」判型。
6. **登录失败态的路由归属**：不属于 `/admin` 也不属于工作台路由组，实现为登录流程的终态页（login 组件内分支），不建独立 route。
7. **三级子 tab 的路由化**：`tools-builtin/tools-mcp/tools-workflow/tools-api` 实现为 `/integrations` 下的 query 或嵌套路由（浏览器前进后退可用），不用纯前端 state（mockup 是演示切换，真实页面要可分享 URL）。
8. **知识库 notice 文案**：指向「联系系统管理员」，不指向具体管理页 URL（普通用户无权访问 `/admin`，指路即死链）。
9. **一期验收联动**：本页「插件全部托管徽标/无安装入口」的验收与 UI 设计稿 §7 流 B QA 是同一套用例（`/integrations` 侧走查），两份文档共用 QA 清单，不重复立项。

## 6. 与系统管理控制台 mockup 的边界

| 维度 | 工作台（本文） | 系统管理控制台（2026-08-26 稿） |
|---|---|---|
| 受众 | 普通用户（空间成员） | 系统管理员 |
| 插件 | 只读使用（卡片+抽屉） | 四动词治理（装/升/改范围/回收） |
| 凭据 | 只见状态（可用/未配置） | 组织凭据 CRUD + 分派（二期） |
| 知识库 | 使用+收窄导入源 | 不涉及 |
| 登录失败态 | 本文 §3.4 | 无（管理员有 `/admin` 兜底） |
| MCP | 空间自建维持 | 二期目录模型 |

两份 mockup 共用：视觉 token、侧栏组件、账号区/头像菜单组件。
