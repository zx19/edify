# 系统管理控制台 UI 设计

> 状态：设计稿已确认（2026-08-26）；2026-08-28 修订：一期收窄贯通、MCP 托管移除（路由与事件清单同步）、login 预检与无空间登录口径补录、QA 清单扩充；2026-08-30 修订：插件托管动作模型定稿（四动词：装/升/改范围/回收，无「分配」动作、「推送」改「升级」、改范围双向+reason、回收拆解除托管/回收两动作）、凭据显式分派模型（删回退/遮蔽/默认策略表，凭据范围与插件分发解耦），与总体方案 §6.4 同步；**2026-08-31 修订：§4.9 空间侧口径对齐工作台设计稿——升级/卸载由「禁用+tooltip」改为「不显示入口」（工作台侧为卡片+只读抽屉形态）；数据源/触发器由「一期不变」改为「一期不出现」（触发器一期不用、数据来源整体不开放，含 OAuth 与 Key 类，存量建议经本控制台回收）；§4.7 分期表对应两行同步；§4.6/§7 防线口径随总体方案同步为四道（新增 `/permission/change` 锁改）**。
> 上游方案：《权限体系自研总体方案-模型A》流 B（`docs/guide/权限体系自研总体方案-模型A.md`）——本文是其前端部分的展开。

## 1. 背景与范围

系统管理员（`is_system_admin`）需要一个面向人的跨空间管理界面，承载流 B 一期的后端能力（`/console/api/admin/*`：空间/成员/系统管理员/审计）。

**已确认的三个形态决策**：

1. 独立路由 `/admin`（不嵌入设置弹窗）
2. 跨空间成员为独立页面（按人聚合视角）
3. `/admin` 内部左侧二级导航 + 右侧内容区（与 console 视觉一致）

**2026-08-26 范围扩展（用户确认）**：插件/工具统一管理与 LLM 凭据集中管理**均纳入一期**。插件/工具采用「中央托管 + 按空间扇出」模式（daemon 安装是租户级，扇出复用现有安装链；**2026-08-30 动作模型定稿：四动词 装/升/改范围/回收**）；LLM 凭据为组织级凭据（**2026-08-27 收窄：一期全量组织统一**；**2026-08-30 显式分派模型：无回退链，分派表一期只读恒 org**；动热路径，需完整回归）。

**非目标（一期不做）**：审计导出 CSV、跨空间批量编辑成员、概览仪表盘、MCP 服务器托管（连接实例型，不适用扇出模式，维持空间自建）。

## 2. 信息架构与路由

```
/admin                        → 重定向 /admin/workspaces
/admin/workspaces             空间列表
/admin/workspaces/[id]        空间详情（基本信息 + 成员 + 集成 + 危险区）
/admin/members                跨空间成员
集成（一级分组）
  /admin/plugins                插件管理（托管运营四动词：改范围/升级/回收/解除托管；类型过滤覆盖工具/模型/数据源/触发器/Agent 策略 + 右上「安装插件」跳插件中心）
  /admin/model-providers        模型提供商（组织级凭据，凭据操作行内化）
/admin/marketplace            插件中心（**安装总入口**：市场 / GitHub / 本地上传三源 tab）
/admin/admins                 系统管理员
/admin/audit-logs             审计日志
```

- 路由组 `web/app/admin/`，**独立 layout**，不挂 `(commonLayout)` 的工作空间上下文依赖（系统管理员可能不属于任何空间）。
- 左侧导航：空间 / 成员 / **集成**（插件管理、模型提供商）/ **插件中心** / 系统管理员 / 审计日志。**MCP 服务器不纳入托管**（连接实例型，见 §4.7），原「工具」二级分组取消，工具插件由插件管理页类型过滤承载。
- 安装入口集中在「插件中心」页（安装对象不限于工具，放"工具"下语义不通）；「插件管理」的「安装插件」按钮仅作跳转快捷入口，安装逻辑单点维护。

## 3. 入口与守卫

- 入口：头像下拉菜单新增「系统管理」，仅 `is_system_admin` 为真时渲染；普通用户无感知。
- `is_system_admin` 由后端在 `/account/profile` 下发（system-features 不动，与总体方案 §6.1 一致）。
- 守卫：`/admin` layout 层校验，非系统管理员 → 403 页；无空间的系统管理员正常进入（依赖后端 `load_user` 窄分支，见总体方案 §6.1.1）。
- 无空间的普通账号登录失败并得到明确引导文案（复用 login 既有 fail 响应，引导联系系统管理员开通空间），不建立会话、不进入任何控制台页。
- **租户定位模型**：admin 后台无"当前空间"上下文（区别于普通控制台的 current_tenant + 切换器）——目标租户全部显式指定：路径参数（`/admin/workspaces/<id>/…`）、查询参数（审计 `?workspace_id=`）、表单选择（建空间 owner、插件分发范围）。服务端鉴权只看 `is_system_admin`，不要求系统管理员是目标空间成员；每个管理动作审计记 `workspace_id`（组织级动作记 NULL）。
- **管辖范围（2026-08-27 确认）**：Dify 中**工作空间=租户**（一级结构，`tenants` 表）。系统管理员为**部署级**——管辖本部署下全部空间；不采用"组织>空间"两级模型（多组织 SaaS 形态），若未来需要再议。

## 4. 页面设计

### 4.1 空间列表 `/admin/workspaces`

- 顶部：搜索框（空间名）、状态过滤（全部/正常/已归档）、「创建空间」按钮。
- 表格列：空间名、owner（姓名+邮箱）、成员数、状态徽标、创建时间、操作（详情）。
- 「创建空间」弹窗：空间名 + owner 邮箱。owner 已注册且 active → 直加并置 owner；未注册 → PENDING 预创建（复用邀请状态机）。弹窗内明确提示两种结果。
- 行点击 → 空间详情页。

### 4.2 空间详情 `/admin/workspaces/[id]`

- 头部：空间名（可编辑）、状态徽标、创建时间。
- 成员 tab：成员表格（头像/姓名/邮箱/角色/加入时间）；操作：加成员（邮箱+角色选择）、改角色、移除。
- **集成 tab**（重新设计，系统管理员视角的该空间集成全景，只读 + 跳托管页调整）：
  - **插件与工具**：该空间可见插件列表（名称/类型/版本/来源徽标/状态）——一期来源只有「托管分发」（空间侧无自装入口，存量自装为迁移遗留标记「空间自装」）
  - **凭据与授权**：模型与工具各配置项状态徽标（一期两态：**组织统一 / 未配置**--未配置=插件已装但组织未配凭据，解耦后正常态；二期分派开放后增加「空间自配」态）
  - **数据源 / 触发器**：一期维持空间自配、不属于托管分发对象，集成 tab 不展示分发项
- 底部危险区：归档/启用。二次确认弹窗写明影响（成员登录将切换到其他空间、空间内应用不可访问）。

### 4.3 跨空间成员 `/admin/members`

- 按人聚合表格：姓名、邮箱、所属空间徽标组（如「空间A·owner」「空间B·editor」）、最后活跃时间。
- 过滤：搜索（姓名/邮箱）+ 空间下拉。
- 行操作：跳转对应空间详情。
- 一期不做跨空间批量编辑。

### 4.4 系统管理员 `/admin/admins`

- 列表列：姓名、邮箱、来源徽标（环境变量 / 邮箱邀请 / 系统授予）、状态徽标（正常 / **待激活**）、授予人、授予时间、操作。
- 「授予」弹窗（邮箱邀请制，2026-08-30）：邮箱输入 + **当前账号密码确认**（验证操作者）；两路径--
  - 邮箱已注册且 active：直接生效，发通知邮件，列表即时出现（状态「正常」）；
  - 邮箱未注册：**PENDING 预创建**，发邀请邮件（激活链接），列表出现「待激活」行；激活前可撤销（等同作废邀请）。
  - **邮件发送失败降级**：授予结果处展示**邀请链接供复制转交**（不阻塞授予，落审计「邮件发送失败」）。
- 「撤销」：密码确认弹窗；**最后一位系统管理员禁撤**（按钮禁用 + 提示，待激活账号也计入在位数）；来源为环境变量的条目撤销禁用并标注「来自环境变量，需修改配置」。

### 4.5 审计日志 `/admin/audit-logs`

- 过滤条：操作类型（空间创建/归档/启用/成员变更/系统管理员变更/集成托管变更/凭据变更…）、操作人、目标空间、时间范围。
- 表格列：时间、操作人、动作、目标（空间/成员/插件）、详情（可展开 JSON）。
- 分页加载。
- **集成类必记事件**（实施埋点清单）：`integration.install`（含来源与范围）、`integration.scope_change`（**收缩方向必含 reason**，见 §4.6）、`integration.upgrade_push`（升级波触发，含目标版本；回滚/漂移修复同事件、direction 字段区分）、`integration.revoke`（回收）、`integration.unmanaged`（解除托管）、`credential.create/update/delete`、`admin.grant_invite`（管理员授予：含已注册直效/未注册邀请两路径与邮件发送结果）、`admin.revoke`。（`credential.assignment_change` 为二期分派写入口开放后的事件，一期分派表只读不触发；**`credential.scope_change` 移除**--凭据范围与插件分发已解耦、一期无凭据范围概念；MCP 不托管、无对应事件。）这些事件的安全/成本权重高于空间管理类（插件分发=供应链面，凭据=成本与数据出域阀门）。

### 4.6 插件管理 `/admin/plugins`（原"插件与工具"）

**模式**：中央托管 + 按空间扇出，**admin 四动词：装、升、改范围、回收**（2026-08-30 定稿）。托管记录（`integration_grants`：plugin_id × version × source × 范围 × 状态）；安装由「插件中心」页发起（§4.8，表单即选范围、默认全部空间，**无独立「分配」动作**）；`scope=全部` 的托管项在空间创建时自动安装（钩子补未来、扇出扫描补存量，竞态闭合）。**空间侧锁定靠四道 api 层防线**（noone 收口 / 托管态 403 拦截 / 自动升级任务过滤 / `/permission/change` 锁改，见总体方案 §6.4），daemon 不兜底。

- 顶部：类型过滤（工具/模型/数据源/触发器/Agent 策略）+ 搜索（**无安装按钮**，安装统一在插件市场页）。
- 表格列：插件（图标+名称）、类型徽标、版本、**适用范围**（「全部空间」/「指定空间 · N」徽标）、覆盖状态（成功/失败空间数）、波次状态（active/recycling 徽标）、操作（改范围/升级/回收/解除托管）。
- **升级**（原「推送升级」，术语 2026-08-30 改）：按钮一个、**确认框动态副文案显式目标版本**（「将 N 个空间升级到 vX」「回滚到 vY」）；语义为对齐 grant.version 的收敛波，方向无关（升级/回滚/修漂移同一动词），回滚走卸载+重装链；失败空间可重试。不做版本挑选 UI（版本在 grant 上编辑后点升级）。
- **改范围**：双向自由（试点是回环非单向漏斗；单向限制会删掉唯一 undo 路径）。弹窗单选全部空间/指定空间（后者多选清单）+ 保存即波（202 + 进度句柄）；**收缩方向**（含全量->指定、缩清单）：保存即生效（无确认框、无门原则），事前 toast 静态警示「范围外空间若正在使用将无法运行」+ **reason 必填**进审计 + 向被移除空间发通知；扩围方向无警示。
- **回收**（确认框 + 静态警示「正在使用该插件的应用将无法运行」，不做使用扫描）拆两动作：**解除托管**（轻确认、无波次，即时删 grant、插件留在各空间继续可用、空间恢复自管--安全阀）；**回收**（全量卸载，grant -> recycling 波次徽标 + 失败可重试 -> 卸载波完成 -> 删记录；波次部分失败时 grant 留 recycling 可续重试，防孤儿安装。上游 uninstall 连带删各空间该插件工具凭据，回收后重新托管需重配，弹窗文案提及）。
- 工具插件不设独立子页，由本页类型过滤（工具）承载；**MCP 服务器不纳入托管**（连接实例型，无"插件包+凭据"分离结构，不适用扇出模式，维持空间自建）；组织级 MCP 若做走目录/白名单模型，二期独立立项。
- **对账入口**：管理台手动触发的「一致性检查」（拉 daemon 安装记录 × grants 比对 drift 报告，异步任务），非常驻轮询。

### 4.8 插件中心 `/admin/marketplace`（安装总入口）

- **三源 tab**：插件市场（默认，卡片网格：图标/名称/简介/分类徽标/版本/「安装」）/ GitHub（仓库 URL + 版本号表单）/ 本地上传（`.difypkg` 拖拽区）。
- 任何来源点「安装」-> 统一范围选择弹窗（默认勾选**全部空间**；切「指定空间」展开多选清单）-> 扇出安装 -> 出现在「插件管理」托管列表。范围即 grant 字段、**无后续「分配」步骤**（调整走插件管理页改范围）。
- 页头搜索 + 分类过滤 chips（模型/工具/数据源/触发器/Agent 策略）。
- **内网降级**：市场服务不可达时该 tab 展示明确提示并引导至本地上传（QA 内网无公网）。

### 4.7 模型提供商 `/admin/model-providers`（组织级凭据）

- 架构前提：**模型提供商本身是插件**（模型供应商已全面插件化，见插件手册 §5.1）——提供商插件的安装走「插件中心」页（三源），本页管**组织级凭据**。
- 列表 = 所有已托管的模型提供商插件，行内操作（凭据属于具体提供商，不做全局添加按钮）：
  - 状态「正常」：[编辑凭据]
  - 状态「未配置」：[添加凭据]（行内出现）
  - 状态「未安装」：[去安装]（跳插件中心）
  - 列：提供商（图标+名称）、脱敏 Key（`sk-…****`）、状态徽标、更新时间
- 页面右上角仅「安装提供商插件」（跳插件中心）。
- **一期形态（全量组织统一，2026-08-27 收窄；2026-08-30 显式分派模型）**：**无「分配空间」操作、无凭据范围概念**--凭据对全部空间生效（分派表 `provider_credential_assignments` 一期只读、值恒为 org，UI 不出现分派控件）。空间侧凭据区只读"由组织统一配置"，无编辑入口、不显示来源徽标。凭据掩码只进不出。**动 ProviderManager 热路径，配完整回归**（分派表读链路一期随真实流量上线烤一个周期）。
- **二期形态（显式分派，2026-08-30 定稿，替代原回退/遮蔽设计）**：开放「空间自配」时**不做隐式回退链**（原「空间自有 > 组织」优先级删除），改为**显式分派指针**--每个 (provider, 空间) 一行 `assignment(org/self)`，切换 = 改指针 + 失效该空间解析缓存，解析按分派直查、无优先级规则。UI 形态：本页每行展开「分派」子视图（org/self 每空间一格）；「该空间在用哪份凭据」一眼可答。**策略粒度收敛 provider 级**（不做 model 级：撞 load balancing `CredentialSourceType` 语义，场景罕见）。原「遮蔽语义」随指针模型自然消失（策略不在密文行上，切换不碰密文）；**凭据范围与插件分发解耦**（插件范围管装不装、分派管用哪份，两维度正交，无「⊆ 插件范围」约束）。
- **范围解耦的边界提示（2026-08-30）**：凭据独立分派后，可能出现「空间装了插件但未获组织凭据」的正常态（该空间未配置任何凭据、相关模型/工具不可用，状态由空间详情集成 tab 呈现）；不再以「插件范围」作凭据可用性的前置约束。
- **各集成类型的分期口径**（类型只定节奏，不做默认策略开关）：

  | 类型 | 一期 | 二期 |
  |---|---|---|
  | 模型供应商 + 工具插件（Key/Secret 类） | 组织统一凭据（本页 + 工具插件行内「配置凭据」） | 显式分派开放自配 |
  | OAuth 授权类（数据源 Notion/Google Drive、部分触发器） | **一期不开放**（2026-08-31 修订：原「空间自行授权」——工作台侧数据来源整体不开放、无入口，空间自授权无从发生） | 组织代授权（复用同一分派模型，token 归属 = 分派指针） |
  | 触发器订阅/Webhook 秘钥 | **一期不开放**（2026-08-31 修订：原「空间自行配置」——触发器一期不用、不分发） | 同上 |
  | **MCP 服务器 / OpenAPI 服务** | 空间自建（不托管） | 若集中治理走**目录/白名单模型**（登记可信服务器，空间从目录选择），非分派模型 |
  | Agent 策略 | 插件分发范围治理（无凭据） | 同左 |

  即：**凭据分派仅适用于"插件包 + 凭据"可分离的类型**（模型插件、工具插件、OAuth 数据源）；连接实例型（MCP/OpenAPI）走目录模型、无凭据型（Agent 策略）只受插件分发治理，三者不互相从属。
- **配置需求不止模型**（组织级配置为通用能力，按类型分期）：
  - Key/Secret 类（模型、**工具**如搜索 key）：一期纳入组织级凭据；工具插件行内加「配置凭据」
  - OAuth 授权类（数据源 Notion/Google Drive、部分触发器）：需跳第三方授权页，token 归属/刷新复杂——**一期不开放（2026-08-31 修订：原「空间自行授权」，工作台侧入口已整体关闭），组织级代授权二期**
  - 触发器的订阅/Webhook 秘钥：**一期不开放（2026-08-31 修订：原「空间自行配置」，触发器一期不用）**
- **配套收口（2026-08-31）**：空间侧「添加模型」收走（工作台设计稿 §3.3.1）——本页组织级凭据配置需承载模型清单管理（自定义模型随凭据配置）；「默认模型设置」保留在空间侧页面顶层（空间级，同现状），组织级无需承载。
- **凭据/模型表单必须 schema 驱动（2026-08-31 用户强调）**：不同供应商的凭据字段与表单 UI 各不相同（如 Azure 的 endpoint/deployment/api-version、OpenAI 的组织 ID 等），「配置凭据」「添加模型」弹窗**复用现有空间侧供应商页的动态表单机制**——按插件 declaration 的 `provider_credential_schema` / `model_credential_schema` 渲染，**不做固定字段表单**。
- 空间详情「集成」tab：该空间已装插件/工具/凭据的只读视图 + 跳托管页调整。

## 5. 数据流与技术约定

- 服务层新增 `web/service/admin/`（TanStack Query hooks，风格仿 `web/service/access-control/`）；后端端点即总体方案 §6.2 的 `/console/api/admin/*`。
- 所有变更操作后 `invalidateQueries` 对应列表。
- 组件：`@langgenius/dify-ui` primitives + Tailwind v4 token；表格/弹窗样式对齐现有 `members-page`、`access-rules-page`。
- i18n：新增 `admin.json` 命名空间（zh-Hans / en）。
- 密码确认弹窗为复用组件（授予/撤销/归档共用）。

## 6. 异常与边界

| 场景 | 行为 |
|---|---|
| 非系统管理员访问 `/admin/*` | 403 页 |
| 无空间普通账号登录 | 登录失败 + 引导文案（联系系统管理员开通空间），不建立会话 |
| 归档空间 | 二次确认（列明影响），写审计 |
| 归档成员仅有的空间 | 登录得明确失败提示（login 既有 "workspace not found" 响应），引导联系系统管理员 |
| 授予管理员：邮箱不存在/未激活 | 弹窗内明确报错 |
| 撤销 env 来源管理员 | 按钮禁用 + 提示改配置 |
| 撤销最后一位管理员 | 按钮禁用 + 提示 |
