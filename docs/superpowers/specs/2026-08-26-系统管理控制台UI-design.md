# 系统管理控制台 UI 设计

> 状态：设计稿已确认（2026-08-26）；2026-08-28 修订：一期收窄贯通、MCP 托管移除（路由与事件清单同步）、login 预检与无空间登录口径补录、QA 清单扩充。
> 上游方案：《权限体系自研总体方案-模型A》流 B（`docs/guide/权限体系自研总体方案-模型A.md`）——本文是其前端部分的展开。

## 1. 背景与范围

系统管理员（`is_system_admin`）需要一个面向人的跨空间管理界面，承载流 B 一期的后端能力（`/console/api/admin/*`：空间/成员/系统管理员/审计）。

**已确认的三个形态决策**：

1. 独立路由 `/admin`（不嵌入设置弹窗）
2. 跨空间成员为独立页面（按人聚合视角）
3. `/admin` 内部左侧二级导航 + 右侧内容区（与 console 视觉一致）

**2026-08-26 范围扩展（用户确认）**：插件/工具统一管理与 LLM 凭据集中管理**均纳入一期**。插件/工具采用「中央托管 + 按空间扇出」模式（daemon 安装是租户级，扇出复用现有安装链）；LLM 凭据为组织级凭据（**2026-08-27 收窄：一期全量组织统一、无回退层**；动热路径，需完整回归）。

**非目标（一期不做）**：审计导出 CSV、跨空间批量编辑成员、概览仪表盘、MCP 服务器托管（连接实例型，不适用扇出模式，维持空间自建）。

## 2. 信息架构与路由

```
/admin                        → 重定向 /admin/workspaces
/admin/workspaces             空间列表
/admin/workspaces/[id]        空间详情（基本信息 + 成员 + 集成 + 危险区）
/admin/members                跨空间成员
集成（一级分组）
  /admin/plugins                插件管理（托管运营：范围/升级/回收；类型过滤覆盖工具/模型/数据源/触发器/Agent 策略 + 右上「安装插件」跳插件中心）
  /admin/model-providers        模型提供商（组织级凭据，凭据操作行内化）
/admin/marketplace            插件中心（**安装总入口**：市场 / GitHub / 本地上传三源 tab）
/admin/admins                 系统管理员
/admin/audit-logs             审计日志
```

- 路由组 `web/app/admin/`，**独立 layout**，不挂 `(commonLayout)` 的工作空间上下文依赖（系统管理员可能不属于任何空间）。
- 左侧导航：空间 / 成员 / **集成**（插件管理、模型提供商）/ **插件中心** / 系统管理员 / 审计日志。**MCP 服务器不纳入托管**（连接实例型，见 §4.7），原「工具」二级分组取消，工具插件由插件管理页类型过滤承载。
- 安装入口集中在「插件中心」页（安装对象不限于工具，放"工具"下语义不通）；「插件管理」的「安装插件」按钮仅作跳转快捷入口，安装逻辑单点维护。

## 3. 入口与守卫

- 入口：头像下拉菜单新增「系统管理」，仅 `is_system_admin` 为真时渲染；普通用户无感知。
- `is_system_admin` 由后端在 `/account/profile` 下发（system-features 不动，与总体方案 §6.1 一致）。
- 守卫：`/admin` layout 层校验，非系统管理员 → 403 页；无空间的系统管理员正常进入（依赖后端 `load_user` 窄分支，见总体方案 §6.1.1）。
- 无空间的普通账号登录失败并得到明确引导文案（复用 login 既有 fail 响应，引导联系系统管理员开通空间），不建立会话、不进入任何控制台页。
- **租户定位模型**：admin 后台无"当前空间"上下文（区别于普通控制台的 current_tenant + 切换器）——目标租户全部显式指定：路径参数（`/admin/workspaces/<id>/…`）、查询参数（审计 `?workspace_id=`）、表单选择（建空间 owner、插件分发范围）。服务端鉴权只看 `is_system_admin`，不要求系统管理员是目标空间成员；每个管理动作审计记 `workspace_id`（组织级动作记 NULL）。
- **管辖范围（2026-08-27 确认）**：Dify 中**工作空间=租户**（一级结构，`tenants` 表）。系统管理员为**部署级**——管辖本部署下全部空间；不采用"组织>空间"两级模型（多组织 SaaS 形态），若未来需要再议。

## 4. 页面设计

### 4.1 空间列表 `/admin/workspaces`

- 顶部：搜索框（空间名）、状态过滤（全部/正常/已归档）、「创建空间」按钮。
- 表格列：空间名、owner（姓名+邮箱）、成员数、状态徽标、创建时间、操作（详情）。
- 「创建空间」弹窗：空间名 + owner 邮箱。owner 已注册且 active → 直加并置 owner；未注册 → PENDING 预创建（复用邀请状态机）。弹窗内明确提示两种结果。
- 行点击 → 空间详情页。

### 4.2 空间详情 `/admin/workspaces/[id]`

- 头部：空间名（可编辑）、状态徽标、创建时间。
- 成员 tab：成员表格（头像/姓名/邮箱/角色/加入时间）；操作：加成员（邮箱+角色选择）、改角色、移除。
- **集成 tab**（重新设计，系统管理员视角的该空间集成全景，只读 + 跳托管页调整）：
  - **插件与工具**：该空间可见插件列表（名称/类型/版本/来源徽标/状态）——一期来源只有「托管分发」（空间侧无自装入口，存量自装为迁移遗留标记「空间自装」）
  - **凭据与授权**：模型与工具各配置项状态徽标（一期两态：**组织统一·锁定 / 未配置**；空间自有/组织回退为二期开放空间自配后新增）
  - **数据源 / 触发器**：一期维持空间自配、不属于托管分发对象，集成 tab 不展示分发项
- 底部危险区：归档/启用。二次确认弹窗写明影响（成员登录将切换到其他空间、空间内应用不可访问）。

### 4.3 跨空间成员 `/admin/members`

- 按人聚合表格：姓名、邮箱、所属空间徽标组（如「空间A·owner」「空间B·editor」）、最后活跃时间。
- 过滤：搜索（姓名/邮箱）+ 空间下拉。
- 行操作：跳转对应空间详情。
- 一期不做跨空间批量编辑。

### 4.4 系统管理员 `/admin/admins`

- 列表列：姓名、邮箱、来源徽标（环境变量 / 系统授予）、授予人、授予时间、操作。
- 「授予」弹窗：邮箱输入 + **当前账号密码确认**；仅接受已注册且 active 的账号（未注册报错，不预创建）。
- 「撤销」：密码确认弹窗；**最后一位系统管理员禁撤**（按钮禁用 + 提示）；来源为环境变量的条目撤销禁用并标注「来自环境变量，需修改配置」。

### 4.5 审计日志 `/admin/audit-logs`

- 过滤条：操作类型（空间创建/归档/启用/成员变更/系统管理员变更/集成托管变更/凭据变更…）、操作人、目标空间、时间范围。
- 表格列：时间、操作人、动作、目标（空间/成员/插件）、详情（可展开 JSON）。
- 分页加载。
- **集成类必记事件**（实施埋点清单）：`integration.install`（含来源与范围）、`integration.scope_change`、`integration.upgrade_push`、`integration.revoke`、`credential.create/update/delete`、`credential.scope_change`。（`credential.policy_change` 为二期策略开关开放后的事件，一期固定组织统一不触发；MCP 不托管、无对应事件。）这些事件的安全/成本权重高于空间管理类（插件分发=供应链面，凭据=成本与数据出域阀门）。

### 4.6 插件管理 `/admin/plugins`（原"插件与工具"）

**模式**：中央托管 + 按空间扇出。托管记录（`integration_grants`：插件 × 范围 × 版本 × 状态）；安装由「插件市场」页发起（§4.8）对每个目标空间调现有安装链（daemon 租户级安装）；`scope=全部` 的托管项在空间创建时自动安装，收回授权即对该空间卸载。**托管插件在空间侧锁定**（成员不可自行升级/卸载、不参与空间自动更新策略），版本只能由系统管理员统一推送——否则版本漂移、托管失效。

- 顶部：类型过滤（工具/模型/数据源/触发器/Agent 策略）+ 搜索（**无安装按钮**，安装统一在插件市场页）。
- 表格列：插件（图标+名称）、类型徽标、版本、**适用范围**（「全部空间」/「指定空间 · N」徽标）、覆盖状态（成功/失败空间数）、操作（改范围/推送升级/回收）。
- **推送升级**（需要但简化）：上传新版本包/选新版本 → 对所有托管空间扇出升级；不做版本挑选 UI；失败空间可重试。
- 工具插件不设独立子页，由本页类型过滤（工具）承载；**MCP 服务器不纳入托管**（连接实例型，无"插件包+凭据"分离结构，不适用扇出模式，维持空间自建）。

### 4.8 插件中心 `/admin/marketplace`（安装总入口）

- **三源 tab**：插件市场（默认，卡片网格：图标/名称/简介/分类徽标/版本/「安装」）/ GitHub（仓库 URL + 版本号表单）/ 本地上传（`.difypkg` 拖拽区）。
- 任何来源点「安装」→ 统一范围选择弹窗（默认全部空间/指定空间多选）→ 扇出安装 → 出现在「插件管理」托管列表。
- 页头搜索 + 分类过滤 chips（模型/工具/数据源/触发器/Agent 策略）。
- **内网降级**：市场服务不可达时该 tab 展示明确提示并引导至本地上传（QA 内网无公网）。

### 4.9 普通控制台配套修改（方案 A 对空间侧的影响面）

| # | 位置 | 修改 |
|---|---|---|
| 1 | 头像菜单 | 新增「系统管理」入口（`is_system_admin` 显隐） |
| 2 | 登录落地路由 | 无空间系统管理员 → `/admin`；无空间普通账号 → 登录失败 + 引导文案（联系管理员开通空间）；有空间账号不变 |
| 3 | 插件页（/integrations） | 一期全部托管：所有插件显示「托管」徽标，升级/卸载禁用（tooltip"由系统管理员统一托管"）；`TenantPluginPermission.install_permission` 收口为 noone（存量空间批量迁移 + 新建空间默认 noone，见总体方案 §6.4），空间内无安装入口 |
| 4 | 模型供应商页 | 一期全部组织统一：凭据区纯只读提示"由组织统一配置"，无编辑入口、**不显示来源徽标**（无自有态）；未配置的供应商不展示或置灰 |
| 5 | 工具页 | 工具凭据同上锁定 |
| 6 | 数据源/触发器 | 一期不变（仍空间自配） |
| 7 | 空间创建 | 维持 `ALLOW_CREATE_WORKSPACE=false`：普通用户无创建入口，创建收归系统管理员 |
| 8 | 全局 providers 兜底 | 无空间系统管理员 `currentWorkspaceAtom` 为空：commonLayout 全局 providers 需兜底，误入普通控制台页 → 重定向 `/admin` |

> 一期空间侧=纯使用方；二期开放「空间自配」后恢复来源徽标与自配入口（数据结构已预留策略字段，无迁移）。

### 4.7 模型提供商 `/admin/model-providers`（组织级凭据）

- 架构前提：**模型提供商本身是插件**（模型供应商已全面插件化，见插件手册 §5.1）——提供商插件的安装走「插件中心」页（三源），本页管**组织级凭据**。
- 列表 = 所有已托管的模型提供商插件，行内操作（凭据属于具体提供商，不做全局添加按钮）：
  - 状态「正常」：[编辑凭据] [分配空间]
  - 状态「未配置」：[添加凭据]（行内出现）
  - 状态「未安装」：[去安装]（跳插件中心）
  - 列：提供商（图标+名称）、脱敏 Key（`sk-…****`）、状态徽标、分配范围、更新时间
- 页面右上角仅「安装提供商插件」（跳插件中心）。
- **凭据范围语义**：**凭据范围 ⊆ 插件分发范围**——弹窗只读展示插件范围，凭据默认「跟随插件范围」，可收窄到子集（多选列表只列插件范围内的空间）；范围的唯一真相在插件管理页，不产生"凭据分给了没装插件的空间"的矛盾态。
- **凭据优先级语义（二期，空间自配开放后）**：**空间自有凭据 > 组织级凭据**（空间无自有凭据时回退，各空间可用不同 key 独立配置）；一期无此路径（仅组织凭据）。凭据掩码只进不出。**动 ProviderManager 热路径，配完整回归**。
- **配置策略模型**（每个凭据项一个开关，Key/Secret 与 OAuth 通用，系统管理员决定；**下表为二期开放后的形态，一期全部固定「组织统一」**）：

  | 策略 | 空间侧表现 | 凭据解析 |
  |---|---|---|
  | **空间自配**（默认） | 与现状一致，空间自行配置 | 空间自有 > 组织回退（若组织已配） |
  | **组织统一** | 空间侧锁定（只读/不可见） | 仅组织凭据 |

  **一期收窄（2026-08-27 用户决策）：全部凭据项固定「组织统一」**——空间侧不可配、不显示来源徽标；策略字段在数据结构中保留但 UI 不做开关，二期再开放「空间自配」选项。插件安装权限同步收紧：`TenantPluginPermission` 设为"无人"，空间内不可自装/升级/卸载，安装只走系统管理员。

  OAuth 类：组织统一 = 组织代授权（空间显示"已由组织授权"不可重授权）；空间自配 = 现状各自授权。
  **遮蔽语义**：策略切换**遮蔽而非删除**凭据——切回后原凭据重新生效。**缓存失效**：策略/凭据变更按 tenant 失效解析缓存。
- **各集成类型的默认策略建议**（策略是凭据项粒度，类型只定默认值）：

  | 类型 | 默认策略 | 理由 |
  |---|---|---|
  | 模型供应商（核心商用） | 组织统一 | token 成本归口 + 数据出域管控；实验性模型（内网 Ollama）可自配 |
  | 工具插件（共享 key 类：搜索/邮件） | 组织统一 | 公共资产 |
  | 工具插件（团队自研类） | 空间自配 | 他人用不上 |
  | **MCP 服务器 / OpenAPI 服务** | **不适用策略模型** | 连接定义即整体（URL+auth+schema 一体），无"插件与凭据分离"结构，无回退层可言；**也不做托管分发**（一期维持空间自建，如需集中治理二期再议） |
  | 数据来源（OAuth） | 空间自配 | 授权绑定业务部门真实账号，知识归属即业务归属；公司级共享源二期组织代授权 |
  | 触发器 | 空间自配 | 业务自动化各自为政；公司级事件源除外 |
  | Agent 策略 | 不适用 | 无凭据；治理点在插件分发范围（装不装/装给谁） |
  | 自定义端点/扩展（审核类） | 组织统一 | 合规收口；其余自配 |

  即：**策略开关仅适用于"插件包 + 凭据"可分离的类型**（模型插件、工具插件、OAuth 数据源）；连接实例型（MCP/OpenAPI）与无凭据型（Agent 策略）不在策略模型内。
- **配置需求不止模型**（组织级配置为通用能力，按类型分期）：
  - Key/Secret 类（模型、**工具**如搜索 key）：一期纳入组织级凭据；工具插件行内加「配置凭据」
  - OAuth 授权类（数据源 Notion/Google Drive、部分触发器）：需跳第三方授权页，token 归属/刷新复杂——**一期由空间自行授权，组织级代授权二期**
  - 触发器的订阅/Webhook 秘钥：一期由空间自行配置
- 空间详情「集成」tab：该空间已装插件/工具/凭据的只读视图 + 跳托管页调整。

## 5. 数据流与技术约定

- 服务层新增 `web/service/admin/`（TanStack Query hooks，风格仿 `web/service/access-control/`）；后端端点即总体方案 §6.2 的 `/console/api/admin/*`。
- 所有变更操作后 `invalidateQueries` 对应列表。
- 组件：`@langgenius/dify-ui` primitives + Tailwind v4 token；表格/弹窗样式对齐现有 `members-page`、`access-rules-page`。
- i18n：新增 `admin.json` 命名空间（zh-Hans / en）。
- 密码确认弹窗为复用组件（授予/撤销/归档共用）。

## 6. 异常与边界

| 场景 | 行为 |
|---|---|
| 非系统管理员访问 `/admin/*` | 403 页 |
| 无空间普通账号登录 | 登录失败 + 引导文案（联系系统管理员开通空间），不建立会话 |
| 归档空间 | 二次确认（列明影响），写审计 |
| 归档成员仅有的空间 | 登录得明确失败提示（login 既有 "workspace not found" 响应），引导联系系统管理员 |
| 授予管理员：邮箱不存在/未激活 | 弹窗内明确报错 |
| 撤销 env 来源管理员 | 按钮禁用 + 提示改配置 |
| 撤销最后一位管理员 | 按钮禁用 + 提示 |

## 7. 测试

- 前端 vitest：路由守卫（非管理员重定向/403）、列表渲染、授予/撤销交互（含末位保护）、创建空间弹窗两分支、登录落地三分支（无空间管理员 → `/admin`、无空间普通账号 → 引导文案、有空间账号不变）。
- 后端：端点鉴权（非管理员 403）、约束（末位禁撤、未注册邮箱拒授）、审计写入完整性、login 预检与 `load_user` 窄分支单测（有空间不变 / 无空间管理员放行 / 无空间普通账号 fail）。
- 手工 QA：五件事全程走通（建空间含 PENDING 分支 / 归档含唯一空间成员登录提示 / 空间内成员管理 / 授撤管理员 / 查审计）；**插件三源安装 + 扇出失败重试 + 新建空间自动安装 + 空间侧锁定（/integrations 无安装/升级/卸载入口）**；**组织凭据配置后模型调用全链路（对话/补全）与变更缓存失效**；**无空间系统管理员首登直达 /admin 并完成首空间创建**。

## 8. 验收标准

1. 系统管理员全程 UI 完成：创建空间（含 PENDING 分支）、归档/启用空间、空间内加人/改角色/移除、授予/撤销系统管理员、按条件查询审计日志。
2. 非系统管理员看不到入口、访问 `/admin` 得到 403。
3. 普通用户（有空间）的现有路径无回归。
