## 1. 背景与范围

系统管理员（`is_system_admin`）需要一个面向人的跨空间管理界面，承载流 B 一期的后端能力（`/console/api/admin/*`：空间/成员/系统管理员/审计）。

**已确认的三个形态决策**：

1. 独立路由 `/admin`（不嵌入设置弹窗）
2. 跨空间成员为独立页面（按人聚合视角）
3. `/admin` 内部左侧二级导航 + 右侧内容区（与 console 视觉一致）

**2026-08-26 范围扩展（用户确认）**：插件/工具统一管理与 LLM 凭据集中管理**均纳入一期**。插件/工具采用「中央托管 + 按空间扇出」模式（daemon 安装是租户级，扇出复用现有安装链；**2026-08-30 动作模型定稿：四动词 装/升/改范围/回收**）；LLM 凭据为组织级凭据（**2026-08-27 收窄：一期全量组织统一**；~~2026-08-30 显式分派模型~~；**2026-09-02 两级模型定稿：配置位置即作用域——组织统一兜底 + 空间详情单独配置，取消分派表**；动热路径，需完整回归）。

**非目标（一期不做）**：审计导出 CSV、跨空间批量编辑成员、概览仪表盘、MCP 服务器托管（连接实例型，不适用扇出模式，维持空间自建）。

## 2. 信息架构与路由

```
/admin                        → 重定向 /admin/workspaces
/admin/workspaces             空间列表
/admin/workspaces/[id]        空间详情（基本信息 + 成员 + 集成 + 危险区）
/admin/members                跨空间成员
集成（一级分组）
  /admin/plugins                插件管理（行操作：改范围/移除；类型过滤覆盖工具/模型/数据源/触发器/Agent 策略 + 右上「安装插件」三源下拉：插件市场跳页、GitHub/本地集成包页内弹窗；升级无行内按钮、经安装流升级态）
  /admin/model-providers        模型提供商（组织级凭据，凭据操作行内化）
/admin/marketplace            插件市场（市场浏览与安装：搜索/分类/卡片「安装」；GitHub 与本地集成包入口在插件管理页下拉）
/admin/admins                 系统管理员
/admin/audit-logs             审计日志
```

- 路由组 `web/app/admin/`，**独立 layout**，不挂 `(commonLayout)` 的工作空间上下文依赖（系统管理员可能不属于任何空间）。
- 左侧导航（2026-09-03 定稿）：工作空间/成员/系统管理员/审计日志为**一级项**（无组头）；**集成**为唯一可收起组——与其他一级项**同款样式**（图标 + 14px 常规字重），右侧 chevron 收起/展开子项（含 插件管理/模型提供商/插件市场——插件市场由一级项归入集成组），子项以树形引导线缩进。**MCP 服务器不纳入托管**（连接实例型，见 §4.7），原「工具」二级分组取消，工具插件由插件管理页类型过滤承载。
- 侧栏底部账号菜单（2026-09-03）：点击头像展开——偏好设置（界面语言/通知弹窗）、外观（浅色/深色/跟随系统弹窗）、版本（静态行）、登出。
- 空间详情为**全屏视图**（2026-09-03）：进入时隐藏左侧导航、内容占满主区，「返回」恢复侧栏并回到来源页。
- 安装入口（2026-09-01 修订）：插件管理页右上「安装插件」下拉（插件市场跳页 / GitHub 弹窗 / 本地集成包弹窗）+ 插件市场页卡片安装，两处共用同一确认弹窗（新装=选范围；命中已管理插件=自动切升级态，见 §4.6），安装逻辑单点维护；原「插件中心三源 tab」口径作废。

## 3. 入口与守卫

- 入口：头像下拉菜单新增「系统管理」，仅 `is_system_admin` 为真时渲染；普通用户无感知。
- `is_system_admin` 由后端在 `/account/profile` 下发（system-features 不动，与总体方案 §6.1 一致）；**创始人标记（source=install）一并下发**，用于系统管理员页按钮显隐（安全靠后端 403，2026-09-02）。
- 守卫：`/admin` layout 层校验，非系统管理员 → 403 页；无空间的系统管理员正常进入（依赖后端 `load_user` 窄分支，见总体方案 §6.1.1）。
- 无空间的普通账号登录失败并得到明确引导文案（复用 login 既有 fail 响应，引导联系系统管理员开通空间），不建立会话、不进入任何控制台页。
- **租户定位模型**：admin 后台无"当前空间"上下文（区别于普通控制台的 current_tenant + 切换器）——目标租户全部显式指定：路径参数（`/admin/workspaces/<id>/…`）、查询参数（审计 `?workspace_id=`）、表单选择（建空间 owner、插件分发范围）。服务端鉴权只看 `is_system_admin`，不要求系统管理员是目标空间成员（**唯一例外**：授予/撤销/转让三个名单管理端点额外要求创始人身份，见 §4.4）；每个管理动作审计记 `workspace_id`（组织级动作记 NULL）。
- **管辖范围（2026-08-27 确认）**：Dify 中**工作空间=租户**（一级结构，`tenants` 表）。系统管理员为**部署级**——管辖本部署下全部空间；不采用"组织>空间"两级模型（多组织 SaaS 形态），若未来需要再议。

## 4. 页面设计

### 4.1 空间列表 `/admin/workspaces`

- 顶部：搜索框（空间名）、状态过滤（全部/正常/已归档）、「创建空间」按钮。
- 表格列：空间名、owner（姓名+邮箱）、成员数、状态徽标、创建时间、操作（详情）。
- 「创建空间」弹窗：空间名 + owner 邮箱。owner 已注册且 active → 直加并置 owner；未注册 → PENDING 预创建（复用邀请状态机）。弹窗内明确提示两种结果。
- 行点击 → 空间详情页。

### 4.2 空间详情 `/admin/workspaces/[id]`

- **全屏页级视图**（2026-09-03）：进入详情隐藏左侧导航、内容占满主区；「← 返回」恢复侧栏并回到来源页（空间列表或成员页）。
- 头部：空间名（可编辑）、状态徽标、创建时间。
- 成员 tab：成员表格（头像/姓名/邮箱/角色/加入时间）；操作：加成员（邮箱+角色选择）、改角色、移除。
- **集成 tab**（重新设计，系统管理员视角的该空间集成全景，只读 + 跳托管页调整）：
  - **插件与工具**：该空间可见插件列表（名称/类型/版本/来源徽标/状态）——一期来源只有「托管分发」（空间侧无自装入口，存量自装为迁移遗留标记「空间自装」）
  - **凭据与授权（2026-09-02 起可配置，配置位置即作用域）**：模型供应商三态徽标——**组织统一 / 单独配置 / 未配置**（未配置=插件已装但两级均无凭据，解耦后正常态）；行内「单独配置」为本 tab 的凭据写入口（管理员为该空间配置，存在即生效、优先于组织统一，删除即回落组织统一，机制同组织级：多凭据/切换/模型开关；**交互链路同 §4.7**——凭据管理浮层 + 授权配置弹窗 + 配置模型弹窗，作用域徽标=该空间·单独配置）。工具插件凭据一期维持组织级（徽标两态：组织统一/未配置，无本 tab 写入口，2026-09-02 决策）
  - **数据源 / 触发器**：一期维持空间自配、不属于托管分发对象，集成 tab 不展示分发项
- 底部危险区：归档/启用。二次确认弹窗写明影响（成员登录将切换到其他空间、空间内应用不可访问）。

### 4.3 跨空间成员 `/admin/members`

- 按人聚合表格：姓名、邮箱、所属空间徽标组（如「空间A·owner」「空间B·editor」，**超 3 个折叠为「+N」**）、最后活跃时间。
- **行展开看全量空间**（2026-09-02 补，多空间多角色主查看路径）：点击行展开下方子行，逐行列出该成员的每个空间——空间名（可点，跳转该空间详情）· 角色徽标 · 加入时间；「所属空间」格内的徽标与折叠计数只是摘要，完整清单在展开区。展开为纯展示，管理动作（改角色/移除）仍在对应空间详情的成员 tab（显式空间上下文，避免误操作）。
- 过滤：搜索（姓名/邮箱）+ 空间下拉（过滤后仅显示命中空间的行，展开区同样只列命中空间）。
- 行操作：跳转对应空间详情。
- 一期不做跨空间批量编辑。

### 4.4 系统管理员 `/admin/admins`（两级模型，2026-09-02 定稿）

- **两级管理员**：**创始人管理员**（/install 激活、`system_admin_source=install`，全部署恒一位）独占**管理员名单管理权——授予、撤销、转让**；**普通系统管理员**（env/邀请/授予来源）其余管理功能全部可用，本页对其**只读**（列表可见，操作按钮不出现；后端端点 403 兜底）。创始人标记随 `/account/profile` 下发用于按钮显隐。
- 列表列：姓名、邮箱、来源徽标（**部署初始化（/install）** / 环境变量 / 邮箱邀请 / 系统授予）、状态徽标（正常 / **待激活**）、授予人、授予时间、操作。
- 「授予」弹窗（邮箱邀请制，2026-08-30；**仅创始人可见**）：邮箱输入 + **当前账号密码确认**（验证操作者）；两路径--
  - 邮箱已注册且 active：直接生效，发通知邮件，列表即时出现（状态「正常」）；
  - 邮箱未注册：**PENDING 预创建**，发邀请邮件（激活链接），列表出现「待激活」行；激活前可撤销（等同作废邀请）。
  - **邮件发送失败降级**：授予结果处展示**邀请链接供复制转交**（不阻塞授予，落审计「邮件发送失败」）。
- 「撤销」（仅创始人）：密码确认弹窗；**创始人不可自撤**（防无创始人锁死；转让是唯一身份让渡路径）——创始人行不出现撤销按钮；~~最后一位系统管理员禁撤~~（两级模型下普通管理员无撤销权，原末位保护由「创始人恒一位 + 不可自撤」替代，2026-09-02）；来源为环境变量的条目撤销禁用并标注「来自环境变量，需修改配置」；待激活邀请可撤销（作废）不变。
- 「转让」（仅创始人，2026-09-02 新增）：创始人身份转让给一位**现有普通系统管理员**（密码确认 + 目标下拉）；**转让后原创始人变普通系统管理员**（本页随之变只读）。
- **部署落地（2026-09-02 用户确认）**：生产全新部署，/install 置位创始人；QA 已跑过 /install，上线时**改库标记 source 或清数据重跑 /install**（本部署无存量升级场景；env 名单保留为静态应急通道，注入者为普通级无名单管理权）。

### 4.5 审计日志 `/admin/audit-logs`

- 过滤条：操作类型（空间创建/归档/启用/成员变更/系统管理员变更/集成托管变更/凭据变更…）、操作人、目标空间、时间范围。
- 表格列：时间、操作人、动作、目标（空间/成员/插件）、详情（可展开 JSON）。
- 分页加载。
- **集成类必记事件**（实施埋点清单）：`integration.install`（含来源与范围）、`integration.scope_change`（**收缩方向必含 reason**，见 §4.6）、`integration.upgrade_push`（升级波触发，含目标版本；回滚/漂移修复同事件、direction 字段区分）、`integration.revoke`（回收）、`integration.unmanaged`（解除托管）、`credential.create/update/delete`（组织级记 NULL workspace_id、空间详情单独配置记该空间，2026-09-02）、`admin.grant_invite`（管理员授予：含已注册直效/未注册邀请两路径与邮件发送结果）、`admin.revoke`、`admin.transfer`（创始人身份转让，含目标账号，2026-09-02）。（~~`credential.assignment_change`~~ 与 ~~`credential.scope_change`~~ 均取消——分派表已随 2026-09-02 两级模型作废、凭据范围与插件分发解耦后无凭据范围概念；MCP 不托管、无对应事件。）这些事件的安全/成本权重高于空间管理类（插件分发=供应链面，凭据=成本与数据出域阀门）。

### 4.6 插件管理 `/admin/plugins`（原"插件与工具"）

**模式**：中央托管 + 按空间扇出，**admin 四动词：装、升、改范围、回收**（2026-08-30 定稿；2026-09-01 UI 动词层收敛为普通词——安装/升级/改范围/移除，「托管/回收/解除托管」退为实现层与审计事件词汇）。托管记录（`integration_grants`：plugin_id × version × source × 范围 × 状态）；安装由插件管理页右上「安装插件」下拉（插件市场跳页 / GitHub / 本地集成包弹窗）或插件市场页卡片发起（表单即选范围、默认全部空间，**无独立「分配」动作**）；`scope=全部` 的托管项在空间创建时自动安装（钩子补未来、扇出扫描补存量，竞态闭合）。**空间侧锁定靠四道 api 层防线**（noone 收口 / 托管态 403 拦截 / 自动升级任务过滤 / `/permission/change` 锁改，见总体方案 §6.4），daemon 不兜底。

- 顶部：类型过滤（工具/模型/数据源/触发器/Agent 策略）+ 搜索 + 右上**「安装插件」下拉**（2026-09-01：插件市场跳页 / GitHub 弹窗 / 本地集成包弹窗；原「无安装按钮」口径作废）。
- 表格列：插件（图标+名称）、类型徽标、版本（公网部署下行内**「市场有 vX」新版本徽标**——grant 版本落后市场 latest 时显示，复用上游 `list/latest-versions` 批量查询与 Redis 缓存、组织级调用；点击进入安装流升级态）、**适用范围**（「全部空间」/「指定空间 · N」徽标）、覆盖状态（成功/失败空间数，波次结果口径）、波次状态（active/recycling 徽标）、操作（改范围/移除）。
- **升级（2026-09-01 定稿：无行内升级按钮，升级=安装流升级态）**：安装表单识别 plugin_id 命中既有托管时自动切换为升级态——版本对比（grant vX -> 源/包解析的 vY）、**范围不动**（改范围是独立动作）、确认按钮**动态副文案显式目标版本**三态：「将 N 个空间从 vX 升级到 vY」（vY>vX）/「回滚 N 个空间到 vY」（vY<vX）/「向 N 个空间分发 vX，已是该版本的空间自动跳过」（vY=vX，幂等重分发）；确认后更新 grant.version + 收敛波（只动实际版本不符的空间）。**复用上游手动升级服务层链**：市场/GitHub 走 `upgrade_plugin_with_marketplace/github`（静态方法显式传 tenant_id，非工作台端点），本地包走「卸载(preserve_credentials=true)+重装」（上游 `useInstallOrUpdate` 同款，凭据保留；幂等：卸载查无返回 success、已装返回 AllInstalled）；**取包源与安装来源解耦**（grant.source 随最近一次取包更新）。**何时提示升级**：公网部署靠市场新版本徽标；内部自研插件不在市场、无信号，仍意图驱动（经「安装插件」传包）。**不做版本挑选 UI**（市场卡片/版本选择器与 GitHub release 表单即版本来源，上游已有）。
- **改范围**：双向自由（试点是回环非单向漏斗；单向限制会删掉唯一 undo 路径）。弹窗单选全部空间/指定空间（后者多选清单）+ 保存即波（202 + 进度句柄）；**收缩方向**（含全量->指定、缩清单）：保存即生效（无确认框、无门原则），事前 toast 静态警示「范围外空间若正在使用将无法运行」+ **reason 必填**进审计 + 向被移除空间发通知；扩围方向无警示。
- **移除（2026-09-01 定稿：解除托管/回收合并为一个入口、弹窗二选一；语义与审计事件不合并）**：点「移除」弹窗问「已安装该插件的 N 个空间，如何处理」——○ **保留在各空间**（默认）：仅移除管理记录，插件留在各空间、**冻结在当前版本**继续可用（空间侧无升级路径，一期防线下无人能升），无波次（=解除托管，安全阀：扇出错版本/波次故障时的止血通道，重新托管即恢复）；○ **从所有空间卸载**：静态警示「正在使用的应用将无法运行。已配置的工具凭据将一并删除，将来重新安装时需重新配置」，grant -> recycling 波次徽标 + 失败可重试 -> 卸载波完成 -> 删记录（波次部分失败时 grant 留 recycling 可续重试，防孤儿安装）。**弹窗文案不出现「托管」术语**（用安装/卸载/保留等具体动作词）；两分支对应审计事件 `integration.unmanaged` / `integration.revoke` 不变。误触成本不对称故默认轻选项：保留错了=重新托管便宜；卸载错了=凭据全删需重配。
- 工具插件不设独立子页，由本页类型过滤（工具）承载；**MCP 服务器不纳入托管**（连接实例型，无"插件包+凭据"分离结构，不适用扇出模式，维持空间自建）；组织级 MCP 若做走目录/白名单模型，二期独立立项。
- **漂移呈现一期不做**（2026-09-01 用户决策）：无「N 个空间版本不一致」徽标、无对账「一致性检查」入口（随漂移一并移至二期）；收敛波「只动版本不符空间」的幂等语义保留为实现行为，覆盖状态列仅呈现波次结果（成功/失败空间数），失败重试入口不变。

### 4.7 模型提供商 `/admin/model-providers`（组织级凭据）

- 架构前提：**模型提供商本身是插件**（模型供应商已全面插件化，见插件手册 §5.1）——提供商插件的安装走「安装插件」下拉（插件市场/GitHub/本地集成包）或插件市场页卡片，本页管**组织级凭据**。
- **列表形态（2026-09-02 修订：表格 → 卡片，照上游 QA 实证结构）**：列表 = 所有已托管的模型提供商插件，每张卡片 = 图标 + 名称 + 版本徽标（mono）+ 模型类型徽标（LLM/TEXT EMBEDDING…）+ **右侧凭据面板三态**（已配置 = ● 当前凭据名（多凭据标「等 N 个」）+「配置」按钮；未配置 =「需要配置 API Key」+「添加 API 密钥」；插件未安装 =「去安装」跳插件市场）+「N 个模型 ›」点击开**模型清单抽屉**（2026-09-03 修订：行内展开 → 右侧抽屉，与工作台设计稿 §3.3.1 空间侧模型清单抽屉同语言；**管理台版为可操作抽屉**：按类型分组，模型行 = mono 模型名 + 类型/上下文徽标 + **凭据指定状态**（供应商管理 / 负载均衡·N 组徽标）+「配置」按钮 + 启用开关，底部「+ 添加模型」；工作台侧为只读抽屉）。凭据属于具体提供商，不做全局添加按钮。**管理台增量**：卡片作用域行标注「组织统一 · 对全部空间兜底（含未来新建）」，存在空间单独配置时加「N 个空间已单独配置」。
- **凭据/模型配置交互链路（2026-09-02 照上游 `model-auth` QA 实证，两级共用）**：
  - 点卡片「配置」→ **凭据管理浮层**（对应上游 Authorized popover）：凭据列表（状态点 + 凭据名 + 脱敏 key + 当前 ✓，hover 出行内编辑/删除，点选即切换当前凭据）+ 底部「添加 API 密钥」+ 作用域提示行；**无凭据时跳过浮层直达表单**（上游 `triggerOnlyOpenModal` 同款）
  - 添加/编辑凭据 → **「API 密钥授权配置」弹窗**（对应上游 model-modal）：凭据名称 + schema 驱动字段 +「从 XX 获取 API Key ↗」链接 + 底部加密通栏（PKCS1_OAEP）；**头部作用域徽标区分两级**（组织统一 / 空间名·单独配置）
  - 模型行「配置」→ **「配置模型」弹窗**（对应上游 model-load-balancing-modal）：模型行（图标+名+徽标）+「由模型供应商管理（单组凭据=当前凭据）」vs「负载均衡（多组凭据自动调用）」选择卡；LB 态展开凭据组列表（逐组选凭据 + 启停开关 + 移除，**<2 组启用时保存禁用**）
- 页面右上角仅「安装提供商插件」（跳插件市场）。
- **两级模型（2026-09-02 定稿，配置位置即作用域，替代 08-30 显式分派方案）**：
  - **本页配置 = 组织统一**：凭据对全部空间生效，是无单独配置空间的兜底（含未来新建空间，开箱即用）；
  - **空间详情集成 tab 内配置 = 该空间单独配置**：行内「单独配置」入口，管理员为该空间写入自己的凭据（该空间租户原生凭据行），**存在即生效、优先于组织统一；删除即回落组织统一**。不要求组织级先配过；同一套配置弹窗（多凭据/切换/模型开关）。
  - 解析规则一条：**空间有单独配置用单独的，没有用组织兜底**——无指针表、无优先级嵌套；「该空间在用哪份」由空间详情集成 tab 三态徽标（组织统一/单独配置/未配置）一眼可答。**分派表 `provider_credential_assignments` 取消**（08-30 显式指针方案作废，状态 = 空间凭据行是否存在，直查）。
  - **存储与机制（复用上游全套）**：组织级凭据 = **专设锚租户上的原生 `ProviderCredential` 行**（加密锚点方案 A 语义保留：锚租户 RSA；锚租户从「仅加密锚点」升格为「组织凭据宿主」，须为专设租户非真实空间）；单独配置 = 空间自己租户的凭据行。**多凭据 + 按模型指定/切换凭据 + 负载均衡 + 逐模型开关（`ProviderModelSetting.enabled`）+ 自定义模型在两级均原生支持**——admin 端点做锚租户/目标租户的代理读写，掩码只进不出。
  - **模型开关跟随凭据来源**：单独配置空间用自己租户的模型开关行；组织统一空间用锚租户的。一个解析维度，不做两级开关叠加。
  - **动 ProviderManager 热路径，配完整回归**（解析链：本租户凭据行 → 锚租户行；两级配置变更均失效对应缓存）。
- **二期形态（2026-09-02 重述）**：① 工具插件凭据同规则进空间详情（机制相同，一期未做仅因范围收敛）；② OAuth 组织代授权与触发器订阅共享复用同一两级模型（token 归属 = 单独配置优先/组织兜底）；③ 若要开放「空间成员自配」（放权给空间 owner/admin 自行配 key）为独立决策另议——上游凭据端点无角色门槛（仅 `login_required`），放权须先加权限门。
- **范围解耦的边界提示（2026-08-30，2026-09-02 沿用）**：可能出现「空间装了插件但两级均无凭据」的正常态（相关模型/工具不可用，状态由空间详情集成 tab 呈现）；不以「插件范围」作凭据可用性的前置约束（插件范围管装不装、凭据两级管用哪份，两维度正交）。
- **各集成类型的分期口径**（类型只定节奏，不做默认策略开关）：

  | 类型 | 一期 | 二期 |
  |---|---|---|
  | 模型供应商 + 工具插件（Key/Secret 类） | 组织统一凭据（本页 + 工具插件行内「配置凭据」）；**模型供应商另支持空间详情单独配置（2026-09-02）**，工具插件一期仅组织级 | 工具插件凭据同规则进空间详情 |
  | OAuth 授权类（数据源 Notion/Google Drive、部分触发器） | **一期不开放**（2026-08-31 修订：原「空间自行授权」——工作台侧数据来源整体不开放、无入口，空间自授权无从发生） | 组织代授权（复用同一两级模型，token 归属 = 单独配置优先/组织兜底） |
  | 触发器订阅/Webhook 秘钥 | **一期不开放**（2026-08-31 修订：原「空间自行配置」——触发器一期不用、不分发） | 同上 |
  | **MCP 服务器 / OpenAPI 服务** | 空间自建（不托管） | 若集中治理走**目录/白名单模型**（登记可信服务器，空间从目录选择），非分派模型 |
  | Agent 策略 | 插件分发范围治理（无凭据） | 同左 |

  即：**凭据分派仅适用于"插件包 + 凭据"可分离的类型**（模型插件、工具插件、OAuth 数据源）；连接实例型（MCP/OpenAPI）走目录模型、无凭据型（Agent 策略）只受插件分发治理，三者不互相从属。
- **配置需求不止模型**（组织级配置为通用能力，按类型分期）：
  - Key/Secret 类（模型、**工具**如搜索 key）：一期纳入组织级凭据；工具插件行内加「配置凭据」（组织级）；模型供应商两级（本页 + 空间详情单独配置）
  - OAuth 授权类（数据源 Notion/Google Drive、部分触发器）：需跳第三方授权页，token 归属/刷新复杂——**一期不开放（2026-08-31 修订：原「空间自行授权」，工作台侧入口已整体关闭），组织级代授权二期**
  - 触发器的订阅/Webhook 秘钥：**一期不开放（2026-08-31 修订：原「空间自行配置」，触发器一期不用）**
- **配套收口（2026-08-31；2026-09-02 补充）**：空间侧「添加模型」收走（工作台设计稿 §3.3.1）——本页组织级凭据配置需承载模型清单管理（自定义模型随凭据配置）；「默认模型设置」保留在空间侧页面顶层（空间级，同现状），组织级无需承载。**配置弹窗完整承载上游能力（2026-09-02 用户要求）**：多凭据管理（加/删/命名）、按模型指定或轮询凭据（负载均衡）、逐模型启用开关——两级配置（本页与空间详情）共用同一套弹窗组件，复用上游 `model-auth`/模型清单机制。
- **凭据/模型表单必须 schema 驱动（2026-08-31 用户强调）**：不同供应商的凭据字段与表单 UI 各不相同（如 Azure 的 endpoint/deployment/api-version、OpenAI 的组织 ID 等），「配置凭据」「添加模型」弹窗**复用现有空间侧供应商页的动态表单机制**——按插件 declaration 的 `provider_credential_schema` / `model_credential_schema` 渲染，**不做固定字段表单**。
- 空间详情「集成」tab：该空间已装插件/工具的视图 + 跳托管页调整；**凭据区为模型供应商的单独配置写入口**（三态徽标 + 行内「单独配置」，见 §4.2；交互链路同本页——凭据管理浮层 + 授权配置弹窗 + 配置模型弹窗，作用域徽标=空间名·单独配置；工具插件凭据一期只读徽标）。

## 5. 数据流与技术约定

- 服务层新增 `web/service/admin/`（TanStack Query hooks，风格仿 `web/service/access-control/`）；后端端点即总体方案 §6.2 的 `/console/api/admin/*`。
- 所有变更操作后 `invalidateQueries` 对应列表。
- 组件：`@langgenius/dify-ui` primitives + Tailwind v4 token；表格/弹窗样式对齐现有 `members-page`、`access-rules-page`。
- i18n：新增 `admin.json` 命名空间（zh-Hans / en）。
- 密码确认弹窗为复用组件（授予/撤销/归档共用）。

## 6. 异常与边界

| 场景 | 行为 |
|---|---|
| 非系统管理员访问 `/admin/*` | 403 页 |
| 无空间普通账号登录 | 登录失败 + 引导文案（联系系统管理员开通空间），不建立会话 |
| 归档空间 | 二次确认（列明影响），写审计 |
| 归档成员仅有的空间 | 登录得明确失败提示（login 既有 "workspace not found" 响应），引导联系系统管理员 |
| 授予管理员：邮箱不存在/未激活 | 弹窗内明确报错 |
| 撤销 env 来源管理员 | 按钮禁用 + 提示改配置 |
| 创始人自撤 | 创始人行无撤销入口（防无创始人锁死；转让是唯一让渡路径） |
| 普通管理员访问授予/撤销/转让 | 页面只读（按钮不出现）；直连端点 403 |
