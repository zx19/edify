# PRD：系统管理控制台（流 B 一期）

> 版本：v1.0（2026-08-27）
> 关联文档：UI 设计稿 `2026-08-26-系统管理控制台UI-design.md`、可交互原型 `2026-08-26-系统管理控制台UI-mockup.html`、后端方案《权限体系自研总体方案-模型A》流 B
> 读者：工程团队 + 管理层（完整版）

## 1. 执行摘要

### 问题陈述

社区版 Dify 缺乏组织级管理能力：工作空间创建依赖初始化流程或注册开关、无跨空间管理视图、插件/模型凭据逐空间重复配置、管理操作无审计痕迹。这些能力是本平台上线的交付内容之一，缺失则无法上线多团队使用。

### 方案概述

新增独立路由 `/admin` 的系统管理控制台，面向系统管理员提供：工作空间全生命周期管理（创建/归档/成员）、跨空间成员视图、系统管理员授予与撤销、审计日志、插件/工具的中央托管与按空间分发、组织级模型凭据（含配置策略）。配套改造 `/install` 为仅初始化系统管理员（不建空间），并放行无空间系统管理员的登录路径。

### 成功标准（量化指标为建议值，标注 *，待评审确认）

| # | 指标 | 目标 |
|---|---|---|
| 1 | 系统管理员完成"建空间 + 指定 owner + 加 3 名成员"全流程 | ≤ 3 分钟 *，全程 UI 无后端介入 |
| 2 | 插件统一安装并分发到 12 个空间的成功率 | ≥ 99%，失败空间可见可重试 |
| 3 | 管理操作审计覆盖率（空间/成员/管理员/凭据/插件托管动作） | 100% |
| 4 | 非系统管理员访问 `/admin/*` 的拦截率 | 100%（403），普通用户路径零回归 |
| 5 | 组织凭据回退正确性：空间自有/组织/未配置三态解析准确率 | 100%（模型调用全链路回归） |

## 2. 用户体验与功能

### 用户角色

| 角色 | 描述 |
|---|---|
| 系统管理员 | 平台运维/平台组，管全部空间与集成；可为无空间的纯管理账号 |
| 空间 Owner/Admin | 各空间自治管理（成员、集成自配），权限不变 |
| 普通成员 | 无感知（看不到系统管理入口） |

### 用户故事与验收标准

**US-1 系统初始化（install 瘦身）**
> 作为部署者，我希望 /install 只创建系统管理员账号、不建空间，以便空间全部由管理动作产生。

- AC1：`/install` 仅创建账号（email+密码）并置 `is_system_admin`，写 `DifySetup` 后关闭
- AC2：首登无空间系统管理员正常进入 `/admin`（load_user 窄分支放行）
- AC3：无空间普通账号登录被引导至提示页；有空间账号行为不变（回归）

**US-2 工作空间管理**
> 作为系统管理员，我希望创建/归档空间并指定 owner，以便按团队开通环境。

- AC1：创建空间支持已注册 owner（直加）与未注册 owner（PENDING 预创建）两分支
- AC2：归档需二次确认（列明影响）；归档空间成员登录自动切换可用空间；一期不做物理删除
- AC3：全部动作写 `admin_audit_logs`

**US-3 跨空间成员管理**
> 作为系统管理员，我希望按人查看其在各空间的角色，以便审计与排障。

- AC1：成员页按人聚合展示「空间·角色」徽标组；支持搜索与空间过滤
- AC2：空间详情内可加人/改角色/移除，生效即时

**US-4 系统管理员管理**
> 作为系统管理员，我希望授予/撤销其他系统管理员，以便多人协作运维。

- AC1：仅可授予已注册且 active 账号；授予/撤销需当前账号密码确认
- AC2：最后一位系统管理员不可撤销；env 名单来源的条目控制台不可撤（标注来源）
- AC3：全量写审计

**US-5 插件托管与分发**
> 作为系统管理员，我希望插件装一次就能分发给全部或指定空间，以便统一版本与安全管控。

- AC1：插件中心三源安装（市场卡片/GitHub URL+版本/本地 .difypkg），安装时选范围（默认全部空间，含未来新建）
- AC2：托管列表展示范围/分发状态（含失败空间可重试）；支持改范围、推送升级（上传新版本扇出）、回收（对空间卸载）
- AC3：托管插件空间侧锁定（不可自行升级/卸载、不参与空间自动更新）
- AC4：新建空间自动安装 scope=全部的托管插件
- AC5：QA 内网市场不可达时明确降级提示并引导本地上传

**US-6 组织级凭据与配置策略**
> 作为系统管理员，我希望决定每个凭据项是组织统一配置还是空间自配，以便成本与安全收口。

- AC1：模型/工具（Key/Secret 类）支持组织级凭据；解析优先级：空间自有 > 组织回退
- AC2：策略开关 per 凭据项：空间自配（默认）/ 组织统一（空间侧锁定）；OAuth 类一期仅空间自配
- AC3：凭据范围 ⊆ 插件分发范围（弹窗只读展示插件范围，默认跟随、可收窄子集）
- AC4：策略切换遮蔽而非删除空间凭据；变更按 tenant 失效解析缓存
- AC5：凭据掩码只进不出（sk-…****）

**US-7 审计日志**
> 作为系统管理员，我希望按操作人/动作/空间/时间查询管理操作记录。

- AC1：覆盖空间/成员/系统管理员/**凭据（增删改/分配/策略切换）/插件托管（安装/分发/升级/回收）/MCP 登记**全部动作，含操作者、目标、参数明细（集成类事件清单见设计稿 §4.5）
- AC2：支持多维过滤与分页；一期不做导出

**US-8 空间集成视图**
> 作为系统管理员，我希望在空间详情看到该空间的插件、凭据状态全景。

- AC1：集成 tab 展示插件（托管分发/空间自装来源徽标）、凭据四态（空间自有/组织回退/组织统一·锁定/未配置）、MCP/数据源/触发器已分发项

### 非目标（一期不做）

- RBAC 本地化（流 A）与细粒度资源授权；ABAC；权限组
- OAuth 类组织代授权、触发器订阅共享（二期）
- 空间物理删除；审计导出 CSV；概览仪表盘；跨空间批量编辑成员
- MCP/OpenAPI 连接实例的凭据策略（连接实例型不适用策略模型，仅托管分发/空间自建）

## 3. 技术规格

### 架构与数据流

- 前端：`web/app/admin/` 独立路由组 + 独立 layout（不依赖 workspace context）；TanStack Query hooks 新增 `web/service/admin/`；dify-ui + Tailwind v4；i18n 新增 `admin.json`
- 后端：新命名空间 `/console/api/admin/*`，装饰器 `@system_admin_required`（会话 + `SYSTEM_ADMIN_EMAILS` ∪ `accounts.is_system_admin` 并集判定）；业务复用 `TenantService`/`RegisterService`
- 新增表：`admin_audit_logs`、`integration_grants`（插件托管记录）、组织级凭据表；`accounts` 加 `is_system_admin` 列
- 插件分发：托管记录 + 逐 tenant 扇出（复用现有安装链）+ 空间创建钩子
- 凭据回退：ProviderManager 解析链加组织级回退层 + 按 tenant 缓存失效
- bootstrap：`AccountService.setup()` 去建空间、置系统管理员标记；`load_user` 无空间窄分支（仅 is_system_admin 放行）

### 集成点与安全

- 鉴权：`@system_admin_required`；机器通道 `ADMIN_API_KEY` 保留并存
- 高危操作：授予/撤销系统管理员需密码确认；归档二次确认；末位管理员禁撤
- 凭据：加密存储、掩码展示、只进不出；审计全量落库
- 失败回滚：install 置位落在 setup 既有回滚范围内

## 4. 风险与路线

### 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| `load_user`/`ProviderManager` 热路径改造引入回归 | 高 | 窄分支 + 全链路回归 + QA 灰度 |
| 插件扇出部分空间失败 | 中 | 分发状态可见 + 重试；安装异步任务化 |
| QA 内网市场/GitHub 不可达 | 中 | 插件中心内网降级提示 + 本地上传 |
| 凭据回退语义误解（空间覆盖组织） | 中 | UI 明示优先级 + 空间详情四态视图 |

### 路线

- **一期（上线必做）**：bootstrap 瘦身 + 空间/成员/系统管理员/审计 + 插件托管分发 + 组织级凭据（Key/Secret）——约 6.5-8 人日 + 凭据回退改造（另估，≥5 人日）
- **二期**：OAuth 组织代授权、触发器订阅共享、审计导出
- **三期（需求驱动）**：流 A RBAC 本地化、集中凭据与 RBAC 组织角色合流
