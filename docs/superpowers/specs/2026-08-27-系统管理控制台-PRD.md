## 1. 执行摘要

### 问题陈述

社区版 Dify 缺乏组织级管理能力：工作空间创建依赖初始化流程或注册开关、无跨空间管理视图、插件/模型凭据逐空间重复配置、管理操作无审计痕迹。这些能力是本平台上线的交付内容之一，缺失则无法上线多团队使用。

### 方案概述

新增独立路由 `/admin` 的系统管理控制台，面向系统管理员提供：工作空间全生命周期管理（创建/归档/成员）、跨空间成员视图、系统管理员授予与撤销、审计日志、插件/工具的中央托管与按空间分发、组织级模型凭据（一期全部组织统一，空间侧只读、无回退层）。配套改造 `/install` 为仅初始化系统管理员（不建空间），并放行无空间系统管理员的登录路径。

### 成功标准（量化指标为建议值，标注 *，待评审确认）

| # | 指标 | 目标 |
|---|---|---|
| 1 | 系统管理员完成"建空间 + 指定 owner + 加 3 名成员"全流程 | ≤ 3 分钟 *，全程 UI 无后端介入 |
| 2 | 插件统一安装并分发到 12 个空间的成功率 | ≥ 99%，失败空间可见可重试 |
| 3 | 管理操作审计覆盖率（空间/成员/管理员/凭据/插件托管动作） | 100% |
| 4 | 非系统管理员访问 `/admin/*` 的拦截率 | 100%（403），普通用户路径零回归 |
| 5 | 组织凭据解析正确性：组织统一/未配置两态（一期无空间自有凭据与回退层） | 100%（模型调用全链路回归） |

## 2. 用户体验与功能

### 用户角色

| 角色 | 描述 |
|---|---|
| 系统管理员 | 平台运维/平台组，管全部空间与集成；可为无空间的纯管理账号 |
| 空间 Owner/Admin | 各空间自治管理（成员、集成自配），权限不变 |
| 普通成员 | 无感知（看不到系统管理入口） |

### 用户故事与验收标准

**US-1 系统初始化（install 瘦身）**
> 作为部署者，我希望 /install 只创建系统管理员账号、不建空间，以便空间全部由管理动作产生。

- AC1：`/install` 仅创建账号（email+密码）并置 `is_system_admin`，写 `DifySetup` 后关闭
- AC2：首登无空间系统管理员正常进入 `/admin`（load_user 窄分支放行）
- AC3：无空间普通账号登录失败并得到明确引导文案（复用 login 既有 "workspace not found" fail 响应，引导联系系统管理员），不建立会话；有空间账号行为不变（回归）

**US-2 工作空间管理**
> 作为系统管理员，我希望创建/归档空间并指定 owner，以便按团队开通环境。

- AC1：创建空间支持已注册 owner（直加）与未注册 owner（PENDING 预创建）两分支
- AC2：归档需二次确认（列明影响）；归档空间成员登录自动切换可用空间（多空间）；仅有的空间被归档则登录得明确失败提示（同一无空间口径）；一期不做物理删除
- AC3：全部动作写 `admin_audit_logs`

**US-3 跨空间成员管理**
> 作为系统管理员，我希望按人查看其在各空间的角色，以便审计与排障。

- AC1：成员页按人聚合展示「空间·角色」徽标组；支持搜索与空间过滤
- AC2：空间详情内可加人/改角色/移除，生效即时

**US-4 系统管理员管理**
> 作为系统管理员，我希望授予/撤销其他系统管理员，以便多人协作运维。

- AC1（2026-08-30 邮箱邀请制）：邮箱**已注册且 active** -> 密码确认后直接生效并发通知邮件；**未注册** -> PENDING 预创建 + 邀请邮件（激活链接 `/activate?token=...`），激活后首登直达 `/admin`；防滥用靠邀请 token 时效与一次性
- AC2：最后一位系统管理员不可撤销（待激活账号计入在位数）；env 名单来源的条目控制台不可撤（标注来源）；待激活邀请可撤销（作废）
- AC3：全量写审计（含邮件发送结果）；**SMTP 失败不阻塞授予**：控制台展示邀请链接供手动转交

**US-5 插件托管与分发**
> 作为系统管理员，我希望插件装一次就能分发给全部或指定空间，以便统一版本与安全管控。

- AC1：插件中心三源安装（市场卡片/GitHub URL+版本/本地 .difypkg），安装时选范围（默认全部空间，含未来新建）
- AC2：托管列表展示范围/分发状态/波次状态（含失败空间可重试）；四动词：**升级**（对齐托管版本的收敛波，方向无关--升级/回滚/修漂移同一动词，确认文案显式目标版本）、**改范围**（双向自由，收缩方向 reason 必填进审计并向被移除空间发通知）、**回收**（拆解除托管--即时删托管记录无波次--与回收--active→recycling→卸载波→删，防孤儿安装）
- AC3：托管插件空间侧锁定（不可自行升级/卸载、不参与空间自动更新）
- AC4：新建空间自动安装 scope=全部的托管插件
- AC5：QA 内网市场不可达时明确降级提示并引导本地上传

**US-6 组织级凭据（一期全部组织统一）**
> 作为系统管理员，我希望所有模型/工具凭据由组织统一配置，空间侧不可自配，以便成本与安全收口。

- AC1：一期所有凭据项固定「组织统一」：空间侧凭据区只读（"由组织统一配置"）、无编辑入口、不显示来源徽标
- AC2：分派表（`provider_credential_assignments`）一期建表、读链路上线、值恒为 org、无写入口--解析链「按分派读」一期建好二期不动（热路径一个版本、全链路回归只跑一次）；二期开放自配为纯增量（写入口+切换 UI），无 schema 迁移；**显式分派指针（org/self），无回退链、无遮蔽语义**
- AC3：解析仅组织凭据（无回退层，一期无空间自有凭据概念）
- AC4：凭据与插件分发范围**解耦**（插件范围管装不装、分派管用哪份，一期恒 org 对全部空间生效）；掩码只进不出；加密锚点方案 A（组织凭据密文挂锚租户 RSA，空 tenant 无密钥可用）
- AC5：空间不可自装/升级/卸载插件（`TenantPluginPermission.install_permission` 收紧为 noone：存量空间批量迁移 + 新建空间默认 noone，防新空间回退为默认 everyone）

**US-7 审计日志**
> 作为系统管理员，我希望按操作人/动作/空间/时间查询管理操作记录。

- AC1：覆盖空间/成员/系统管理员/**凭据（增删改）/插件托管（安装/改范围/升级/回收/解除托管）**全部动作，含操作者、目标、参数明细（集成类事件清单见设计稿 §4.5；改范围收缩必含 reason；`credential.assignment_change` 为二期分派写入口开放后的事件，一期分派表只读不触发）
- AC2：支持多维过滤与分页；一期不做导出

**US-8 空间集成视图**
> 作为系统管理员，我希望在空间详情看到该空间的插件、凭据状态全景。

- AC1：集成 tab 展示插件（一期只有「托管分发」；存量自装为迁移遗留）、凭据状态（一期两态：**组织统一 / 未配置**--未配置=插件已装但组织未配凭据，解耦后正常态；二期显式分派开放后增加「空间自配」态，单空间分派入口在本 tab）

### 非目标（一期不做）

- RBAC 本地化（流 A）与细粒度资源授权；ABAC；权限组
- OAuth 类组织代授权、触发器订阅共享（二期）
- 空间物理删除；审计导出 CSV；概览仪表盘；跨空间批量编辑成员
- MCP/OpenAPI 连接实例的托管分发与凭据策略（连接实例型：无"插件包+凭据"分离结构，不适用托管扇出与策略模型，一期维持空间自建）

## 3. 技术规格

### 架构与数据流

- 前端：`web/app/admin/` 独立路由组 + 独立 layout（不依赖 workspace context）；TanStack Query hooks 新增 `web/service/admin/`；dify-ui + Tailwind v4；i18n 新增 `admin.json`
- 后端：新命名空间 `/console/api/admin/*`，装饰器 `@system_admin_required`（会话 + `SYSTEM_ADMIN_EMAILS` ∪ `accounts.is_system_admin` 并集判定）；业务复用 `TenantService`/`RegisterService`
- 新增表：`admin_audit_logs`、`integration_grants`（插件托管记录）、`organization_credentials`（组织级凭据：策略字段保留、一期固定组织统一，明细见总体方案 §3）；`accounts` 加 `is_system_admin` 列
- 插件分发：托管记录 + 逐 tenant 扇出（复用现有安装链）+ 空间创建钩子；`TenantPluginPermission` 存量迁移 + 新建空间默认 noone
- 凭据解析：一期仅组织凭据（无回退层）；ProviderManager 解析链改造 + 按 tenant 缓存失效；空间侧只读
- bootstrap：`RegisterService.setup()` 去建空间、置系统管理员标记；login 工作空间预检加 is_system_admin 放行（`console/auth/login.py:180`，否则首登管理员被既有 "workspace not found" 拒绝、到不了 load_user）；`load_user` 无空间窄分支（仅 is_system_admin 放行）

### 集成点与安全

- 鉴权：`@system_admin_required`；机器通道 `ADMIN_API_KEY` 保留并存
- 高危操作：授予/撤销系统管理员需密码确认；归档二次确认；末位管理员禁撤
- 凭据：加密存储、掩码展示、只进不出；审计全量落库
- 失败回滚：install 置位落在 setup 既有回滚范围内

### 测试与验收承接

| 成功标准 | 验证方式 |
|---|---|
| #1 建空间全流程 ≤3 分钟 | 手工 QA（UI 设计稿 §7 五件事走查） |
| #2 插件扇出成功率 ≥99% | 流 B QA：三源安装 + 扇出失败重试 + 新建空间自动安装用例（总体方案 §9） |
| #3 审计覆盖率 100% | 后端单测断言各 admin 端点审计写入（UI 设计稿 §7） |
| #4 /admin 拦截率 100% | 前端路由守卫 vitest + 后端端点鉴权 403 用例 |
| #5 组织凭据解析正确性 | 模型调用全链路回归 + 凭据变更缓存失效用例（总体方案 §9） |

测试明细见 UI 设计稿 §7 与总体方案 §9。


## 4. 风险与路线

### 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| `load_user`/`ProviderManager` 热路径改造引入回归 | 高 | 窄分支 + 全链路回归 + QA 灰度 |
| 插件扇出部分空间失败 | 中 | 分发状态可见 + 重试；安装异步任务化 |
| QA 内网市场/GitHub 不可达 | 中 | 插件中心内网降级提示 + 本地上传 |
| 组织凭据一处配错影响全部空间（无空间自配兜底） | 中 | 变更二次确认 + 审计 + 模型调用全链路回归 |

### 路线

- **一期（上线必做）**：bootstrap 瘦身 + 空间/成员/系统管理员/审计（约 5.5-7.5 人日）+ 插件托管与插件中心（4-6）+ 组织级凭据·全量组织统一（4-6）——**合计约 14-20 人日**（明细见总体方案 §10：B-P0~P2 + B-P4/P5）
- **二期**：OAuth 组织代授权、触发器订阅共享（复用分派模型）、审计导出、凭据分派写入口（空间自配，显式指针无回退链）、MCP 集中治理（目录/白名单模型，如需）
- **三期（需求驱动）**：流 A RBAC 本地化、集中凭据与 RBAC 组织角色合流
