# PRD：工作台 UI 重构（流 B 一期 · 空间侧）

> 版本：v1.0（2026-09-03 由设计稿定稿内容结构化产出）；v1.1（同日：主线补第四条——保留功能同步 UI 重构、视觉语言统一，「保留」指能力与数据不动、界面不原样保留）
> 关联文档：设计稿 `2026-08-28-工作台UI重构-design.md`（口径源头）、可交互原型 `2026-08-28-工作台UI重构-mockup.html`、系统管理控制台 PRD `2026-08-27-系统管理控制台-PRD.md`、后端方案《权限体系自研总体方案-模型A》流 B §6.4
> 读者：工程团队 + 管理层

## 1. 执行摘要

### 问题陈述

方案 A（权限体系自研）落地后，插件安装/升级/卸载、模型与工具凭据配置等治理能力收归系统管理控制台，但工作台（空间侧）仍是上游「全功能自助空间」形态：保留安装入口（点了会吃后端 403）、凭据编辑入口、Marketplace 一级入口与各类托管叙事，与普通用户「纯使用方」的新角色不符；同时「WEB APPS」区、侧栏账号区等壳层与新版视觉语言不统一。

### 方案概述

按「保留原有功能、删减不用的、重新设计 UI」三原则重构工作台。四条主线：**①侧栏重构**（导航收敛 +「应用」一级导航项 + 账号菜单，视觉与管理台统一）；**②集成页重构**（最大改动面：Marketplace 一级入口删除，集成二级 + 工具页内三级子 tab 双层导航，模型供应商/工具全部卡片 + 只读抽屉）；**③空间侧全面只读化**（安装/升级/卸载/凭据写入口全删，渗透面 5 处改提示态；UI 收敛之外由后端四道防线兜底——`install_permission=noone` / 托管态 403 / 自动升级任务过滤 / `/permission/change` 锁改）；**④其他功能保留并 UI 重构**（主页/工作室/Agents/Skills/知识库/MCP/工作流/Swagger 功能行为不变，全部换成新视觉语言——「保留」指能力与数据不动，不是界面原样保留）。

### 成功标准（量化指标为建议值，标注 *，待评审确认）

| # | 指标 | 目标 |
|---|---|---|
| 1 | 空间侧插件安装/升级/卸载/凭据写入口移除率（前端无入口 + 后端防线 403 拦截，「藏了且拦了」双标准） | 100% |
| 2 | 普通用户主路径回归（工作室创建/编排/发布、知识库创建与导入、应用使用、空间切换） | 零回归 |
| 3 | 导航收敛：Marketplace 一级入口、集成二级四类型页（数据来源/触发器/扩展/自定义端点）、调试/权限入口对普通用户不可见 | 100% |
| 4 | 系统管理员互跳通道：头像菜单「系统管理」入口显隐正确（`is_system_admin` 真才出现）、点击直达 `/admin` | 100% |
| 5 | 渗透面 5 处（工具/Agent 节点选择器、Trigger/DataSource 节点、知识库建文档、索引设置）提示态覆盖 | 100% 覆盖、无安装按钮残留 |

## 2. 用户体验与功能

### 用户角色

| 角色 | 描述 |
|---|---|
| 普通成员 / 空间 Owner·Admin | 纯使用方：使用与编排应用，插件/凭据/版本无感知（不可行动项不呈现） |
| 系统管理员 | 同账号下从头像菜单多一个「系统管理」入口直达 `/admin` |
| 无空间普通账号 | 登录失败终态页 + 引导联系系统管理员 |

### 用户故事与验收标准

**US-1 侧栏与导航重构**
> 作为工作台用户，我希望导航结构清晰收敛，只看到我能用的东西。

- AC1：侧栏 = logo + 空间切换器 + 导航（主页/工作室/Agents/知识库/Skills/集成/应用）+ 底部账号区；视觉 token 与系统管理控制台完全一致（白+黑+橙）
- AC2：Marketplace 一级入口整页删除（含工具页底部市场精选轮播）；集成二级四类型页（数据来源/触发器/扩展/自定义端点）一期不出现；调试/权限入口与顶部安装按钮移除
- AC3：「应用」为一级导航项（原 WEB APPS 区重设计，2026-09-03 终版）：与主导航连续、无分隔线/无内嵌条目/无徽标，直达 `/apps` 列表页（搜索 + 卡片网格 + 最近使用排序），卡片进 `/installed/<id>` 内嵌使用页；与工作室分工=使用门/编辑门（卡片信号「最近使用」/「编辑于」）
- AC4：「集成」可收起/展开（默认收起）：展开且不在集成视图时进入默认子页，收起时页面不动；展开态 localStorage 记忆、独立于当前视图
- AC5：Agents（BETA）/Skills 保留在导航、一期不改动；未来执行摘除评估方案 A 时入口随 `NEXT_PUBLIC_ENABLE_AGENT_V2` flag 消失、本设计不返工

**US-2 集成 · 模型供应商只读化**
> 作为空间成员，我只关心有哪些供应商和模型可用，配置的事与我无关。

- AC1：无 Add API Key、无添加模型、无安装入口、无自动更新；卡片网格照 QA 现状结构（图标/名称/版本号 mono/类型徽标/状态徽标），点击开右侧抽屉看模型清单（按类型分组、纯查看无操作按钮）
- AC2：状态两态——可用（绿）/未配置（灰）；未配置卡片标注「未配置凭据，模型不可用」，抽屉内 amber 提示「如需使用请联系系统管理员配置」；这是解耦后的正常态不是错误态；配额/失效等细分态二期再分层
- AC3：默认模型设置保留在页面最外层（工具栏右侧），弹窗照 QA（五个类型下拉 + 取消/保存），空间级语义不变
- AC4：治理叙事不呈现——页头无托管徽标、卡片无来源小字（「默认不说，不可用时才说」）

**US-3 集成 · 工具四形态**
> 作为空间成员，我用卡片找到工具并查看其能力；MCP/工作流/API 维持空间自建。

- AC1：工具二级 + 页内三级子 tab（工具插件/MCP/工作流作为工具/Swagger API 作为工具），子 tab 路由化（可分享 URL、浏览器前进后退可用）；Agent 策略保留为集成二级、与工具同级
- AC2：工具插件/Agent 策略 = 大卡片网格（图标/名称/描述/版本 mono/来源 org·name，无来源徽标）+ 只读详情抽屉（简介 + actions 列表 + 二级参数 schema 详情）；工具栏含标签筛选下拉（搜索+多选）与搜索框；删安装按钮/市场轮播/自动更新/行内操作
- AC3：凭据只在未配置时出现（抽屉顶部 amber 提示，正常态不提凭据）；Agent 策略无凭据概念
- AC4：MCP/工作流/Swagger 三 tab 功能与结构照 QA 现状（MCP 添加弹窗三段 tab、工作流空态三步引导无创建按钮、Swagger 创建弹窗=「创建自定义工具」），仅视觉对齐新语言；卡片可点开详情（抽屉外壳复用）；MCP 凭据空间自管不纳入组织凭据
- AC5：抽屉外壳四处复用（工具插件/Agent 策略/MCP/Swagger API + 模型供应商模型清单），同一外壳内容各表一维

**US-4 知识库收窄**
> 作为空间成员，我通过本地文件或网址导入文本建知识库。

- AC1：保留即用型知识库创建、本地文件上传/网址抓取两导入源、标签筛选与搜索
- AC2：数据源同步导入整体不开放（含 OAuth 类与 Key 类），顶部提示「导入源仅保留导入已有文本；数据源同步一期暂不开放」——不提「收归系统管理员配置」（指路即误导）
- AC3：管线型（Pipeline）存量卡片可见可进，新建入口一期隐藏；存量为零则自然不出现，无需特判

**US-5 渗透面收敛**
> 作为空间成员，我在编排时只看到已装可用的插件，不会点到装不了的东西。

- AC1：5 处渗透位（工作流工具节点选择器/Agent 策略选择器/Trigger·DataSource 节点/知识库建文档/索引设置）全部改提示态「由系统管理员统一分发，如需请联系系统管理员」，不出现安装按钮
- AC2：存量引用显示插件缺失态（`ToolProviderNotFoundError` + 编辑器标红）；知识库索引设置在组织未配凭据时显示「未配置，联系系统管理员」
- AC3：验收双标准——前端藏了且后端拦了（四道防线逐条 403 用例，同控制台 PRD 成功标准 #2/插件 QA 清单共用）

**US-6 登录失败态（无空间普通账号）**
> 作为无空间账号，我登录时得到明确失败提示与引导，而不是白屏或卡死。

- AC1：独立全屏终态页（非控制台外壳）：图标 + 「登录失败：未加入任何工作空间」+ 引导联系系统管理员 + 返回按钮；侧栏在此态隐藏
- AC2：实现为 login 流程终态页（不建独立 route）；与后端 login 预检口径一致（无会话建立）

**US-7 空间切换面板与账号菜单**
> 作为多空间用户，我能在侧栏顶部切换空间；作为系统管理员，我能从头像菜单直达管理台。

- AC1：切换面板上滑打开：操作行两项（工作空间设置 → 既有 `?settings=` 弹窗、邀请成员按 owner/admin 显隐）+ 当前空间高亮与角色副文本 + 多空间列表 + **已归档空间置灰不可选**；无「创建空间」入口
- AC2：切换成功整页刷新（沿用现状 `location.assign()`）
- AC3：头像菜单=个人资料/密码与安全/偏好设置/外观/退出登录（现状功能保留）；**系统管理员追加「系统管理」入口**（`is_system_admin` 显隐，普通用户菜单完全无此项）——两份控制台唯一互跳通道
- AC4：`?settings=` 弹窗体系整体保留（成员/偏好/品牌等 tab 不变）；仅收敛集成 modal 双入口（只留 `/integrations` 页形态，下线时勿误伤共享 renderer）

### 非目标（一期不做）

- 工作室与主页改版（维持现状）、Agents/Skills 任何改动、知识库管线型新建入口
- 数据来源（整体不开放）、触发器（一期不用，存量建议管理台回收）
- 空间内插件安装/调试/权限页；凭据任何写入口；通知中心（改范围收缩通知走既有站内信/邮件通道）
- 配额不足/凭据失效等供应商细分状态分层（二期）

## 3. 技术规格

### 架构与数据流

- 侧栏为**共享组件**（如 `web/app/components/console-shell/`）：工作台 `(commonLayout)` 与 `/admin` 独立 layout 两处引用的同一组件两实例；不放任一路由组目录、不复制两份
- 视觉 token 全量对齐系统管理控制台（CSS 变量集一致），抽公共 token 层（Tailwind v4 + `@langgenius/dify-ui` primitives）
- 集成三级子 tab 路由化（`/integrations` 下 query 或嵌套路由）；卡片/抽屉数据来自 daemon `list_plugins`（经 api 聚合）+ 插件 declaration；内置工具走 `BuiltinToolProvider` 既有链路，以「有无 plugin_unique_identifier」判型混排
- `/apps` 复用现状已安装 WebApp 列表数据源与行为，仅换视觉与入口
- 空间切换对接既有 `currentWorkspaceAtom` 与租户切换 API；`is_system_admin` 由 `/account/profile` 下发（同控制台 PRD）

### 集成点与安全

- 后端四道防线（`TenantPluginPermission.install_permission=noone` 存量迁移+新建默认 / 托管态 403 / 自动升级任务过滤 / `/permission/change` 锁改）为真正封死层；前端隐藏只是避免点击吃 403
- 凭据掩码只进不出，空间侧连掩码都不呈现
- 归档空间在切换面板置灰可见（UI 防误触，login 预检兜底拦截）

### 测试与验收承接

| 成功标准 | 验证方式 |
|---|---|
| #1 入口移除率 100%（藏了且拦了） | 前端 vitest（渲染断言无安装/凭据入口）+ 后端四道防线逐条 403 用例（与控制台 PRD 插件 QA 清单共用，不重复立项） |
| #2 主路径零回归 | 既有 e2e 回归（工作室/知识库/应用/切换）+ 手工走查 |
| #3 导航收敛 | 渲染断言（无 Marketplace/四类型页/调试权限入口）+ 路由直访 404/重定向用例 |
| #4 系统管理入口 | vitest：`is_system_admin` 真/假两态菜单渲染 + 跳转断言 |
| #5 渗透面提示态 | 5 处逐一点开截图走查 + 缺失态标红用例 |

## 4. 风险与路线

### 风险

| 风险 | 等级 | 对策 |
|---|---|---|
| 侧栏共享组件改动面大（commonLayout 影响全部页面） | 高 | 组件抽离先行 + 全页面回归；与 `/admin` layout 并行引用验证 |
| 「藏了没拦」造成虚假安全感 | 高 | 验收双标准（前端无入口 + 后端 403 用例），防线用例进 CI |
| `?settings=` 集成 modal 收敛误伤页形态（共享 renderer） | 中 | 下线时逐引用点核对；页形态回归用例 |
| Agents/Skills 摘除决策与本稿耦合 | 低 | flag 机制解耦（`NEXT_PUBLIC_ENABLE_AGENT_V2`），本设计无需返工 |
| 触发器/数据来源存量插件残留（QA 已装） | 低 | 建议系统管理员在插件管理页「移除·从所有空间卸载」；不移除则无 UI 入口 |

### 路线

- **一期（上线必做）**：侧栏与导航重构（含「应用」一级项、集成组收起）+ 集成页只读化（模型供应商/工具四形态）+ 渗透面提示态 + 知识库收窄 + 登录失败态 + 账号菜单与系统管理入口——人日待评估（随总体方案 §10 排期，与控制台流 B 同一批次）
- **二期（需求驱动）**：供应商细分状态分层（配额/失效）、数据源开放（跟随 OAuth 组织代授权）、MCP 目录/白名单模型空间侧呈现、触发器开放
