> 上游文档：`2026-09-03-WebApp自定义-design.md`（token 体系 / ui_config 契约 / 三件套机制 / 功能保留红线——全部沿用）；执行计划 v2 第 4 步。
> **本稿定位**：五类型共用的交互/布局/形态语言定稿。逐单元 HTML mockup + 功能对照表仍按三件套流程照此出稿；本稿不替代 mockup。

## 0. 背景与拍板记录

- **2026-09-22 用户拍板**：旧 mockup 为「双列保留换肤」（Dify 骨架原样、仅换 token 与细节样式），方向作废；UI/交互要**真·重设计**，参考市面现代 AI 产品交互。
- **2026-09-24 定稿链**：
  1. 气质锚点 = **极简对话流（ChatGPT/Claude 系）**——界面退后、内容为王：大留白、单焦点消息流、会话管理按需唤出、输入区为唯一恒定交互中心；toB 平台适配面最广，且 2026 市面主流均在减元素。
  2. 骨架方向 = **A：抽屉式会话管理**——默认无侧栏，会话历史收进 overlay 抽屉（☰/⌘K 唤出）；桌面/移动同一交互范式。终端用户场景以单次咨询为主，会话历史是弱需求，常显侧栏属闲置成本。
  3. 细部两轮（chat 族四面 + 四类型适配与机制）逐项呈现，D1–D10 决策全部按推荐通过。

## 1. 设计原则

| 原则 | 含义 |
|---|---|
| 界面退后 | 默认态只保留消息流 + 输入区 + 40px 极薄 header；一切管理性 UI 按需唤出 |
| 功能保留红线刚性 | 三件套流程不变，QA 功能清单每行须有落点；**形态/位置/默认可见性可自由重组** |
| token 不动 | 白+黑+橙、light/dark、`.webapp-theme` 作用域、`chat_color_theme` accent 注入全部沿用；本稿视觉全部落在既有 token 上 |
| 两断同范式 | 桌面与移动端共用同一交互模型（抽屉即范例），不做桌面专属交互 |
| 空态即首页 | 空会话 = 欢迎屏 + 输入区居中，首发后进入对话态 |

## 3. chat 族（类型 1 `/chat/[token]`，范本）

### 3.1 骨架与抽屉

**桌面默认态**（无侧栏，整屏三段）：

- **40px 极薄 header**:`[☰]` `[应用小图标+名（弱化)]` `[会话标题▾ 点击出操作下拉：置顶/重命名/删除]` …右部 `[+ 新建]` `[↻ 重置]` `[查看变量(条件)]`。**header 不设 ⋯ 菜单**——更多菜单（主题/隐私/关于/退出）唯一落点在抽屉底部（抽屉 = 会话管理 + 应用菜单的语义容器；降级 `show_conversation_sidebar=false` 时菜单不可达，与现状 sidebar 隐藏即菜单不可达一致）。
- **消息流**：720px 居中列
- **底部悬浮输入卡**：与消息流同宽对齐

**抽屉**（☰ 或 ⌘K 唤出；overlay 300px，不推挤布局；蒙层点击/ESC 关闭；选中会话或新建后自动关闭）：

```
┌─────────────┐
│ 🔍 搜索会话      │ ← D1 新增,前端过滤
│ [+ 新建会话](橙CTA)│ ← 全页唯一主按钮(沿用旧拍板)
│ 📌 置顶          │ ← 有才显示
│  今天            │ ← D2 时间分组:今天/昨天/更早
│  会话A       ⋯  │ ← hover ⋯ = 置顶/重命名/删除(沿用)
│  更早…          │
│─────────────────│
│ 主题/隐私/关于/退出 │ ← 条件项沿用现状
│ Powered by 杏树林  │ ← 品牌链:应用级→工作区级→默认
└─────────────┘
```

- ⌘K 语义 = 唤出抽屉并聚焦搜索框（**不做独立命令面板**）。
- 重命名/删除 = 居中弹窗（沿用）。
- `ui_config.layout.show_conversation_sidebar=false` 降级：抽屉入口（☰/⌘K）不渲染；header 保留 +新建/↻重置/会话标题▾（操作不丢，沿用旧拍板降级语义）。

### 3.2 消息流（720px 居中，去气泡化）

- **用户消息**：右置浅灰胶囊（`bg-soft` 底、radius 12、max 75% 宽）；hover 出复制/编辑，编辑 → 内联 textarea 保存重发（交互沿用现状）。
- **AI 回答**：无框直接排版、满 720 宽、**去头像**（D3；应用身份由 header/欢迎屏承担）。
- **流式**：发送键原位变 ■ 停止键（D4）。
- **折叠条族沿用**（旧 mockup 已定形态，本身即现代形态）：推理面板（pill 折叠条 + 竖线引文式展开）、workflow 过程 / agent-step 折叠卡片、引用「引用了 N 个来源」折叠条 + 卡片列表 + 命中详情弹窗。
- **操作条**：hover/focus 才显现，回答末尾左对齐 icon 行（赞/踩/复制/重新生成/朗读·TTS 条件）；多答案切换 ‹1/2› 收其中；**性能行默认隐藏、随操作条同出**（D5）。
- **建议问题**：答案后推荐 = pill 列表（沿用）。
- 人工介入表单内嵌 / 附件列表 / 点踩反馈弹窗 / 标注反馈栏（条件）等：功能保留，视觉随折叠条族 token 化。

### 3.3 输入区（悬浮卡）

- 底部居中悬浮卡：720 对齐消息流、radius 12、1px border、focus accent 晕环、一级阴影。
- 内部：textarea 自增（max 160px 沿用）｜左下 📎（`file_upload` 条件）🎙（`speech_to_text` 条件）｜右下 accent 实心发送（空内容灰禁用 / 流式变 ■）。
- 快捷键提示行**移除常显**（D6，快捷键功能保留）。
- 拖拽/剪贴板粘贴上传保留（拖拽高亮 = accent 虚线框沿用）；输入禁用态 = 整体 60% 透明（沿用）。

### 3.4 欢迎屏与变量表单

- **空会话 = 欢迎屏**：垂直居中——应用图标 64px + Markdown 开场白 + 副标题（`welcome_subtitle`，空不渲染）+ 建议问题 2×2 卡片（点击直接发送，沿用）。
- **输入区空态居中**：无消息时输入卡位于视口中心（欢迎屏流内），首发后落底（ChatGPT/Gemini 共识形态）。
- **变量表单**：欢迎屏流内区块（同 720 列）；**有必填变量时默认展开、全选填时折叠**为「对话前请完善信息 ▾」；「开始聊天」accent CTA；header「查看变量」入口保留（有条件表单时）。
- **应用描述**：收为开场白下一行 line-clamp + 「展开」（现状独立描述卡取消）。

### 3.5 移动端

- 抽屉 = 左滑 85% 宽 overlay（替代现状全屏浮层，与桌面同范式）。
- 输入区贴底悬浮卡 + 安全区适配；欢迎屏同结构缩放；header 同极薄化（菜单/会话标题/⋯）。

## 4. chatbot（类型 2 `/chatbot/[token]` 嵌入式）

- **骨架**：气泡窗/全屏两种宿主形态（**embed.js 行为不动**）；无会话历史（现状如此）→ 无抽屉。
- **header 极薄化**：左 = 应用图标+名；右 = ↻重置（有会话且 URL 未锁 conversation_id）+ 查看变量（条件）+ 展开/收起钮（仅 iframe 内条件链）。**中性化**：头部不再吃 chat_color_theme 蓝底（延续 inverted 退役口径）。
- **聊天核心 = chat 族同语言满血复用**（消息流/输入区/欢迎屏/变量表单卡）；气泡窗 ~400px 窄宽时 720 列退化满宽。
- **外壳去渐变**：桌面灰白渐变底 → `--bg` 纯色；移动端 rounded-2xl 卡片保留、头部蓝渐变 → 中性。
- Powered by 链落点沿用（header 桌面位 + 移动页脚位），末级默认「杏树林」。
- **保留红线逐字保全**：iframe 协议三消息（ready/config/expand-change）+ embed.js 父页侧行为 + URL 参数契约（sys.\*/user.\*/inputs 预填/locale/sendOnEnter/conversation_id）。
- 去 Dify 化登记：`isDify()` referrer 恒 false 分支删除（入删旧台账）。

## 5. text-generation 族（类型 3/4/5）——单列化

**废桌面左右双列**（D7），单列 720 居中，与 chat 同列宽同语言：

```
[极薄 header:应用标识 …… ⋯菜单(主题/隐私/关于/退出)]
[segment: 运行一次 | 批量运行* | 已保存*]   ← D8;*条件项(批量=ui_config.show_batch_tab 默认隐藏,已保存=completion 型专属+Badge)
─────────────────────────────
 变量表单(8 字段型同 chat 欢迎屏样式族;vision 上传区条件显示)
 [清空]  [▶ 运行(accent)]   ← 运行中变 ⏹ + spinner(沿用);结果区不再单独出停止钮(同 D4 口径)
─────────────────────────────
 结果区(流内,替换式 = 最新一次):
 · 空态 / Loading
 · TextGenerationRes(markdown/复制/赞踩/保存/moreLikeThis/TTS/任务编号/结果·详情双tab)
 · workflow 过程卡(折叠卡片族)/ 深度思考折叠
 · 批量结果(执行数头/下载/失败重试)
─────────────────────────────
 Powered by 杏树林(主列底部居中)
```

- 结果语义不变：替换式展示最新一次，保存才进「已保存」。
- 移动端：结果流内化（D10，原底部抽屉 + drag handle 取消）。
- **workflow（类型 4）** = 同语言 + 过程卡；**env-workflow（类型 5）** 同语言，但无独立 QA 功能清单——回炉到该单元时先按三件套补实证清单（不默认同稿，09-03 既定约束）。

## 7. 回炉范围与实施顺序

- **回炉量 = 呈现层 DOM/样式重排**；hooks/契约/状态/服务层不动；契约层 spec 保持绿，呈现层测试随改。呈现层新写机制不变（家族根自挂 `.webapp-theme` 单实现；console 真共享面 text-generate/item 保留双层口径）。
- **顺序**：chat（范本）→ chatbot（复用携带）→ completion 族 → workflow → env-workflow（先补清单）。
- **每单元新三件套**：mockup（本稿语言）→ 功能对照表（已有清单沿用、落点重映射）→ 回炉代码。
- i18n 新 key 只维护 zh-Hans + en-US（C14 口径）。
- e2e 缺口仍挂 M2（后端 T3 阻塞），QA 走查链补位（`2026-09-22-WebApp五类型-QA走查清单.md`）。
